# Base-Density Forward-Predictor Efficacy Spike

## Goal

Measure whether a **contribution-aware forward predictor** — evaluable *before* the base-indirect SH bake, from light geometry and probe positions alone — reproduces the post-bake composed-receiver coarsenability oracle accurately enough (near-zero unsafe false-positives) and cheaply enough to justify the deferred foundational base-probe-density (bake-time-win) spec. Measurement-only: changes no baked bytes, opens no format or renderer door. The deliverable is a decision — is the bake-time win reachable by a cheap forward predictor, or not — per `experimental_spikes.md`.

## Scope

### In scope

- **A forward-predictor harness** in the compiler analysis layer (a new module sibling to `sh_analyze`), evaluated at `probe_grid_layout` time, per 4×4×4 affinity brick, from `MapLight` geometry + probe positions + the bake BVH — reusing `sh_analyze`'s `pub(crate)` brick primitives so its numbers line up with the oracle.
- **Two forward predictor families** on an input-cost spectrum: **P1 contribution-geometry** (per-light cone + falloff + facing at the brick's probe positions, no ray tracing) and **P2 + occlusion** (P1 plus a per-light corner shadow test). An optional **P3 direct-field ceiling** using the baked direct-at-probe volume (id 35) as the richest signal, run only as an accuracy ceiling. A **distance / surface-distance negative control** (the invalidated predictor) for the refutation.
- **The oracle**: per brick, the coarsest base-indirect level (L0/L1/L2) that the production relative gate (`sh_coarsen::CoarsenParams` `rel_p95_max` 0.10 / `rel_max_max` 0.25 / `darkness_frac` 0.02) admits, with numerator = base-indirect reconstruction error (`sh_analyze` `BrickRecord.base_l1`/`base_l2`) and denominator = composed magnitude (`BrickRecord.composed_magnitude`). Warranted below (Rough sketch, linearity).
- **Scoring**: per-brick confusion matrix, predictor level vs oracle level; the **false-positive rate** (predictor coarser than oracle — the unsafe, under-baked direction), the **recovered-savings** fraction (of oracle-coarsenable bricks, how many the predictor also frees, and at which level), and the **predictor evaluation wall-time vs the base-indirect bake wall-time** (a predictor as expensive as the bake saves nothing).
- **Fixtures**: `content/dev/maps/occlusion-test.map` (primary — its animated baked lights *are* aimed `light_spot`s, so it strictly satisfies delta-indirect + aimed-spot and bakes fast) and `content/dev/maps/stress-warren-mini.map` (heavier realistic cross-check; also delta-indirect + aimed-spot). Both populate id 27.
- **Output-preserving harness + findings**: byte-identical emitted `.prl` with vs. without the spike flag (mirrors `--sh-analyze`); a JSON report and a findings note with the promote/no-promote recommendation for the foundational spec.

### Out of scope (non-goals)

- **The base-grid format change and the renderer-side variable-density sampler** — the one-way door this spike exists to gate. Foreclosed here in source: the spike writes no `density_level` (the hard-zero write in `sh_bake.rs` `bake_probe` and the nonzero-reject on parse in `sh_volume.rs` are untouched) and edits no renderer file (`sh_sample.wgsl` `probe_tile_origin`, `sh_compose.rs` `build_probe_indirection_words` unchanged). The harness only reads baked sections and scores; it cannot change the wire or the sampler.
- **Actually skipping dense base-indirect probe bakes (the bake-time win itself).** Foreclosed by the oracle's data dependency: the score compares each predictor against the post-bake ground-truth level, which requires the dense bake to *exist* — a bake you skipped has no ground truth to score against. The spike therefore bakes dense as normal (`bake_sh_volume_controlled` over `0..total`, unchanged) and measures only the predictor's agreement. Skipping bakes is the foundational spec's job.
- **The base *direct* (id 35) and delta (ids 27/41/45) bake-time.** The expensive bake is the base indirect (id 34): 256 hemisphere rays × soft visibility per probe (`sample_radiance_rgb`, `RAYS_PER_PROBE = 256`). The direct-at-probe field is cheaper and is consumed here only as a predictor *input* (P3), never a skip target.
- **The surface-distance forward classifier.** Invalidated by the coarsenability spike (shares the cone-blindness distance does; `context/plans/drafts/lighting-scale--sh-probe-density-coarsenability-spike/findings.md`) and self-invalidated by the archived plan on review. Included only as the negative control the spike refutes, never as a candidate.
- **The delta (storage/bandwidth) coarsening.** Shipped and productionized in `context/plans/ready/lighting-scale--sh-adaptive-coarsening-v2`; this spike is the sibling bake-time question that spec deferred.
- **Runtime cells as the density key.** Rejected on owner measurement (archived `adaptive-base-probe-density`: on campaign-test 49% of interior cells are smaller than one affinity cell). The predictor keys on the affinity-brick grid, not cell membership.

## Direction

**Problem.** The bake-time win — skipping dense base-indirect probe bakes in coarsenable regions — is foreclosed behind a foundational, one-way-door change (base-grid format + renderer variable-density sampler), and its enabling assumption is unmeasured: that a *forward* predictor, evaluable before the bake, can decide which bricks need dense probes. The coarsenability spike proved regions are coarsenable *post-hoc* (bake dense, then classify by composed-receiver error) and that the predictor must be **contribution-aware** (angle-off-cone-axis r = −0.765 vs distance r = −0.355), invalidating the archived surface-distance classifier. But post-hoc coarsenability is not forward predictability: the spike never measured whether a cheap pre-bake signal reproduces that classification accurately enough to skip bakes without receiver error. That gap — named verbatim in the coarsenability spike's open questions as "forward-predictor efficacy … the bake-time win's gating measurement" — is the cause; everything downstream (the format, the sampler) is a bet on it.

**Prior commitments.** The coarsenability spike (`.../sh-probe-density-coarsenability-spike/findings.md`) established three load-bearing facts this spike builds on: the predictor must be contribution-aware not distance-aware; base indirect coarsens far more readily than the composed receiver (base-L2 mean 0.005–0.015 vs composed-L2 0.03–0.09, composition amplifying ~6–8×); and its stronger, still-unmeasured test needs a fixture with a genuinely contributing indirect delta (`has_delta_indirect: true`), since `kinematic-platform` has none. The storage half shipped as `lighting-scale--sh-adaptive-coarsening-v2`, which explicitly deferred this base-density sibling. The archived `adaptive-base-probe-density` plan is the foundational spec this gates; its surface-distance classifier is dead, its base-grid + sampler rewrite is the one-way door, and `AFFINITY_FACTOR = 4` (`affinity_grid.rs`) and the reserved-zero `density_level` (`sh_volume.rs`) are its landed hooks. The oracle is the composed-receiver relative gate already in `sh_coarsen` reusing `sh_analyze`'s primitives. **Divergence:** this spike measures a contribution-aware forward predictor where the archive proposed surface distance — a divergence already committed by the coarsenability spike's finding, restated here so the negative control is explicit.

**Alternatives rejected.** *Skip the spike; build the foundational spec and measure efficacy inside it.* Rejected — that opens the format + sampler one-way door before knowing the predictor works, exactly the bet this cheap measurement de-risks; the whole line has run measurement-first. *Measure one hardcoded predictor (angle-off-cone only).* Rejected — the predictor's **input cost** is co-equal with its accuracy: a predictor that needs the full hemisphere bake to decide saves no bake time, so the spike must sweep a small family across the cost spectrum and report the cheapest that is accurate enough. *Measure on the existing three fixtures only.* Rejected — none carries a divergent indirect delta (`kinematic-platform` `has_delta_indirect: false`), the precise gap the coarsenability spike flagged; the stronger test needs `occlusion-test` (animated aimed spots) where the indirect delta genuinely contributes to the composed oracle.

**Placement.** Build-time compiler analysis layer, a new module beside `sh_analyze`, output-preserving. Correct level because the question is answerable entirely at bake time — compute the forward predictor and the post-bake oracle on the same dense bake and score their agreement — with no format, wire, or renderer change. Opening those doors is the foundational spec's job, gated on this result.

**Foreclosure / reversibility.** None. Measurement-only; the harness is a report generator behind a default-off flag, deletable at no cost. Its entire purpose is to precede the actual one-way door so that door opens on data.

## Acceptance criteria

Split by what they prove (`experimental_spikes.md`): honesty gates are automated; measured findings are measure-and-report, never a pass/fail threshold.

**Honesty gates (automated):**

- [ ] Output-preserving: on both fixtures, the emitted `.prl` is byte-identical with and without the spike flag — the harness reads baked sections and scores, mutating nothing (mirrors the `--sh-analyze` byte-preserving property).
- [ ] Complete classification: every non-empty affinity brick receives both a predictor level (each family) and an oracle level, so the confusion matrix has no unclassified cell. The degenerate cases resolve without panic: a map with no baked lights, a map with no animated baked lights (id 27 absent), and an empty/all-invalid brick each produce a well-formed (possibly empty) matrix, not a crash.
- [ ] Fixture honesty: the primary fixture's report shows `has_delta_indirect: true` and a non-zero baked aimed-spot (`light_spot`) count, asserting the delta-indirect + aimed-spot precondition the measurement rests on.
- [ ] Oracle fidelity: the oracle level is computed by reusing `sh_analyze`'s brick primitives and `sh_coarsen::CoarsenParams`, so the ground truth the predictor is scored against is numerically the same classification the production gate would apply to the base-indirect field.

**Measured findings (measure-and-report):**

- [ ] Per predictor family × fixture, the **false-positive rate** (fraction of bricks the predictor calls coarser than the oracle — the unsafe, under-baked direction) and the **recovered-savings** fraction (of the oracle's L1+L2 bricks, the fraction the predictor also frees, by level) are recorded as a **tradeoff curve over a sweep of the predictor's decision threshold** (the predictor emits a continuous per-brick score; the level is a thresholding of it — mirror `sh_analyze`'s `DEFAULT_THRESHOLDS` sweep), not a single operating point. The curve answers the learnable question: does *any* threshold achieve near-zero false-positives with meaningful savings? The confusion matrix and agreement rate at the best near-zero-FP operating point are recorded alongside. Each is a recorded value feeding the recommendation, not a gate.
- [ ] The **predictor evaluation wall-time** for each family is recorded against the **base-indirect bake wall-time** on the same fixture, so the cost side of "cheap enough to save bake time" is measured, not assumed.
- [ ] The contribution-aware vs. distance comparison from the coarsenability spike is reproduced on the delta-indirect primary fixture (the previously-unmeasured stronger test): the correlation of predictor signal with oracle level for the contribution-aware families (P1/P2) vs. the distance-to-nearest-light negative control (the r ≈ −0.36 signal the spike found weak), recorded. The load-bearing candidates the recommendation rests on are the cost-viable P1 and P2; P3 is an accuracy ceiling and surface-distance a bonus control, not required for the call.
- [ ] The findings note recommends whether the foundational base-density spec is worth its one-way door: it names the cheapest predictor family whose false-positive rate is near-zero and whose evaluation cost is a small fraction of the base-indirect bake, or reports that none of the measured families clears both bars, with the numbers behind the call.

## Tasks

### Task 1: Forward-predictor harness — thin slice, P1 on the primary fixture

Build the measurement harness end to end for the cheapest predictor on one fixture, so the byte-preserving property, the oracle reuse, and the confusion-matrix shape are all falsified before the family fans out. Add a new compiler module (do not extend the 2196-line `sh_analyze.rs` or the 3214-line `sh_bake.rs`; place the predictor + scoring in a new file, e.g. `crates/level-compiler/src/sh_forward_predict.rs`, reusing `sh_analyze`'s `pub(crate)` primitives `build_brick_tiles` / `level_errors` / `tile_magnitude` / `BrickRecord` / `AnalyzeInputs`). Behind a new default-off `--sh-forward-predict` flag (parsed in `main.rs` beside `--sh-analyze`, byte-preserving, running after section finalization at the same seam as `run_sh_analysis` in `pipeline.rs`), on `content/dev/maps/occlusion-test.map`: (a) compute the **oracle** per non-empty brick — the coarsest base-indirect level admitted by `sh_coarsen::CoarsenParams` with numerator `BrickRecord.base_l1`/`base_l2` and denominator `BrickRecord.composed_magnitude`, darkness floor `max(darkness_frac * map_p95, 1e-6)`; (b) compute the **P1 contribution-geometry** predictor per brick from the `MapLight` set (`incident_radiance_at_point` / `spot_cone_attenuation` / `falloff` / `light_reaches_point` in `sh_bake.rs`, aggregated at the brick's probe positions from `probe_grid_layout`), yielding a **continuous per-brick score** from the estimated delivered-light magnitude and its spatial gradient across the brick (thresholded to a level for scoring); (c) sweep the score threshold and score the per-brick confusion matrix predictor-vs-oracle at each, emitting the false-positive-vs-recovered-savings tradeoff curve plus a JSON report (mirror `--sh-analyze-out`, default `<output>.forward-predict.json`). Assert the emitted `.prl` is byte-identical with and without the flag. This slice falsifies "a cheap forward predictor reproduces the oracle" before the family and the sweep commit. Emit results to a sibling `research.md`; contract no accuracy threshold (measure-and-report).

### Task 2: Predictor family + negative control

Extend the Task 1 harness with the rest of the input-cost spectrum, all scored against the same oracle: **P2 + occlusion** (P1 plus a per-light corner shadow test via `segment_clear` / `soft_visibility`, capturing shadow boundaries P1 over-brightens); the **distance / surface-distance negative control** (nearest-light distance, and — if cheaply available by hoisting `sdf_bake.rs`'s point-to-triangle machinery — nearest-surface distance, the invalidated archived classifier, included to reproduce its refutation); and an optional **P3 direct-field ceiling** that reads the already-baked direct-at-probe volume (id 35) per-probe gradient across the brick as the richest signal, run purely as an accuracy ceiling with its cost recorded (do not assert id 35 is free — measure whether it is baked before the base-indirect bake and record its marginal cost). Each family produces a per-brick level and its own confusion matrix vs. the oracle. Record each family's evaluation wall-time separately so the cost axis is per-family.

### Task 3: Measurement sweep + findings note

Run the full family across both fixtures — `occlusion-test.map` (primary, strict delta-indirect + aimed-spot) and `stress-warren-mini.map` (heavier cross-check) — and consolidate: per family × fixture, the confusion matrix, the false-positive rate, the recovered-savings fraction (by level), the agreement rate, the predictor evaluation wall-time vs. the base-indirect bake wall-time, and the contribution-aware-vs-distance correlation on the primary fixture. Record the base-indirect field's overall coarsenability on each fixture (does finding 3's "near-lossless almost everywhere" hold here, making the predictor's real job the correct protection of the few contribution-concentrated dense-needed bricks). Recommend promote (the foundational base-density spec is worth its one-way door — name the cheapest predictor clearing near-zero false-positives at a small fraction of bake cost) or no-promote (no measured family clears both bars — the bake-time win is not reachable cheaply and the door stays shut), with the numbers behind it. This is the spike deliverable — a decision, not a contracted threshold.

The findings note is written as the **hand-off to the foundational base-density spec's drafting session**, so that drafting can begin the moment the spike agent completes. On a promote, it records, in terms a drafter can spec against: (a) the winning predictor family and its exact input signals — which `MapLight` fields, whether occlusion is needed, whether the id-35 direct field is required — so the forward classifier can be specified; (b) its operating point (the near-zero-FP threshold), its recovered-savings and false-positive numbers, and its evaluation cost vs. bake cost; (c) the base-indirect coarsenability characterization (near-lossless-everywhere vs. structured), which sets what fraction of the bake the win can reach; and (d) the explicit list of what the foundational spec must still design that this spike deliberately did not touch — the `density_level` format semantics (`sh_volume.rs`, currently reserved-zero/reject), the renderer-side variable-density sampler (`sh_sample.wgsl` `probe_tile_origin`, `sh_compose.rs` `build_probe_indirection_words`), and the bake path that skips unstored probes (`sh_bake.rs` `bake_sh_volume_controlled`). On a no-promote, it records which bar each family missed (accuracy or cost) and whether a richer-but-still-cheaper predictor is worth a follow-up spike, so the door is not reopened blindly.

## Sequencing

**Phase 1 (sequential):** Task 1 — thin slice; falsifies the byte-preserving property, the oracle reuse, and the confusion-matrix shape on one fixture before the family fans out.
**Phase 2 (sequential):** Task 2 — extends the Task 1 harness module with the rest of the predictor family; shares the one harness file, so it follows Task 1 rather than running concurrently.
**Phase 3 (sequential):** Task 3 — consumes the full family; runs the sweep across both fixtures and writes the findings + recommendation.

## Rough sketch

- **New module** `crates/level-compiler/src/sh_forward_predict.rs` (keeps the 2196-line `sh_analyze.rs` and 3214-line `sh_bake.rs` from growing): the predictor families + the oracle recomputation + the confusion-matrix scoring + JSON emit. Reuses `sh_analyze::{build_brick_tiles, level_errors, tile_magnitude, BrickRecord, MagnitudeStats, AnalyzeInputs, LevelKind}` (all `pub(crate)`) and `sh_coarsen::CoarsenParams`.
- **Oracle, warranted by linearity.** Coarsening the base-indirect field (id 34) in a brick perturbs the composed receiver by that brick's base-indirect reconstruction error, so — the same linearity `sh_coarsen::classify_section_levels` documents for delta sections — the induced composed-receiver error equals the base-indirect reconstruction error, gated relative to composed magnitude. Oracle level = coarsest of {L0, L1, L2} whose `base_lN / max(composed_magnitude, floor)` passes both `rel_p95_max` and `rel_max_max`; sub-floor-dark bricks take the coarsest evaluable level. Every input is a field already on `BrickRecord`; no new bake.
- **Predictor inputs** live entirely pre-base-bake: `MapLight` (`map_data.rs` — `origin`, `light_type`, `cone_direction`, `cone_angle_inner`/`_outer` radians, `falloff_model`/`falloff_range`, `intensity`), `probe_grid_layout` positions/validity (`sh_bake.rs`), and the bake BVH for P2 occlusion. The cheap per-light contribution primitives (`incident_radiance_at_point`, `spot_cone_attenuation`, `falloff`, `light_reaches_point`) are already `pub(crate)` in `sh_bake.rs`.
- **CLI**: `--sh-forward-predict` (default off) + `--sh-forward-predict-out <PATH>`, parsed in `main.rs` beside `--sh-analyze`, wired in `pipeline.rs` at the post-finalization byte-preserving seam (`run_sh_analysis` neighbor). Tuning constants (predictor level thresholds) are debug-tool/CLI knobs, never user-facing settings.
- **Fixtures** (no authoring needed): `occlusion-test.map` — 4 animated baked `light_spot` (id 27 populated, animated lights *are* the aimed spots); `stress-warren-mini.map` — 16 baked aimed spots + 3 animated baked lights incl. a `light_spot` with `brightness_curve`.
- **Bake wall-time** for the cost axis comes from the existing pipeline stage timing (the base-indirect bake stage), the same instrumentation the `sh-adaptive-coarsening-v2` validation slice reads; the predictor evaluation wall-time is timed per family inside the harness.

## Open questions

- **P3 direct-field cost.** Whether the direct-at-probe volume (id 35) is baked before the base-indirect volume, making the P3 ceiling predictor cheap, is a measured result (Task 2 records its marginal cost) — not assumed. If id 35 is baked after id 34, P3 is a ceiling reference only, never a viable cheap predictor.
- **Base-indirect coarsenability on these fixtures.** Finding 3's "base indirect coarsens near-losslessly almost everywhere" is a three-map directional result; Task 3 records whether it holds on `occlusion-test`/`stress-warren-mini`. If it does, the predictor's real job is protecting the few contribution-concentrated dense-needed bricks, and the false-positive metric dominates the recommendation.
