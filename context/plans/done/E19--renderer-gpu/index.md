# postretro-renderer (GPU)

> Epic: `E19--render-stack-decomposition`. The terminal cut: the single GPU crate that restores "Renderer owns GPU" within one boundary and hides `wgpu::SurfaceTexture`.

## Goal

Extract all wgpu-touching render code into `postretro-renderer`, **absorbing** the GPU modules that currently live outside `render/`, and expose an engine-facing API that names no wgpu types — so the binary and every other crate are wgpu-free and the invariant holds by construction.

## Scope

### In scope
- Move all of `render/` that touches wgpu: `Renderer`/`FullRenderer` (`renderer_types.rs`), every `renderer_*.rs` impl file, every pass (forward/depth/wireframe/shadow/`mesh_pass` GPU/`smoke`/`fog_pass`/`screen_effects`/`splash_pass`/`sh_volume` compose/`sh_compose`/`animated_lightmap`/`sdf_atlas`/`sdf_shadow`/`frame_timing`/`debug_lines`/`debug_ui` GPU), `pipeline_layout` BGL objects, `loaded_texture` GPU upload, and the GPU UI pass (`ui/mod.rs` `UiPass` + `ui/text.rs` `UiTextRenderer`).
- **Absorb the stray GPU modules** so no wgpu lives outside this crate: `compute_cull`, `candidate_cull`, `shadow_cull`, and `lighting::{spot_shadow,cube_shadow,lightmap}`. `chunk_list` stays in `postretro-render-cpu`; renderer consumes its byte payloads and owns upload/resources. (`candidate_cull_mirror`/`candidate_cull_probes` are CPU test oracles at `crates/postretro/src/` — keep test-side; exact home is implementer's discretion.)
- **Opaque present handle:** replace `render_frame_indirect`'s `Result<Option<wgpu::SurfaceTexture>>` return with `Result<Option<PresentHandle>>` — an opaque renderer-owned handle carrying the acquired surface texture (the frame encoder is submitted inside `render_frame_indirect`, ahead of its post-submit readback tail, so no encoder rides out; `present()` just presents). The three-way outcome maps 1:1: `Err` = fatal, `Ok(None)` = frame skipped, `Ok(Some(handle))` = present it (both binary call sites already branch `if let Some(...)`). The binary calls `renderer.present(handle)`, never `surface_texture.present()` — no wgpu name reaches the binary; `present` is infallible (`fn present(&self, handle: PresentHandle)` → `()`, since `SurfaceTexture::present()` is). The handle absorbs surface acquire (Success/Suboptimal/Outdated/Lost/Timeout/Validation) and view creation into the renderer; the acquire-variant→outcome mapping (which variants yield `Ok(None)` vs `Err`, where Outdated/Lost reconfigure) is behavior-preserving — relocate the current `render_frame_indirect` acquire logic, do not redesign it. `PresentHandle` is built on the splash path's existing `PresentOutcome`. **The two-step shape (return handle, then present it) is forced, not stylistic:** the dev-tools debug-UI pass draws into the acquired surface *between* frame render and present (`main.rs` gameplay path), so a one-step `render_and_present` would erase that injection point — `render_debug_ui` therefore *borrows* the `PresentHandle` (`&mut`), not `&wgpu::SurfaceTexture`, and `present(handle)` consumes it afterward. Unify the gameplay and splash present paths behind the handle.
- Depend on `postretro-ui`, `postretro-render-cpu`, `postretro-visibility`, `postretro-level-loader`, `postretro-render-data`, `postretro-lighting`, `postretro-model` (CPU glTF loader, `E19--model`), `postretro-entities`/`postretro-scripting-core` (snapshot values), `wgpu`, `winit`, `glyphon`, `glam`, `bytemuck`.
- Update binary consumers (`main.rs`, `startup/lifecycle.rs`, `startup/splash_lifecycle.rs`, `session/mod.rs`) to import the renderer crate and drive the present loop via the handle.

### Out of scope
- The `FullRenderer` encapsulation refactor (converting `pub(super)` reach-in to owned-handle constructors). `pub(super)` stays **within** the crate; `FullRenderer` remains private. (The deferred FullRenderer-encapsulation spec.)
- Pass-level GPU sub-crates.
- `render-diagnostics` extraction (the deferred render-diagnostics spec).

## Acceptance criteria
Inherits the epic global acceptance criteria — see `E19--render-stack-decomposition/index.md`. Durable decisions are captured into `context/lib/` per spec as each spec is approved — not in one batch at first promotion.
- [ ] `postretro-renderer` is a workspace member; `cargo build --workspace` + `cargo test --workspace` pass; renderer/GPU and shader-parity tests pass from their relocated home.
- [ ] **Invariant restored:** `wgpu` is absent from the `[dependencies]` of every crate except `postretro-renderer` — **the binary included** — and `cargo build --workspace` still passes, so no non-renderer crate can name a wgpu type by construction. (`rg wgpu` alone is not the gate — it trips on doc-comments and timing-label strings like `"wgpu_init"`; use the Cargo.toml dep check plus `rg 'wgpu::'` for residual type usage.) The binary's present loop names only the opaque handle; the dev-tools debug-UI interleave lives behind the renderer boundary. The cull and lighting-GPU modules now live inside the renderer crate.
- [ ] **No wgpu in the public API:** no consumer of `postretro-renderer` imports `wgpu`; `wgpu::SurfaceTexture`/`TextureView` do not appear in any engine-facing signature. The present handle is opaque.
- [ ] The dependency graph is acyclic and one-way (proven by `cargo build --workspace`); no lower crate depends on `postretro-renderer`.
- [ ] Behavior-preserving (automated): the typedef drift test is byte-identical; the WGSL byte-layout guards (`group3_shader_bindings_are_represented_by_rust_layout`, `shader_tests`) and the shader-parity tests pass from their relocated home. (No render-diff/golden-image test exists in the tree — the pixel-identity check is manual, next line.)
- [ ] Behavior-preserving (manual-visual): a fixture map renders with no visible-output regression — verified by running the engine, not in CI.
- [ ] Editing the binary's non-render code does not recompile `postretro-renderer` (observational build-graph gate: touch a non-render binary file, confirm `cargo build -p postretro-renderer` reports it Fresh, or verify via `--timings`).

## Tasks

### Task 1: Extract postretro-renderer (one transplant)
Create the `postretro-renderer` crate and move, in a single atomic transplant, all wgpu render code into it: every `render/` module that touches wgpu (`renderer_types.rs`, every `renderer_*.rs` impl file, every GPU pass, `pipeline_layout` BGL objects, `loaded_texture` GPU upload, the GPU UI pass `ui/mod.rs` `UiPass` + `ui/text.rs` `UiTextRenderer`) **together with** the stray GPU modules `render/` references — `compute_cull`/`candidate_cull`/`shadow_cull` (`crates/postretro/src/*.rs`) and the lighting GPU pools `lighting::{spot_shadow,cube_shadow,lightmap}`. These move in the *same* step, not a preceding one: `render/` calls into them, so leaving them behind breaks the crate's compile — this is the "one transplant, no staging" of Epic Decision 7. `chunk_list`/`ChunkGrid` stays in `postretro-render-cpu`; the renderer uploads its planned byte payloads. `candidate_cull_mirror`/`candidate_cull_probes` are CPU test oracles — keep test-side (home is implementer's discretion); `candidate_cull_mirror` imports `crate::candidate_cull::{GatherStatus, gather_candidate_leaves}` (both currently `pub(crate)`), so export those two as `pub` from the renderer crate, have the oracle dev-depend on `postretro-renderer`, and re-point that import (`candidate_cull_probes` chains through the mirror — no direct renderer dep). `render/splash.rs` is the CPU splash loader (no wgpu; takes the binary `SplashSource`) — it stays binary-side and is NOT in the move-set; only the GPU `splash_pass.rs`/`renderer_splash.rs` move.

Wire deps on the lower crates (`postretro-ui`, `-render-cpu`, `-visibility`, `-level-loader`, `-render-data`, `-lighting`, `-model`, `-entities`, `-scripting-core`, plus `wgpu`/`winit`/`glyphon`/`glam`/`bytemuck`) — compile errors and existing `use postretro_*` name them. Widen the symbols the binary consumes to `pub` (e.g. `ClearColor`, used as `render::ClearColor`), including the dev-tools setter API (`pub`, no wgpu in signatures). The binary can alias `use postretro_renderer as render;` to keep existing `render::` call sites unchanged. `FullRenderer` stays `pub(super)`/private: moving the subtree wholesale preserves its intra-crate reach (`super` becomes the new crate root), so do NOT do the encapsulation refactor.

**Resolve every binary-internal reach-in across the full move-set (`render/` *and* the absorbed modules)** — paths pointing UP at the binary that a crate cannot depend on; sever each or the crate won't compile:
- `crate::camera::{NEAR,FAR}` (`renderer_render_frame.rs`) — inline these projection constants into the renderer (behavior-preserving; §11 near 0.1 / far 4096.0).
- `crate::nav::NavGraph` via the dev-tools `emit_nav_diagnostics(&NavGraph)` (`renderer_diagnostics.rs`) — a binary type in the would-be public API. Keep the nav→line-segment translation **binary-side**, calling a *new* graph-agnostic debug-line push method on the renderer: `push_line`/`push_line_overlay` are `pub` only on the internal `DebugLines` (`debug_lines.rs`), so expose a thin `pub fn` on the renderer taking segment data only (`start`/`end` `Vec3` + `[u8;4]` color) that forwards into it, and have the binary push at the same frame point `emit_nav_diagnostics` runs today. The nav-diagnostics reader does not transplant into the crate (deferred `render-diagnostics` spec territory — do not pull it forward).
- test-only reach-ins inside `#[cfg(test)]` blocks: `crate::scripting_systems::mesh_anim` (`mesh_pass.rs` tests), `crate::scripting::primitives` (`render/ui/lifecycle_render_test.rs`), and — in an *absorbed* module — `crate::scripting::reactions::log_capture` (`lighting/lightmap.rs`, test `oversize_section_logs_renderer_prefixed_error`) — relocate these tests to the binary's integration-test side rather than carrying them into the crate.

`mesh_pass.rs`/`sh_volume.rs` are oversized but this is largely a move — split only if substantial edits are needed (split-before-extend). The verification gate (`wgpu::` usage / Cargo.toml deps, `cargo tree` isolation, behavior-preservation) provides the safety staging would.

### Task 2: Opaque present handle
Introduce `PresentHandle` on the basis of the splash path's `PresentOutcome` (`render/renderer_splash.rs`, returned by `render_splash_frame`). Rework `render_frame_indirect` and `render_splash_frame` to return `Result<Option<PresentHandle>>`; move surface acquire/view/error handling behind the handle. Re-point the dev-tools `render_debug_ui` interleave (`main.rs` gameplay path) to *borrow* the `PresentHandle` (`&mut`) instead of `&wgpu::SurfaceTexture` — it only needs `surface_texture.texture.create_view(...)`, which a texture-carrying handle satisfies — leaving `present(handle)` to consume the handle afterward. Update both binary present sites to `renderer.present(handle)`, leaving the binary wgpu-free. Acquire + surface-view creation happen during frame recording; **submit stays inside `render_frame_indirect`** — its post-submit readback tail (`encode_sh_probe_readback`, timing/candidate post-submit) depends on the submit having already happened — so the handle carries only the acquired surface texture and `present()` = `handle.output.present()` (no encoder rides out). The one open sliver — whether `render_debug_ui` borrows the handle `&mut` or the overlay folds into `present` — is a wgpu-free renderer-internal call and settles at build time.

## Sequencing
**Phase 1:** Task 1 (the transplant), then Task 2 (present handle). Milestone 3 (terminal). The full verification gate (invariant `rg`, `cargo tree` isolation across all crates, acyclicity, typedef drift, WGSL) runs here.
