> **Status:** in progress. All tasks, measurements, preflight, and review are complete; awaiting review fixes and landing. Certain-win storage work — no measurement gate, no visual-risk mechanism. Prerequisite of the gated sibling `lighting-scale--adaptive-base-probe-density` (drafts/), which populates the density-level field this spec reserves.
> **Track:** Lighting / build pipeline — at-rest cost of the base octahedral SH volume (PRL id 34).
> **Related:** `context/lib/build_pipeline.md` §PRL section IDs (id 34/35 entries) · `context/lib/rendering_pipeline.md` §4 "Indirect", §7.1 step 5 · `context/plans/done/sh-array-atlas/` (layer-aware atlas, landed) · `context/plans/drafts/lighting-scale--adaptive-base-probe-density/` (the follow-on this spec's format field serves).

## Why this is its own spec, not phase 1 of the adaptive-density spec

`/orchestrate` consumes one spec per run: one feature branch, one integration, one preflight + review gate. The adaptive-density work is behind a measurement spike it may not clear, and it rewrites the sampler contract across five pipelines; this spec is unconditional, touches no sampler, and ships a certain win (disk, load time, base-atlas VRAM) regardless of how that spike lands. Binding them would hold this work hostage to the sibling's gate: a mid-run no-go leaves one branch half-implemented and one review panel judging a mixture. Split as two orchestrate runs, coupled through three surfaces this spec pins: the reserved per-probe density-level field (I5, Wire format), the one-`u32`-per-probe indirection word (I3), and the compact x-fastest payload ordering (Wire format). Only the first and third are on-disk contracts; the word is built at load and never serialized (I3), so the sibling may redefine its encoding — including claiming its unassigned high bits — as a renderer change with no format consequence. What the reservation buys is **not** avoiding a second version bump: the sibling bumps id 34 regardless, because v9 parse-rejects a nonzero level. It buys that the bump changes validation semantics only, with zero layout churn, because the level byte already sits in the metadata record's existing padding — which is what averts an unplanned third bump from a mis-shaped record. Cost of the split: a second review gate. Accepted.

## Goal

The base octahedral SH irradiance volume (`OctahedralShVolume`, PRL id 34) stores a full 288 B `Rgba16Float` octahedral tile for **every** probe of a uniform grid spanning the whole world AABB (`probe_grid_layout`, `crates/level-compiler/src/sh_bake.rs:148-194`), including probes inside solid geometry and in exterior space — on `campaign-test` at the 1.0 m default, 57,128 of 194,028 probes are valid (29.4%), yet the section is 57,436,908 B (~296 B/probe, 52.1% of the map's SH bytes; recorded sweep, Measured basis). It is also the only SH atlas with no at-rest format tag: it always serializes and uploads dense `Rgba16Float` (`upload_atlas_texture`, `crates/renderer/src/render/sh_volume.rs:951-1002`), while the sibling direct atlas (id 35) already ships BC6H behind an `irradiance_format` tag. This spec makes the at-rest payload valid-probes-only and BC6H by default, moves per-probe validity out of the atlas alpha channel (BC6H is RGB-only) onto the metadata that already carries it, and reserves a per-probe density-level field — always zero here — for the adaptive-density sibling. **This spec does not reduce per-pixel sampler bandwidth or composed-atlas VRAM: the runtime composed total atlas stays dense per-probe `Rgba16Float`, and every sampler shader is untouched. The wins are disk size, load time, and base-atlas VRAM only.**

## Measured basis

| Quantity | Value |
|---|---|
| Grid probes (world-AABB grid) | 194,028 |
| Valid probes | 57,128 (29.4% — 70.6% solid/exterior) |
| id 34 section bytes | 57,436,908 B (~296 B/probe = 288 B tile + 8 B metadata) |
| id 41 / 35 / 27 / 45 bytes | 34,857,290 / 6,990,796 / 5,451,890 / 5,451,890 B (4 selected lights) |
| Dense tile payload | 194,028 × 288 B = 55.88 MB |

| Valid-only + BC6H (8× on tiles) | ~2.1 MB tiles + 1.55 MB dense metadata (projection) |

Per-probe identity: tile = `tile_dimension² × 4 × 2 B` = 6² × 8 = 288 B; metadata record = 8 B (`OCTAHEDRAL_PROBE_STRIDE`, `crates/level-format/src/sh_volume.rs:40`).

## Scope

### In scope

- **id 34 version 9 format:** atlas payload carries tiles for valid probes only, in x-fastest probe order; an at-rest format tag (BC6H default / uncompressed debug) mirroring id 35's `irradiance_format` discipline; a per-probe density-level field, zero in every v9 bake, validated as zero at parse; version bump with the existing named reject.
- **Compiler emission:** compact-atlas packing, BC6H encode mirroring the direct-atlas encoder, honoring the existing `--uncompressed-irradiance` debug bypass; one-line footprint summary at `log::info`.
- **Runtime consumption:** verbatim BC6H upload of the compacted base atlas; a per-probe indirection-word storage buffer (compact tile slot, or an invalid sentinel) built at load; the indirect SH compose pass reads the base through a non-filtering sampler and the indirection word, and writes validity into the composed atlas alpha — so **no sampler shader changes** (warrant in Direction → Prior commitments and Invariants I1/I2).
- **Dev-tools continuity:** probe-marker irradiance colors served by the existing live GPU readback of the composed dense atlas (no CPU BC6H decode anywhere); once-per-load footprint log.
- **Findings note:** before → after disk / load-time / base-atlas VRAM with ratios, plus the explicit unchanged-bandwidth statement.

### Out of scope (non-goals)

- **Any sampler-side change.** `sh_sample.wgsl`, `forward.wgsl`, `fog_volume.wgsl`, `billboard.wgsl`, `skinned_mesh.wgsl`, `kinematic_brush.wgsl` are not edited; the composed total atlas keeps its dense per-probe layout (Invariant I1).
- **Composed-atlas or per-frame bandwidth reduction.** The compose output shape is unchanged; per-pixel sampler traffic is identical. The adaptive-density sibling owns that goal.
- **Non-uniform probe density / classification.** The level field is reserved and zero. No classifier, no thresholds, no density knobs here.
- **id 35 changes.** Already BC6H behind a tag; its dense per-probe tile layout is load-bearing for direct sampling when no composed direct atlas exists (`crates/renderer/src/render/sh_volume.rs:592` binds the base direct atlas straight into the sampler slot).
- **Delta sections (id 27/41/45).** Their payloads are keyed to the base grid's cell decomposition, which this spec does not touch — grid origin, dims, and spacing are byte-identical to v8 bakes.
- **Probe metadata compaction.** The per-probe metadata records (validity, depth moments) stay dense over the full grid: the depth-moment 3D texture packer consumes them dense (`pack_probe_depth_moments`, `crates/renderer/src/render/sh_volume.rs:913-927`), and at 8 B/probe (1.55 MB on campaign-test) they are not the burden.

## Direction

**Problem.** id 34's at-rest cost is dense storage over a world-AABB grid: 70.6% of stored tiles belong to probes the runtime weights to zero, and the remainder is stored uncompressed while every peer atlas in the engine (lightmap id 22, direct SH id 35) is BC6H at rest.

**Prior commitments.**
- Pre-release no-backward-compatibility: version bump, named reject, no shim (`context/lib/development_guide.md:171`, §1.6).
- BC6H-at-rest is the established engine pattern with a complete in-tree precedent to mirror: `encode_direct_section_bc6h` (`crates/level-compiler/src/direct_sh_bake.rs:876-925`) handles the 4-alignment padding (tile dimension 6 is not block-aligned), the `--uncompressed-irradiance` debug bypass, and drops alpha at encode ("RGB feeds the encoder, A drops", `crates/level-compiler/src/direct_sh_bake.rs:898-899`) — which is precisely why validity cannot stay in alpha. The compose-side BC6H read precedent also exists: the direct compose samples its BC6H base at texel centers through a non-filtering sampler because Metal rejects `textureLoad` on compressed formats (`crates/renderer/src/shaders/direct_sh_compose.wgsl:143-149`).
- **Do not cite `context/lib/rendering_pipeline.md:95` as evidence for this change** — that paragraph describes the *lightmap* irradiance atlas (id 22), not the octahedral SH volume. The id-35 precedent above is the correct one.
- The indirect compose dispatches every world-rendering frame (`crates/renderer/src/render/renderer_shadow_passes.rs:1020-1027`), so the base-atlas read this spec re-routes is per-frame hot-path code; the added cost is one indirection-word load and a sampler fetch replacing a `textureLoad`.

**Alternatives rejected.**
- *Load-time re-expansion to a dense atlas* (store valid-only on disk, expand before upload): forfeits the base-atlas VRAM win entirely, and forecloses BC6H — the encoder is a bake-side cost (`crates/level-compiler/src/bc6h.rs`); there is no load-time encode path and building one would violate the near-instant-boot northstar.
- *Validity as a second small texture* instead of packing it into the indirection word: spends a sampled-texture binding and a second fetch in the compose where one storage word already must exist for the slot remap. One `u32` per probe carries both (sentinel = invalid).
- *An on-disk probe→slot remap table:* unnecessary — the compact slot is derivable at load as the probe's rank among valid probes, because the compact payload preserves x-fastest probe order and the per-probe validity bytes are already in the section (`OctahedralShProbe.validity`, `crates/level-format/src/sh_volume.rs:47-54`). A prefix-sum over bytes the loader already holds beats a redundant table that could disagree with them.
- *Keeping `Rgba16Float` and shipping only the valid-only compaction:* leaves the 8× BC6H factor on the table for no risk saved — the BC6H quality question is already settled by id 22 and id 35 shipping it as production default on the same class of irradiance data.

## Acceptance criteria

Split per `context/lib/experimental_spikes.md`: honesty gates vs measured findings. Measured findings are before → after pairs with ratios — never thresholds to iterate toward.

**Honesty gates:**

- [ ] A v9 section round-trips: serialize → parse reproduces grid geometry, per-probe metadata, level field, format tag, and compact payload exactly (uncompressed path bit-exact; BC6H path byte-exact on the encoded blob).
- [ ] Parse rejects, each with a distinct named error: a non-9 version (existing "recompile" message shape); an unknown format tag; a nonzero density level; a compact payload whose length does not match the tag's identity for the valid-probe count; `compact_atlas_*` geometry that disagrees with the layout computed from the metadata-derived valid-probe count.
- [ ] A `--uncompressed-irradiance` compile of `content/dev/maps/gate-heavily-lit.map` is deterministic across two `--no-cache` runs (byte-identical `.prl`). The BC6H default path is exempt from byte-identity (lossy encode — same exemption the lightmap stage carries) but must be stable in section length across runs.
- [ ] `campaign-test` compiled at defaults boots to first rendered frame with no wgpu validation errors; indirect lighting renders on world geometry, entities, and fog (visual: no black world, no missing-probe falloff regression at former invalid-probe locations — invalid probes contributed zero weight before and must contribute zero weight after).
- [ ] Loading a pre-v9 `.prl` aborts the load with the named version-mismatch/recompile error (fatal `Err`, no wgpu validation crash, no partial load), matching the existing missing-section fatal posture. No compat shim, no silent degrade.
- [ ] Dense-geometry identity: for the same map, the v9 section's `atlas_dimensions`, `atlas_tiles_per_row`, `tiles_per_layer`, and `layer_count` decode to values identical to the v8 bake's (compared as parsed field values, not raw byte offsets — the v9 header layout shifts with the added fields; compact geometry rides only the new fields); the same v8-vs-v9 value-compare extends to grid origin, cell size, and grid dims (header fields, cheap). This is the gate against the failure the sampler-diff check cannot see: compact geometry leaking into the shared sampler uniform corrupts every SH fetch with no shader or BGL diff.
- [ ] No sampler WGSL file and no sampler bind-group layout changes in the diff (negative-existence: verified by review/grep gate, not a runtime test — this check alone proves nothing about sampler correctness; the dense-geometry identity AC and visual A/B carry that). The grep also confirms the id-34 base atlas view is not bound into any sampler group (Invariant I10).
- [ ] Dev-tools probe markers, on a BC6H-default map, two mode-specific observations (the marker modes are mutually exclusive, so a test must set the mode explicitly for each): (a) in Validity marker mode, green/red coloring is correct at load immediately, from metadata, with no readback; (b) in Irradiance marker mode, per-probe colors transition from the neutral load-time placeholder to live composed irradiance within a small bounded number of active-overlay frames (typically 2-3) of the overlay being enabled, and with the overlay inactive the placeholder persists by design.
- [ ] Logging: prl-build prints one info summary (valid/total probes, compact bytes, encoded bytes, format tag); runtime logs the base-atlas footprint once per load (dev-tools); nothing added per frame.
- [ ] A warm-cache-HIT rebuild produces a v9 section bit-exact (uncompressed path) / equal-section-length (BC6H) to an empty-cache MISS build on the same (grouped) code path — cache-hit vs cache-miss, both grouped. The monolithic `--no-cache` bake (`bake_sh_volume`) is a separate path, bounded instead by `WARM_SH_P999_REL_IRRADIANCE_ERROR` (`sh_group.rs`), and is not the comparison baseline here.
- [ ] A zero-valid-probes map and a map whose valid v9 section yields no usable probes (present==false dummy path) both boot to first frame with no wgpu validation errors and no per-frame log noise.

**Measured findings (each "before → after, ratio", recorded in the findings note):**

- [ ] id 34 section bytes on `campaign-test` at the sweep configuration: recorded baseline 57,436,908 B → measured v9 bytes (both BC6H default and `--uncompressed-irradiance`), with the valid-probe count confirming the recorded 57,128 / 194,028.
- [ ] Total `.prl` size, same map, before → after.

Changes, stated as constraints (field order/offsets are implementer-pinned; Wire format section binds the encoding): (a) the atlas payload becomes **compact** — tiles for valid probes only, x-fastest probe order preserved, prefixed or tagged by an `irradiance_format` field mirroring id 35's tag discipline — the tag constants (`IRRADIANCE_FORMAT_BC6H` / `IRRADIANCE_FORMAT_RGBA16F`) are defined in the `lightmap` module (`crates/level-format/src/lightmap.rs`) and reused as-is; `crates/level-format/src/direct_sh_volume.rs:41-92` is the model for the tag-dispatch pattern: `irradiance_format` field, `expected_irradiance_len`-style length identity per tag, unknown-tag reject; the compact atlas has its own layer-aware layout computed over the **valid** probe count via the existing `irradiance_atlas_array_layout` path in `crates/level-format/src/octahedral.rs` — that function takes `grid_dimensions: [u32; 3]` and lays out over the axis product, so the compact layout is obtained by calling it with a synthetic single-axis grid `[valid_probe_count, 1, 1]` (product = the count), or via a thin count-based helper — carried in **new** `compact_atlas_*` fields (Wire format) — every existing v8 field, including `atlas_dimensions` / `atlas_tiles_per_row` / `tiles_per_layer` / `layer_count`, keeps its v8 meaning: the dense per-probe layout the composed runtime atlas and sampler tile math use (Invariant I9; the consumers that depend on this are enumerated in Task 3). (b) each per-probe metadata record gains a **density level** field, `u8`, always 0 in v9, parse-rejected if nonzero ("reserved for adaptive density") — the record currently packs `validity` + two f16 moments + 3 padding bytes into an 8-byte stride (`OCTAHEDRAL_PROBE_STRIDE`, `crates/level-format/src/sh_volume.rs:38-54`); v9 keeps the 8-byte stride by taking one of the three existing padding bytes for the `u8` level (mandated — the certain-win argument in "Why this is its own spec" depends on zero layout churn). Each of the four new validation failures — unknown format tag; nonzero density level; compact payload length ≠ tag identity over the valid count; `compact_atlas_*` geometry ≠ layout over the valid count — gets its own distinct named error (a distinguishing message string, mirroring `direct_sh_volume.rs`'s `FormatError::Io` message discipline — not new enum variants), distinct from the reused version-mismatch reject: the "distinct named error" AC requires five distinguishable errors. Update `placeholder()`, `HEADER_SIZE` if the header grows, the doc-comment layout block (`crates/level-format/src/sh_volume.rs:103-137`), and round-trip/reject tests in-file (existing test shapes at `crates/level-format/src/sh_volume.rs:713+`). No BC6H code moves in this task or any other: the compiler's reference decoder is `#[cfg(test)]`-gated, Mode-11-only (`assert_eq!` on the mode, `crates/level-compiler/src/bc6h.rs:309-314`), and documented as non-production because runtime decode is the GPU's job (`crates/level-compiler/src/bc6h.rs:307-308`) — it stays exactly where it is; the dev-tools consumer that once motivated moving it is served by the existing GPU readback instead (Task 3). Focused test: for a known validity bit-pattern, the built words map each valid probe to its valid-rank compact slot and each invalid probe to the `0xFFFF_FFFF` sentinel. (c) **Compose WGSL** (`sh_compose.wgsl`): the base atlas read at `crates/renderer/src/shaders/sh_compose.wgsl:193` becomes a texel-center `textureSampleLevel` through the non-filtering sampler (the Metal-constraint precedent is `crates/renderer/src/shaders/direct_sh_compose.wgsl:143-149`). The dense composed coordinate `p` addresses only the composed-atlas store; the compact base is a differently-shaped texture, so its sample UV is derived from the probe's indirection word instead (sentinel → skip the fetch): the compact tiles-per-row / tiles-per-layer words resolve the slot to a base-atlas tile origin, the in-tile texel is added, and the result is normalized by `textureDimensions` of the base texture — not `(p+0.5)/dims` as in the dense direct-compose precedent, whose base shares the composed shape. The validity early-out at `crates/renderer/src/shaders/sh_compose.wgsl:196` (`base.a < 0.5`) becomes a sentinel test on the indirection word; and the composed write at `crates/renderer/src/shaders/sh_compose.wgsl:217` stores alpha = 1.0/0.0 **derived from the word**, preserving the composed atlas's alpha-validity contract so the samplers stay untouched — the complete validity-read inventory this rests on is pinned in Invariant I2. Two distinct store branches follow the validity/affinity checks. (a) The invalid / out-of-grid early-out branch (`!atlas_mapping.in_grid || base.a < 0.5`, ~`crates/renderer/src/shaders/sh_compose.wgsl:196-198`) stores a zero tile with alpha 0 — correct, warranted by `pack_octahedral_irradiance_tile` leaving invalid tiles all-zero (`crates/level-compiler/src/sh_bake.rs:800-826`). (b) A separate branch (~`crates/renderer/src/shaders/sh_compose.wgsl:202-204`) covers a valid, in-grid probe whose affinity cell has no reaching animated light (`!affinity.in_range`): today it writes the probe's real base irradiance with alpha 1.0. Under a compact base this branch must route through the same indirection-word base fetch as the main path and write `base.rgb` with alpha 1.0, delta loop skipped — folding it into the zero-tile-alpha-0 branch would black out every valid probe not covered by an animated-light affinity cell, a black-world regression against the "no black world" AC. (d) **Dev-tools probe markers:** the load-time CPU mirror `probe_irradiance` (`crates/renderer/src/render/sh_volume.rs:371-387`, fed by `probe_average_irradiance` at `crates/renderer/src/render/sh_volume.rs:1260`) reads dense atlas texels that no longer exist at rest. Do **not** decode BC6H on the CPU for it — the compiler's reference decoder is test-gated, Mode-11-only, and documented non-production (`crates/level-compiler/src/bc6h.rs:307-314`). Instead, seed `probe_irradiance` with a neutral non-black placeholder RGB at load (not `[0,0,0]`, which renders black markers) and let the **existing live readback path** supply real colors; a reload re-seeds the placeholder before the new readback lands, and with the overlay off the placeholder persists indefinitely by design: `ShProbeReadback` already copies the composed dense atlas (`encode_copy`, `crates/renderer/src/render/sh_diagnostics.rs:370-376`), decodes it into per-probe RGB (`decode_probe_irradiance_atlas`, `crates/renderer/src/render/sh_diagnostics.rs:453-458`), and swaps the result into `sh_volume_resources.probe_irradiance` each completed readback (`crates/renderer/src/render/renderer_render_frame.rs:1000-1001`) — all of it reads the composed `Rgba16Float` atlas this spec leaves dense, so it needs no changes. Accepted semantic shift, stated for the AC: marker irradiance colors appear once the live-irradiance overlay readback completes rather than from load; validity green/red coloring (from metadata, `crates/renderer/src/render/sh_diagnostics.rs:17,251`) is unaffected and immediate. The readback copy reflects the most-recent world-rendered frame's composed atlas and may be stale by a world frame on frames where the world is not drawn (`render_world == false`); acceptable for a debug overlay. (e) **Footprint log:** once per load (dev-tools), base-atlas bytes + format + valid/total probe counts. The GridDims uniform (`crates/renderer/src/shaders/sh_compose.wgsl:33-45`) keeps describing the dense composed atlas — dispatch bounds and `map_atlas_texel` are unchanged — and its two spare words (`_pad0`, `_pad1`, `crates/renderer/src/shaders/sh_compose.wgsl:43-44`) carry the compact tiles-per-row and tiles-per-layer the shader needs to turn an indirection slot into a base-atlas texel; `ComposeGridParams` and its byte builder `build_compose_grid_bytes` are defined in `crates/render-cpu/src/sh_compose.rs`, not the renderer crate — that struct and builder gain the two fields in lockstep, layout size unchanged; the renderer call site (`crates/renderer/src/render/sh_compose.rs:120-129`) passes the two new values through. The existing render-cpu test that pins the two spare GridDims words to zero (`build_compose_grid_bytes_packs_layer_fields_at_std140_tail`, asserting the std140-tail words are 0) must be updated to assert the new compact tiles-per-row / tiles-per-layer values.

## Wire format

v9 rides the existing id-34 section; conventions mirror v8 exactly — little-endian throughout, version as the first `u32`, existing header field widths retained. Constraints for the additions (field order and exact offsets are implementer-pinned at landing; the doc-comment layout block in `crates/level-format/src/sh_volume.rs` is updated in the same change):

- **No existing v8 field changes meaning across the bump.** `atlas_dimensions`, `atlas_tiles_per_row`, `tiles_per_layer`, `layer_count`, and every grid field keep describing the **dense** per-probe layout — the geometry the runtime composed atlas and the sampler tile math use, and the geometry the renderer assigns verbatim into its shared state and sampler uniform (`crates/renderer/src/render/sh_volume.rs:410-415`, `:479-492`). Redefining them to mean the compact payload would ship compact geometry into the sampler uniform with no shader or BGL diff — silent whole-world mis-sampling — and would break the documented id-34/id-35 geometry identity (`context/lib/build_pipeline.md:199`, `:222`). The compact payload gets its **own, new** fields.
- **Format tag:** a `u32` with the same two-value discipline as id 35 (`IRRADIANCE_FORMAT_BC6H` / `IRRADIANCE_FORMAT_RGBA16F` — reuse the existing constants, defined in the `lightmap` module, `crates/level-format/src/lightmap.rs`). Unknown tag rejects at parse. BC6H payload is the 4-aligned padded block blob, layer-major; uncompressed payload is compact `Rgba16Float` texels, layer-major then row-major. Each tag has an exact length identity over the metadata-derived valid-probe count; the stored `compact_atlas_*` fields (below) must equal the layout computed from that same count — both trace to one authoritative quantity, and either disagreement rejects at parse.
- **Compact atlas geometry, new fields:** `compact_atlas_dimensions`, `compact_atlas_tiles_per_row`, `compact_atlas_tiles_per_layer`, `compact_atlas_layer_count` (four header words) describing the **valid-probe** tile set, computed by the same layer-aware layout helper v8 uses for the dense set. Only the base-atlas upload, the indirection-word slot→texel mapping, and the compose pass's base fetch consume them.
- **Compact payload membership:** exactly the probes whose metadata validity byte is nonzero, in x-fastest linear probe order. No per-probe slot table on disk — slot = valid-rank, derivable (Invariant I3).
- **Per-probe metadata record:** gains a `u8` density level, taking one of the three existing padding bytes; v9 writes 0 and parse rejects nonzero. Validity and the two f16 depth moments keep their v8 semantics. v9 does not change the 8-byte record stride; the `probe_stride` header field remains the forward-compat mechanism for a future stride bump only.
- **Empty/degenerate cases follow v8:** empty geometry emits the placeholder-shaped section (zero dims, no probes, no payload); zero valid probes emits an empty compact payload; the section is still present and composes over the real grid, writing invalid alpha to every texel (zero SH contribution) — Validity-mode dev markers still show all-red. Reserve the term "no-SH path" for the genuinely-absent-section case (no id-34 section at all). When the valid-probe count is zero, `compact_atlas_dimensions` is `[0,0]`; the base-atlas texture must be clamped to a minimum of `[1,1]` with dummy content, mirroring the existing `.max(1)` clamp in the dense uploader (`upload_atlas_texture`), so no zero-sized wgpu texture is ever created. The indirect compose dispatches unconditionally every world frame and always binds the indirection storage buffer, so its length is the total grid-probe count, padded to at least one word — matching `pad_storage_bytes`' minimum-size discipline, but padding with `0xFFFF_FFFF` sentinel words, since the helper itself zero-fills and cannot be reused verbatim for this buffer — the empty-compact and no-SH/dummy-atlas paths always carry a valid non-zero buffer; compose reads sentinel → skips fetch → writes invalid alpha.

## Open questions / risks

- **BC6H loss on base irradiance.** id 35 ships the same encoder on the same data class (octahedral irradiance tiles) as production default, and blocks already straddle tile boundaries there; risk is bounded and the manual A/B in Task 4 is the check. If an artifact shows up it shows up behind the tag — `--uncompressed-irradiance` is the escape hatch, not a redesign.
- **Load-time prefix-sum cost.** The indirection-word build is one linear pass over 194 K validity bytes at campaign-test scale — load-time only, negligible. No CPU decode exists anywhere in this spec (dev-tools colors come from the GPU readback, Task 3).
- **Sweep numbers are recorded, not re-derived.** The campaign-test byte counts and probe counts in Measured basis are the owner's recorded sweep; Task 4's baseline compile re-derives the "before" side on the measurement host before comparing.
