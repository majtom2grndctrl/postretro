# Lighting Scale — Adaptive Base Probe Density

> **Status:** draft. Spike-led, **gated on its own Task 1 measurement** — Tasks 2+ proceed only if the spike shows the brick population distributes across levels with low coarse-reconstruction error. Requires `lighting-scale--sh-base-atlas-at-rest-slimming` (done/, landed on main): this spec populates the per-probe `density_level: u8` field that feature reserves (v9, reserved-zero) and consumes its compact valid-probe-only atlas and per-probe indirection-word infrastructure.
> **Supersedes:** `context/plans/drafts/lighting-scale--adaptive-sh-probe-density/` — the delta-section-level adaptive draft. Disposition in Direction.
> **Track:** Lighting / build pipeline — the storage- and bandwidth-scaling root cause: uniform probe density over the world AABB.
> **Related:** `context/lib/build_pipeline.md` §PRL section IDs (ids 34/35/27/41/45) · `context/lib/rendering_pipeline.md` §4, §7.1 step 5, §7.3, §10 · `context/plans/done/perf-animated-sh-light-culling/` (affinity CSR substrate) · `context/lib/experimental_spikes.md`.

## Goal

Every SH payload in the engine is a function of the base probe grid — a uniform lattice spanning the whole world AABB at an authored spacing (`probe_grid_layout`, `crates/level-compiler/src/sh_bake.rs:148-194`; `DEFAULT_PROBE_SPACING = 1.0`, `crates/level-compiler/src/sh_bake.rs:35`). The base atlas stores per-probe tiles; the composed runtime atlas is dense per-probe; and the three delta sections (ids 27/41/45) store one dense 64-probe brick per `(affinity cell, light)` CSR entry, so their payloads scale with probe density times per-light reach — measured exponent ≈2.4–2.95 (Measured basis), reaching 2.58 GB for id 41 alone on the stress map at the 1.0 m shipping default, with the direct compose streaming its stored bytes every active frame. This spec makes stored density **adaptive per 4×4×4 brick**: full 64-probe storage near surfaces, an 8-probe corner brick or a single representative tile in open volumes — the Unreal Volumetric Lightmaps / Unity APV pattern (detail bricks near static geometry, coarse cells in open air) collapsed onto the affinity-cell grid the engine already has. Density is an **authoring parameter with an engine-side backstop cap**, not a constant. The hard part, and the part that spends image quality, is the sampler: `probe_tile_origin` derives every atlas location arithmetically from the probe's linear grid index (`crates/renderer/src/shaders/sh_sample.wgsl:71-88`), so removing or re-spacing stored probes requires a sampler-side indirection consumed by every SH reader — world fragments, entities, and fog alike. Success is a measured before → after reduction in section bytes, composed-atlas VRAM, and per-frame compose traffic, recorded in Task 6 — never a byte target an agent iterates toward.

## Measured basis and design ranges

**Stress sweep (recorded, `content/dev/maps/stress-warren-maze-crates.map`, `--lightmap-density 0.8 --soft-shadow-samples 64` fixed, 61 selected lights):** id-41 direct-delta bytes 401,154,048 @2.0 m → 1,305,870,336 @1.33 m → 2,578,802,688 @1.0 m. Pairwise scaling exponents 2.85 / 2.95 / 2.39 — sub-cubic, flattening as cells saturate, reproduced on both maps. Payload identity: exactly 18,432 B × CSR entries at every spacing (`PROBES_PER_CELL = 64` × 36 texels × 8 B; constants at `crates/level-format/src/delta_sh_volumes.rs:28,31,35-40`, identity asserted at `crates/level-format/src/delta_sh_volumes.rs:118-121`).

**campaign-test @1.0 m (recorded):** 194,028 grid probes, 57,128 valid; id 34 = 57,436,908 B; id 41 = 34,857,290 B; id 35 = 6,990,796 B; id 27 = id 45 = 5,451,890 B; 4 selected lights.

**Design ranges, not a representative level (owner decision — none exists; external research brackets, not code-groundable):** ~75 K probes (classic-scale map), ~600 K (modern-large community map), ~12 M (format ceiling) at 1.0 m spacing. A uniform grid is fine at the low end, marginal in the middle, impossible at the ceiling. Every threshold and cap in this spec is designed against this range, and the spike runs at two points of it (campaign-test, stress-warren).

**Hardware target (owner, binding):** very performant on GTX 10-series, at least runnable on laptops. GTX 1060 and Radeon Pro 5500M are both ~192 GB/s parts; the 5500M ships 4 GB in its base config (external hardware facts). **Divergence flag:** `context/lib/rendering_pipeline.md:378` documents the perf floor as GTX 16-series, which this target undercuts — the divergence is deliberate and owner-stated; capture the widened floor in `context/lib/` at promotion, do not rewrite the lib doc during drafting. Consumer Pascal executes native fp16 arithmetic at 1/64 the fp32 rate (external, search-sourced), which pins the **f16-storage / f32-arithmetic** contract: all compose and sample paths keep f16 at rest read through `unpack2x16float` / float texture decode into f32 math; no WGSL `enable f16` anywhere in this spec.

## Scope

### In scope

- **Task 1 spike (gate):** bake-time, output-preserving analysis on both maps — per-brick surface-distance classification, coarse-reconstruction error at both coarse levels for base irradiance and for delta bricks, near-zero delta-entry fraction, and projected bytes for all five SH sections plus composed-atlas VRAM under the level/drop policy. Changes no baked bytes.
- **Three stored density levels per brick** (brick = affinity cell = 4×4×4 base probes): level 0 = all 64 probes (v-current-identical); level 1 = the 8 corner-lattice probes, trilinear reconstruction at sample time; level 2 = one representative tile (brick mean over valid probes), anchored at the brick's representative probe — the valid probe nearest brick center, x-fastest tiebreak — whose position drives interpolation and whose nominal moments serve the level-2 Chebyshev read. Stored set is additionally intersected with per-probe validity (the at-rest-slimming spec's mechanism); a brick with no valid probe stores nothing and resolves to explicit absence (I1).
- **Authoring parameters with engine backstop:** worldspawn KVPs with CLI overrides for the detail distance and the open-air coarseness floor (mirroring the `_lightmap_density` KVP + `--lightmap-density` override pattern, `crates/level-compiler/src/main.rs:213-218`); a bake-side cap on delta pool bytes with fail-loud overflow; a loader-side engine ceiling — the existing bindable-storage-size guard (`REQUIRED_STORAGE_BUFFER_BINDING_SIZE`, 2 GiB − 8) applied per delta section, distinct from the 64 MiB bake cap and the 128 MiB WebGPU floor.
- **Sampler-side indirection** consumed by every SH reader: the per-probe indirection word (from the at-rest-slimming spec) extended to carry brick level and validity, folded into the dense depth-moments texture's dead B/A channels so it reaches every sampler with no new binding and no new per-fragment fetch; one shared WGSL resolve helper replaces `probe_tile_origin` arithmetic; composed atlases compact to stored probes.
- **Delta sections follow the brick level:** ids 27/41/45 store per-entry bricks at the entry's cell level (8 or 1 probe payloads in coarse cells), plus near-zero entry dropping (encoding: absence from the CSR, which already exists — the empty-cell encoding at `crates/level-format/src/delta_sh_volumes.rs:73-75`).
- **Task 6 findings note:** all measured findings as before → after pairs with ratios; the five recorded decisions (Sequencing).

### Out of scope (non-goals)

- **An arbitrary-depth subdivision hierarchy / coarser-than-brick merging.** The three-level scheme inside the fixed affinity grid already spans 1×–64× per brick; merging bricks would break the workgroup-coupled cell geometry (`AFFINITY_FACTOR` locked at 4, `crates/level-compiler/src/affinity_grid.rs:30-35`). The level field is wide enough that more levels are additive later.
- **Runtime cells as the density key.** Evaluated and rejected (owner measurement, recorded): on campaign-test, 49% of interior cells are smaller than one affinity cell (median shortest edge 0.81 m), while large arena cells would coarsen their floors and ceilings identically to their open volumes. The classifier is surface distance over the brick grid, not cell membership. Do not resurrect cell-keyed density.
- **Probe relocation / virtual offset / dilation.** Position-side fixes for a sampling problem this engine handles read-side (validity + Chebyshev depth-visibility weighting, `context/lib/rendering_pipeline.md` §4 "Probe depth moments"). Probe positions are untouched.
- **Bake-time cost reduction.** Coarse bricks may still bake all 64 probes and store few; skipping unstored probe bakes is a neutral-to-favorable side effect, never a requirement. The known 1.0 m stress-bake host-RAM OOM is a recorded finding, not this spec's problem.
- **Per-cluster streaming / residency.** Separate epic; whole-brick contiguity keeps the layout residency-friendly.
- **Per-brush density-hint volumes.** The worldspawn knobs are map-global; hand-placed densify volumes (the Godot `LightmapProbe` / Unity per-volume-override analog) are deferred breadth — an authoring KVP could bias the classifier later; nothing here forecloses it.
- **Depth-moments compaction.** The per-probe metadata and the 3D moments texture stay dense over the nominal grid (8 B/probe; 1.55 MB at campaign-test scale). One change: the texture's element format goes `Rgba16Float` → `Rgba16Uint` so its previously-zero B/A channels carry the indirection word (Task 4). Moment values are bit-identical, read through `unpack2x16float` (I5); the swap adds no VRAM and no new binding, and dense moments keep the Chebyshev path intact — level-1 corner probes stay nominal lattice probes with real moments.
- **Lowering the requested storage-buffer limit.** `REQUIRED_STORAGE_BUFFER_BINDING_SIZE` stays 2 GiB − 8 (`crates/renderer/src/render/renderer_init_resources.rs:126-134`); whether it can shrink toward the 128 MiB WebGPU floor is a Task 6 recorded decision.

## Direction

**Problem.** Stored SH density is uniform over the world AABB while the lighting signal is not: near surfaces it varies at probe scale, in open volumes it varies slowly — so payload, VRAM, and per-frame compose traffic scale with probe density^≈2.4–2.95 regardless of where the density is needed. Cause, not symptom: every downstream wall (the 2 GiB − 8 binding stopgap, the 2.58 GB id-41 bake, the composed-atlas VRAM) is downstream of uniform per-probe storage.

**Disposition of the superseded draft.** `lighting-scale--adaptive-sh-probe-density` specs the same three-level idea applied only to the id-41 delta payload, with a per-CSR-entry level indirection, over an unchanged uniform base grid. It is **superseded, not orphaned**: the delta payload is defined over the base grid — `affinity_lights.len() × PROBES_PER_CELL × stride` (`crates/level-format/src/delta_sh_volumes.rs:118-121`), `affinity_dims = ceil(base dims / 4)` (`context/lib/build_pipeline.md` id-41 entry) — so a base-grid density change restructures every delta section, and an id-41 v2 contract built on the uniform grid would be rebuilt immediately after this spec landed. What carries forward from it (verified there, re-anchored here): the stress-sweep measured basis and payload identity; the read-equivalence argument (per-frame direct-compose traffic equals stored payload of active lights); the three-level rescope arithmetic and the rejection of two-level and tree schemes; the drop mechanism as a co-primary lever; the f16/f32 Pascal contract; the 64 MiB / 128 MiB two-tier cap posture; and the industry survey (retained in that draft as source material — read it for peer-mechanism detail rather than re-deriving). What this spec changes: the level is keyed to the **brick via the base grid** and set by one classifier; base atlas, composed atlases, and all three delta sections inherit it; the sampler — which the superseded draft deliberately avoided touching — is now the load-bearing change. Whether a *delta-only* refinement beyond the inherited brick level (per-entry level overrides, per-probe occupancy bitmaps) is still worth a spec is Task 6 decision (4).

**Why the sampler must change (and the superseded draft's no-sampler stance cannot carry over).** The SH volume is the world's sole indirect path: forward samples the octahedral atlas per fragment for world geometry (`context/lib/rendering_pipeline.md` §7.3 per-fragment list), and the same probe walk serves fog, billboards, skinned meshes, and kinematic movers via the shared helpers in `sh_sample.wgsl`. A dense composed atlas is what let the superseded draft keep samplers untouched — and the dense composed atlas is exactly the VRAM and per-pixel bandwidth this spec exists to cut. Compacting the composed atlas forces every reader through the indirection. That is the quality-spending seam: coarse bricks reconstruct at sample time, and brick-boundary seams are the failure mode the spike's error measurement and the manual A/B both target.

**One policy for two receiver classes.** Probe density serves static surfaces *and* dynamic receivers — players, enemies, movers crossing open air (`context/lib/rendering_pipeline.md` §4 "Baked direct for dynamic receivers": binding-15 consumers). A policy keyed only to surface proximity would zero out open volumes that entities traverse. Hence the coarseness **floor**: no brick stores fewer than one tile (level 2), never zero — open air stays lit at coarse density, and the floor is an authorable knob, not a constant.

**Fail loud, degrade by explicit choice — the cap posture, decided.** Peers degrade at the cap: Unreal silently culls detail bricks under `MaximumBrickMemoryMb`, HDRP drops shadow maps, Godot shrinks atlas slots. The house posture is fail-loud. The call: **bake-time overflow is a hard, named error — never a silent quality contraction — but the error is one step from the degrade the peers automate:** it reports the map, the cap, the overage, and the *computed coarsening that would fit* (the detail-distance value at which the projection lands under cap), so the author's informed retry is a single flag or KVP edit. Rationale: a static bake can afford to refuse where a runtime system must degrade (the Godot-posture argument the superseded draft already established); silent culling makes quality drift invisible in exactly the tool modders use to judge their maps; and printing the fitting value delivers the peers' convenience without their silence. The loader independently rejects any delta section over the engine ceiling — the existing bindable-storage-size guard (`REQUIRED_STORAGE_BUFFER_BINDING_SIZE`), not a new constant — all-or-nothing, matching the existing id-41 posture. Runtime keeps the existing clean-disable degrade for structurally oversized resources (`context/lib/rendering_pipeline.md:376`) — a load-time reject, not a silent quality loss.

**Alternatives rejected.**
- *Two levels (64/8) + drops* and *arbitrary-depth trees:* rejected by the superseded draft's rescope arithmetic, which transfers unchanged — the all-L2 structural limit lands under budget by construction at the shipping default, two levels cannot reach the binding floor without extreme drop rates, and extra tree depth only helps where entries are drop candidates anyway.
- *Cell-keyed density:* rejected on owner measurement (non-goals).
- *Delta-only adaptivity (the superseded draft's shape):* leaves base-atlas and composed VRAM and sampler bandwidth untouched, and its format contract would be rebuilt when the base grid moves — the reason it is superseded rather than sequenced first.
- *Authored density volumes as the primary mechanism* (hand-placed detail regions, no classifier): shifts the whole burden onto mappers and defaults to uniform for every map that doesn't author them — the classifier gives every map the win by default; hand hints remain a deferred additive.

### Task 2: format contracts — id-34 level semantics + delta version bumps (level-format)

Locks the on-disk contracts everything downstream compiles against. **id 34** (`crates/level-format/src/sh_volume.rs`): bump `SH_VOLUME_VERSION` (the at-rest-slimming spec's v9 established the per-probe density-level field as reserved-zero; this bump makes 0/1/2 valid, brick-uniform — every probe in a 4×4×4 brick carries the same level, validated at parse). The compact-payload membership rule becomes: a probe is stored iff its validity byte is nonzero AND it lies on its brick's level lattice — level 0: all 64; level 1: in-brick local coordinates ∈ {0,3} per axis; level 2: no lattice probe — the brick stores one representative tile (mean over the brick's valid probes) appended in the same x-fastest brick order, and the parse-time length identity sums per-brick stored counts. **Deltas** (`crates/level-format/src/delta_sh_volumes.rs` for id 27; the id-41/45 siblings alongside it): bump each section version; per-entry payload stride becomes a function of the entry's cell level — 64, 8, or 1 tiles — with the dense-payload identity (`crates/level-format/src/delta_sh_volumes.rs:118-121` and its parse mirror) replaced by the per-level identity summed over entries; entry order, CSR shape, `affinity_offsets`/`affinity_lights` semantics, and the existing empty-cell absence encoding are unchanged; entries whose cell is level 2 store 1 tile (the entry's brick-mean delta); dropped entries are simply absent from the CSR. Each delta section self-describes its per-entry cell level, so it parses standalone; the payload stride is validity-independent (64/8/1 by level — validity masks at read via the word, I3), keeping the prefix-sum derivation a pure function of the levels. Parse validates: known level per entry, stride/coverage identities, monotonic implicit offsets (per-entry offsets remain derivable by prefix-summing per-level strides in entry order — pin that as the rule; no per-entry offset table unless the implementer shows derivation is insufficient, in which case the table is monotonic and exactly covering). The loader then cross-checks every delta entry's level against id-34's brick level for the same cell and rejects mismatch through the all-or-nothing arm (I3, I7). All version rejects use the existing named recompile error shape; no compat shim (`context/lib/development_guide.md` §1.6). Round-trip and reject tests per section, including mixed-level fixtures and the level-2 single-tile case.

### Task 3: compiler emission — classifier, knobs, cap (level-compiler)

Emit the adaptive sections from the Task 2 contracts. **Classifier:** per brick, choose the level from surface distance (thresholds seeded from Task 1's recorded error data; if the spike showed proximity is a poor error proxy, key directly on measured reconstruction error — the format is policy-agnostic), floored at level 2 — no brick stores zero base tiles. Delta entries inherit their cell's level; entries the spike's near-zero oracle marks negligible are dropped (not emitted into the CSR). **Authoring knobs, mirroring the `_lightmap_density` worldspawn-KVP + CLI-override pattern (`crates/level-compiler/src/main.rs:213-218`, precedence test at `crates/level-compiler/src/main.rs:1778`):** `_sh_detail_distance` (meters; bricks nearer than this to a surface stay level 0) with CLI `--sh-detail-distance`, and `_sh_open_air_level` (the coarseness floor for far bricks, 1 or 2) with CLI `--sh-open-air-level`; boundary inventory below pins the names. **Cap:** `--sh-delta-max-size`, default 64 MiB, same size grammar as `--cache-max-size` (`parse_size`, `crates/level-compiler/src/main.rs`); during emission accumulate delta pool bytes across ids 27/41/45; on overflow, fail loud with the named error carrying map, cap, overage, and the computed detail-distance that would fit (binary-search the projection — the classifier is a pure function of the distance knob). If even detail-distance 0 (every far brick already at the open-air floor) overflows, no distance fits: the error says so and names the floor as the lever — drop `_sh_open_air_level` to 2, or the cap is infeasible for the map. Non-zero exit, nothing emitted. **Stats:** per-level brick histogram, per-section bytes, drop count — one info line per stage, detail under `-v/--verbose` (Invariant I8). **Cache:** grid layout, probe values, and validity are unchanged inputs, so the `sh_group` value cache stays valid (`SH_GROUP_STAGE_VERSION`, `crates/level-compiler/src/sh_group.rs:49`); level selection and emission are encode-side. The dense per-entry payload identity lives in **two** sites, both moving to the per-level identity in lockstep with Task 2: the parse check in `crates/level-format/src/delta_sh_volumes.rs:118-121`, and a second copy inside `direct_sh_delta_has_valid_csr_shape` (`crates/level-compiler/src/pack.rs`) — the CSR-shape length check reached on the id-41 emission gate via `direct_sh_delta_is_usable_for_selection` (whose result feeds `has_usable_direct_sh_deltas`, `pack.rs`). That check asserts `affinity_lights.len() × PROBES_PER_CELL × delta_probe_f16_stride() == delta_subblocks.len()`, hardcoding 64 probes/entry; under variable per-entry strides it fails for every adaptive id-41 payload and would silently drop id-41 (and `EntityShadowLights` / `ShadowmaskAtlas`) from emission. Replace it with the per-entry-level-summed length identity. Only `direct_sh_delta_covers_selection` (selection-index coverage) and the dims/tile/border equality in `direct_sh_delta_is_usable_for_selection` are genuinely stride-agnostic and carry over unchanged; ids 27/45 serialize unconditionally (`pack.rs`). The pinned selection-index test posture holds: `affinity_lights` values remain selection indices; adaptivity changes payload strides, never light numbering.

### Task 4: indirect atlas end-to-end through the resolve (renderer + WGSL)

The probe-resolve contract on the indirect (total octahedral) atlas — its producer and every consumer — consuming Task 3's real `.prl`s. The direct atlas stays dense until Task 5; the atlas is the seam, not the pass type, because the total atlas is shared by every sampler and compacting it forces all of them through the resolve at once.

**(a) Indirection word in the moments texture.** The at-rest-slimming landing already builds one `u32` per nominal probe — `build_probe_indirection_words` (`crates/renderer/src/render/sh_compose.rs:465`), each word the probe's compact valid-probe slot or the `INVALID_PROBE_INDIRECTION` (`u32::MAX`) sentinel. Extend each word to carry brick level (reserved high bits) and validity alongside the slot, and replace the slot derivation — today a dense valid-probe rank — with the level-dependent stored set (level 0: 64 tiles; level 1: 8 corner tiles; level 2: one representative tile), sentinel = probe not stored. Carry the extended word to every sampler by folding it into the dense depth-moments texture's dead B/A channels: switch `BIND_SH_DEPTH_MOMENTS` from `Rgba16Float` to `Rgba16Uint`, write the word's two `u16` halves into the B/A texels `pack_probe_depth_moments` (`crates/renderer/src/render/sh_volume.rs`) leaves zero today, and read it back as `word = b | (a << 16)`; moments decode from R/G via `unpack2x16float` (I5, values bit-identical). This adds no binding — the moments texture is already bound in every SH stage (group 3, and the mesh group-4 superset) — and the word rides the moments load the corner walk already performs (a path that skipped moments trades removed tile-origin arithmetic for one `textureLoad`). ## Wire format

Constraint-level per `context/lib/context_style_guide.md` — no invented offsets; field order, packing, and exact encodings are implementer-pinned at landing. All sections keep their existing conventions: little-endian, section-internal version first, named reject on mismatch.

- **id 34:** version bump over the at-rest-slimming v9. The per-probe density level becomes meaningful: values 0/1/2, brick-uniform (all 64 probes of a 4×4×4 brick carry the same value; parse rejects non-uniform bricks and unknown values — higher values reserved). Compact-payload membership: valid AND on the brick's level lattice (level 0: all; level 1: local ∈ {0,3}³ in canonical corner order — x fastest, z slowest; level 2: none — one brick-mean representative tile stored instead, in the same x-fastest brick order). Base membership, delta payload, and the sampler's corner resolve all enumerate the level-1 corners in this one canonical order. Parse-time length identity sums per-brick stored counts; grid geometry fields keep their meaning.
- **ids 27 / 41 / 45:** version bump each. CSR shape, entry order, `affinity_offsets`/`affinity_lights` semantics, selection-index meaning (id 41/45), and the empty-cell absence encoding are unchanged. Each section self-describes its per-entry cell level, so it parses without id 34 in hand; the loader then cross-checks each level against id-34's brick level for the same cell and rejects mismatch all-or-nothing. Per-entry payload = stored-count(cell level) × tile stride — 64, 8, or 1 tiles — laid contiguously in entry order, validity-independent (validity masks at read via the word); per-entry offsets are derivable by prefix-summing per-level strides (no offset table unless derivation proves insufficient, in which case the table must be monotonic and exactly covering). Level-1 delta bricks store the 8 corner-lattice probes' tiles in the canonical corner order (above); level-2 store the entry's brick-mean tile. Dropped entries are absent from the CSR. Parse validates stride/coverage identities and known levels on the section's own declaration.
- **The invariant the formats serve:** a world position resolves deterministically — nominal probe coordinate → indirection word → (brick level, stored-tile location) or explicit absence — with identical answers at bake, parse, load, compose, and sample. Base and delta agree on every cell's level; the loader proves this before the first compose, so no runtime path derives one from a stale copy of the other.

## Open questions / risks

- **Brick-boundary seams.** Adjacent bricks at different levels reconstruct differing values at shared corners; level 2's brick-center representative is the flattest and likeliest seam source. Task 1 measures exactly this before any bytes change; the residual (a mis-chosen threshold) is watched by the manual A/B at level boundaries. If seams demand it, the known mitigation direction is corner-sharing (level-1/2 bricks contributing to shared lattice positions) — not specced here; it would be a Task 6-recorded follow-on, not an agent improvisation.
- **Sampler cost.** The resolve replaces `probe_tile_origin` arithmetic with a word the corner walk gets for free from the moments texture it already loads (the word rides moments' B/A). Net per-fragment cost is near-zero — the added work is the level branch and stored-position math, not a fetch. The 10-series compose-time measurement stays an AC: if the resolve unexpectedly eats the bandwidth win, that is a recorded finding for Task 6, not a silent optimization hunt.
- **Base/delta level agreement.** Base (id 34) and delta (ids 27/41/45) are independently-parsed sections that must agree on every cell's level; a mismatch would misalign the CSR tail silently and pass every per-section check. Foreclosed structurally: each delta self-describes its level, and the loader cross-checks against id 34 and rejects all-or-nothing before the first compose (I3, I7) — not left to construction-by-convention.
- **Threshold choice.** Detail distance and the error thresholds are seeded from Task 1 data as compile-time defaults with the two authored knobs on top. The drop threshold deserves the most care: drops are the one class with no reconstruction at all.
- **Recorded and external inputs.** The stress/campaign sweep bytes, the 75 K/600 K/12 M genre brackets, the runtime-cell rejection stats (49% / 0.81 m), the GTX 1060 / 5500M hardware figures, and the Pascal fp16 1/64 rate are recorded or external inputs, not re-derived from this tree; the spike's anchor ACs re-derive the in-tree ones before projections are trusted.
- **Two-spec coupling (verified against landed code).** The at-rest-slimming feature has landed on main; its pins are confirmed present: `SH_VOLUME_VERSION = 9` with a reserved-zero per-probe `density_level: u8` that v9 rejects-if-nonzero (`crates/level-format/src/sh_volume.rs`), the compact valid-probe-only atlas in x-fastest probe order, and one `u32` indirection word per nominal probe (`build_probe_indirection_words`, `crates/renderer/src/render/sh_compose.rs:465`). One divergence from this spec's earlier assumption, already folded into the tasks: that word is **compose-only** today (group 1 binding 26), not yet shared with samplers, and carries only the compact slot. Task 4 extends it (level + validity) and carries it to every sampler by folding it into the depth-moments texture's B/A channels (I4) — no shared storage buffer, because forward's FRAGMENT stage is already at 8/8 storage buffers. Task 2 (format) and Task 4 (runtime word) both re-verify against the landed code, not the sibling spec text.
