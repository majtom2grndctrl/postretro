# Lighting Scale — Delta-SH Valid-Probe Compaction

> **Status:** draft. Not promoted. No `context/lib/` updates until promotion.
> **Track:** Lighting / build pipeline — extend the shipped base-atlas valid-probe compaction to the three sparse SH delta sections.
> **Related:** `context/lib/build_pipeline.md` §PRL section IDs (ids 27/41/45, 34/35) · `context/lib/rendering_pipeline.md` §4 ("Animated SH delta volumes", "Animated direct SH", "Promoted static lights"), §7.1 step 5 · `context/lib/experimental_spikes.md` · shipped precedent `lighting-scale--sh-base-atlas-at-rest-slimming` (main) · stopped successor `context/research/archived-plans/lighting-scale--adaptive-base-probe-density/` (density coarsening) · sibling `research.md`.

## Goal

The shipped `sh-base-atlas-at-rest-slimming` compacts the BASE indirect octahedral atlas (id 34) to valid-probe-only tiles. The three sparse SH **delta** sections do not: id 27 `DeltaShVolumes`, id 41 `DirectShDeltaVolumes`, and id 45 `AnimatedDirectShDeltaVolumes` each store `affinity_lights.len() × PROBES_PER_CELL(64) × stride` — every retained `(affinity-cell, light)` CSR entry carries all 64 probe slots, including in-solid (invalid) probes that carry no signal and are never read on the indirect path. This spec compacts each retained entry to its cell's **valid probes only**, losslessly, in a named post-drop compaction pass (the bake keeps emitting dense-64; see Direction). The composed atlases and every SH sampler are untouched *as code*: the change is confined to the delta storage and the three compose passes that read it. Parity scope differs by path — the id 27 **indirect** composed atlas stays **full-atlas** f16-bit-identical (it stores 0 at invalid probes both ways, and its compose early-outs invalids via the base `probe_indirection` word); the id 41 **direct** and id 45 **animated-direct** composed atlases are f16-bit-identical **only at valid-probe texels**, because those passes have no invalid early-out and legitimately write `base` at invalid direct texels after compaction. That is safe because the SH sampler zero-weights invalid corners (`sh_sample.wgsl` validity-weighting, ~`:157,249`) — the sampler is not edited, but the parity gate depends on it (see AC gate 1, D2, C1).

## Scope

### In scope

- **Compact each retained delta CSR entry to valid-probes-only,** in a new named post-drop compaction pass (`apply_valid_probe_compaction`, `crates/level-compiler/src/delta_sections.rs`; see Direction), not in the bake. Per-entry payload becomes `valid_count(cell) × tile_stride` instead of `64 × tile_stride`. Within-cell storage order is the existing x-fastest local order, filtered to valid probes.
- **Three sections:** id 27 (indirect), id 41 (direct), id 45 (animated-direct). Section-internal version bump each; loader validation; fail-loud rejects; no compat shim.
- **A per-cell valid-probe descriptor** carried by each delta section (self-validating; carrier resolved — see Direction and Task 1) so the compose pass resolves `(cell, local_probe) → stored slot | absent`, and so the loader cross-checks it against the id-34 validity that is the single source of truth and fails loud on any disagreement.
- **Compose-pass resolution** in the three delta compose shaders (`sh_compose.wgsl`, `direct_sh_compose.wgsl`, `animated_direct_sh_compose.wgsl`), their render-cpu buffer builders, and the `renderer` crate wgpu wiring (the descriptor + entry-offset prefix are new storage buffers created and bound in `crates/renderer/src/render/sh_compose.rs`, Renderer-owns-GPU). The composed (total/direct) atlases keep their dense geometry; samplers keep arithmetic reads.
- **Bake + compaction sites.** The bake sites `delta_sh_bake.rs` (id 27), `direct_sh_bake.rs` (id 41), `animated_direct_sh_bake.rs` (id 45) keep emitting dense-64; the compaction pass consumes the post-drop section and emits the compacted section + descriptor. The 64-probe wire identities (`crates/level-format/src/delta_sh_volumes.rs` `to_bytes`/`from_bytes` and siblings; `direct_sh_delta_has_valid_csr_shape` in `crates/level-compiler/src/pack.rs`) become the summed per-cell identity over the compacted on-disk section.
- **Interaction with the exact-zero drop policy and the payload cap** (`crates/level-compiler/src/delta_sections.rs`, `delta_drop_policy.rs`): the exact-zero drop runs first and **unchanged** on dense-64; the compaction pass runs after it; only the payload cap (`enforce_payload_cap`) accounts compacted bytes. The SET of dropped entries is identical whether the drop sees dense-64 or compacted input (invalid probes are dead-zero), so the ordering is mechanics, not behavior drift. Model this in the value framing and ACs.
- **Measured before→after** via the shipped `--sh-analyze` instrument (`(a)compacted` byte line) and `POSTRETRO_GPU_TIMING`.

### Out of scope (non-goals)

- **Density coarsening / adaptive per-brick level (64/8/1).** Dropping *valid* probes is lossy and owned by the stopped-and-reopened successor (`archived-plans/lighting-scale--adaptive-base-probe-density`). This spec drops only invalid probes. See Direction for the seam.
- **Composed-atlas compaction and the sampler resolve rework.** The total/direct composed atlases stay dense; `probe_tile_origin` and `sh_sample.wgsl`'s corner walk are untouched. That whole-SH-reader rework is coarsening's, not compaction's (Direction).
- **id 35 `DirectShVolume` (dense-BC6H base for the direct compose).** Its at-rest compaction is not part of this spec; the direct compose reads it dense today and continues to. Only the delta payload it companions is compacted.
- **id 42 `ShadowmaskAtlas` (`shadowmask_bake.rs`).** Despite being listed as a bake site in the task framing, id 42 is a per-texel world-visibility atlas (`width × height × layer × RGBA`, `crates/level-format/src/shadowmask_atlas.rs`), not affinity-cell × 64-probe. It has no invalid-probe axis to compact. Excluded, with cause.
- **A cap-selection / drop-to-fit-by-light policy.** The current cap is a hard error, not a selection (Direction, Open Questions). Building one is a separate owner decision.
- **New per-frame runtime knobs.** No user-facing settings; measurement is log-line / dev-tools footprint only.

## Direction

**Problem (cause, not symptom).** The delta sections store a fixed 64 probes per retained CSR entry regardless of how many are valid. On `stress-warren-showcase.map` at 2 m spacing only 59% of base probes are valid (67,838 / 115,200); near-surface affinity cells — where deltas concentrate — carry a large in-solid fraction. Every invalid slot is dead weight in `.prl`, in the GPU delta storage buffer at rest, and in the bytes the compose pass streams for each active light. The base atlas already pays this only for valid probes; the deltas do not. Cause: the delta payload stride is `PROBES_PER_CELL`, a compile-time constant, not the cell's valid count.

**How this is priced — honestly (read this before claiming a win).** Measured on the stress map (`--sh-analyze`, the just-completed spike, using the emitted/shipped delta set — post static-light selection and exact-zero drop; an earlier tool version measured a ~4.6× inflated pre-filter superset, since corrected): id 41 shipped delta payload 47.9 MB → valid-probe-compacted 26.4 MB (0.55×); id 27 22.3 → 11.8 MB (0.53×), id 45 20.9 → 11.3 MB (0.54×); total deltas (ids 27/41/45) 126.4 MB → 69.0 MB (0.55×). Holding map content fixed, compaction reduces three things by roughly that ratio: (1) `.prl` on-disk delta bytes; (2) at-rest delta VRAM (the `delta_subblocks` storage buffers, `ComposeStorageFootprint.delta_subblocks_bytes`, `crates/render-cpu/src/sh_compose.rs`); (3) per-frame compose traffic (the compose reads each active entry's payload; smaller entries = fewer bytes read).

The honest caveat on (3): whether the per-frame reduction *materializes as bandwidth saved* or *as quality gained* depends on author behavior against the delta payload cap (`DEFAULT_MAX_PAYLOAD_BYTES = 256 MiB`, `delta_sections.rs:15`). If content is held fixed, all three wins are real and the cap does not bind (measured shipped id 41 ≈ 48 MB after exact-zero drop, far under 256 MiB). If authors instead bake maps up to the cap ceiling — pushing light count and probe density until the aggregate delta payload nears the cap — the headroom compaction frees is spent on more lights / finer density, and the realized win is **higher lighting quality at roughly equal shipped bytes and equal per-frame traffic**, not reduced traffic. Both are true; they are different content counterfactuals. This spec therefore **measures** the byte/VRAM/traffic deltas and **records** them (spike doctrine: findings, not gated targets); it does not contract a per-frame-bandwidth target as a deliverable, and it does not claim the quality win as automatic — that win is an author choosing to spend the headroom.

**Correction to the "cap that drops whole lights" framing.** The shipped cap (`enforce_payload_cap`, `delta_sections.rs:125`) is a **hard, named compile error** when the aggregate exceeds the cap — it does not fit maps by dropping lights, and it performs no light selection. The only shipped dropping is `apply_exact_zero_drop_policy` (`delta_sections.rs:69`), which removes CSR entries whose entire 64-probe payload decodes to exactly zero — lossless, and unrelated to the cap (it runs regardless). So "more lights survive the cap's selection" does not describe current behavior: there is no selection. What compaction actually does to the cap is **raise the light/density ceiling that compiles under a fixed cap** (each retained entry is ~0.55× smaller, so ~1.8× the entries fit before the hard error). Whether the project wants a future *drop-to-fit-by-selection* policy is an owner decision recorded in Open Questions; it is not built here and this spec does not depend on it.

**Prior commitments this touches.**
- **Base-atlas at-rest slimming (shipped, main).** Established valid-probe compaction for id 34, the v9 `SH_VOLUME_VERSION` with a reserved-zero per-probe `density_level`, and `build_probe_indirection_words` (`crates/renderer/src/render/sh_compose.rs:465`) — one `u32` per nominal probe carrying the probe's **global** compact slot or `INVALID_PROBE_INDIRECTION`. This spec reuses that feature's validity source and load-time-derivation pattern (see below) and its fail-loud/no-compat-shim posture (`development_guide.md §1.6`).
- **The affinity CSR substrate.** `AFFINITY_FACTOR = 4`, `affinity_dims = ceil(base_dims / 4)`, CSR `affinity_offsets`/`affinity_lights`, x-fastest in-cell probe order. Unchanged; compaction changes only per-entry payload length and its indexing.
- **Exact-zero drop + hard-error cap.** The exact-zero drop stays first and **literally unchanged**, operating on dense-64 (it removes whole-cell zero entries); the named compaction pass (`apply_valid_probe_compaction`) runs after it and shrinks the survivors; only the hard-error cap is re-accounted to compacted bytes. The dropped-entry SET is identical whether the drop sees dense-64 or compacted input (invalid probes are dead-zero), so this ordering is mechanics, not behavior. Full pipeline: bake(dense-64) → exact-zero drop → compaction pass → `enforce_payload_cap`.
- **f16 at rest / f32 arithmetic.** Payloads stay `Rgba16Float`, read through `unpack2x16float`; no WGSL `enable f16`. Preserved.

**Reuse vs. parallel indirection — and why the shared base word cannot directly serve.** The task asks: reuse the base-atlas indirection-word infra, don't invent a parallel one unless justified. The justification exists and is structural. `build_probe_indirection_words` yields each probe's **global** valid-rank (its slot among all valid probes, whole-grid x-fastest). The delta needs each probe's **within-cell** valid-rank (its slot among the valid probes of its own 4×4×4 cell) plus the entry's payload **base offset** (pinned as a CPU-precomputed per-entry offset array carried in a buffer — see the per-entry-offset Alternative below). A cell's 64 probes are **non-contiguous** in whole-grid x-fastest order, so within-cell rank is not a cheap function of global rank — the shared word is the wrong rank space. What *is* reused: the **validity source** (id-34 probe metadata validity, "the sole source of truth"), the **load-time derivation pattern** (`build_probe_indirection_words`-style, deriving from id-34, never serialized as new PRL bytes on the runtime side), and the **compose-only carrier** shape. The delta's own resolver is a per-cell valid-probe descriptor (recommend a 64-bit mask per affinity cell): `is_valid(local) = (mask >> local) & 1`; `within_cell_rank(local) = countOneBits(mask & ((1u64 << local) - 1))`; `valid_count(cell) = countOneBits(mask)`. The mask doubles as the section's self-validation carrier (its popcount fixes the entry payload length) and as the compose-time resolver — one artifact, no separate side table. This is a sibling of the base word built by the same infrastructure, justified because the base word's rank space does not answer the delta's question.

Additional structural note the base word does not cover: the id 41 / id 45 direct compose passes (`direct_sh_compose.wgsl`, `animated_direct_sh_compose.wgsl`) read a **dense** direct base atlas (id 35) and today bind **no** per-probe indirection at all — unlike the indirect compose, they have no invalid-probe early-out to reuse. Compaction introduces the per-cell descriptor into those passes for the first time.

**Alternatives rejected.**
- *Merge into density coarsening (make it one spec).* Rejected. Coarsening is lossy (drops valid probes; needs an error/seam budget, a gate spike, and manual A/B) and reworks every SH sampler plus the composed atlases; compaction is lossless (drops only zero-signal probes; f16-exact parity is the gate) and touches only the compose internals. Merging blocks a shippable lossless win behind a stopped/reopened lossy plan (the successor is archived pending a research spike). Compaction is the clean prerequisite that pre-builds coarsening's variable-stride delta substrate. Full argument and the exact seam handed forward: `research.md` §Separability.
- *Per-entry offset table instead of a per-cell descriptor.* Rejected as a **replacement** for the descriptor: the mask carries validity (`is_valid`/`within_cell_rank`) and self-validates the payload length, which a bare offset table cannot, and it does not answer `is_valid(local)`. The two are complementary, not alternatives. The entry payload **base offset** is **not** shader-summed: it is pinned as a **CPU-precomputed per-entry offset array**, derived at LOAD from the final post-drop CSR in entry order (== payload write order, x-fastest within cell) and carried in a buffer the shader indexes as `offset[entry]`, for all three sections. The compose resolver is `offset[entry] + within_cell_rank(local) × stride`: the array supplies the base, the mask supplies the in-entry rank and validity. The offset array never replaces the validity carrier.
- *Ship id 41 only, defer id 27/45.* id 41 dominates (47.9 MB vs 22.3/20.9 MB for id 27/45 on the stress map; the gap widens on lighter maps) and Task 2 proves the whole substrate on it alone. Rejected: id 27/45 are pure fan-out over the proven slice (Tasks 3–4, cheap), and leaving them at 64-probe stride strands a permanent format asymmetry that the density-coarsening successor — which needs all three sections variable-stride — would have to finish anyway. Do all three now.
- *Compact the composed atlases too, "while we're here."* Rejected — that forces every sampler through a resolve, is coarsening's blast radius, and buys nothing for the delta (the composed atlas is written by compose and read by samplers arithmetically; the delta storage is the only place invalid probes cost bytes). Kept as an explicit non-goal.
- *Derive validity at load only from id 34, carry nothing in the delta section.* Rejected for fail-loud: a delta section that cannot validate its own payload length standalone, and cannot be cross-checked against id-34 validity, would misalign the CSR tail silently on any disagreement. Each section self-describes its per-cell descriptor and the loader cross-checks it against id-34 (mirrors the successor's base-vs-delta cross-check posture).

**One-way doors / foreclosures.** The section version bumps are one-way (no compat shim, by house posture) — a pre-bump `.prl` rejects with the named recompile error. That is cheap to walk back (a re-bake), matching the existing delta-format and at-rest-slimming posture. Nothing here forecloses density coarsening; it is designed to be coarsening's substrate. Nothing forecloses a future cap-selection policy. No runtime-observable behavior changes for shipped maps beyond identical lighting at fewer bytes (the parity gate).

## Acceptance criteria

Per `experimental_spikes.md`, split into honesty gates (automated: correctness/rejects/parity) and measured findings (recorded, not thresholds to iterate toward). This is a hardened lossless feature, so parity is a hard gate.

**Honesty gates:**

- [ ] **Lossless parity.** For each of the three sections, on `content/dev/maps/stress-warren-showcase.map` and `content/dev/maps/campaign-test.map`, the composed atlas is **f16-bit-identical** to a dense-64 reference for the same bake inputs, scoped per path: **full-atlas** for id 27 (indirect total — it stores 0 at invalid probes both ways, and the compose early-outs invalids via the base `probe_indirection` word, binding 26); **only at valid-probe texels** for id 41 (direct composed) and id 45 (animated-direct), whose passes have no invalid early-out, so after compaction an invalid direct texel legitimately becomes `base`. Writing `base` there is safe because the SH sampler zero-weights invalid corners (`sh_sample.wgsl` validity-weighting, ~`:157,249`) — named explicitly, though samplers are otherwise out of scope, because the implementer must trust it to freely write `base` at invalid direct probes and to trust the gate. Parity holds because compaction drops only probes never read at a valid texel and reorders nothing a reader sees. **Oracle:** an in-test dense-64 reference composer over identical bake inputs (or a committed golden atlas) — no compat shim exists, so "compose both ways" is reference-vs-compacted, not old-loader-vs-new. **Weights:** id 41 is promotion-gated (`selection_weights`), so its parity read requires a nonzero **promotion** weight (at-rest all-zero would make the id-41 read never run — a vacuous pass); id 27/45 use a nonzero **animation** weight. Verified by a compiler/renderer-level test, at rest and under the required nonzero weight.
- [ ] **Self-consistent sections.** Both maps compile end-to-end to `.prl`s whose delta sections are internally consistent: every retained entry's payload length equals `valid_count(cell) × tile_stride`, the per-cell descriptor's popcount matches, entry order and CSR shape are unchanged, and the empty-cell / dropped-entry absence encoding is unchanged. Asserted at bake, self-validated at parse.
- [ ] **Base↔delta validity agreement, fail-loud.** The loader cross-checks each delta section's per-cell descriptor against id-34 probe validity for the same cell **before** the render-cpu builder sizes or fills the compacted buffer or derives the entry-offset array (that buffer build happens between parse and dispatch), never a wgpu validation crash. A descriptor↔id-34 disagreement is corruption or version-skew: for **id 27 and id 45** it is a **named hard load error, all-or-nothing** (nothing composed). For **id 41** it clears the existing all-or-nothing selection set — id 40 `EntityShadowLights` + id 41 `DirectShDeltaVolumes` + id 42 `ShadowmaskAtlas` together — matching the existing direct-path posture, and the compacted buffers are never built. A pre-bump section version rejects with the named recompile error; no compat shim.
- [ ] **Cap + exact-zero drop re-accounted.** The exact-zero drop still removes whole-zero entries first, **unchanged on dense-64**; the compaction pass runs after it; the payload cap (`enforce_payload_cap`) counts **compacted subblock bytes only** (the per-cell descriptor is excluded from the cap); over-cap is still the named hard error naming all three ids. A fixture set below cap compiles; a fixture with the cap set below the compacted need fails loud. No silent degrade.
- [ ] **No budget / binding regression.** Both maps boot to first rendered frame with no wgpu validation errors; the composed atlas geometry and the sampler bind groups are unchanged. Per-stage storage/sampled-texture counts are unchanged **at the consumer/sampler stages** (forward, fog, billboard, skinned, kinematic) — compaction never reaches them. The **three compose passes** legitimately gain the per-cell descriptor (+ entry-offset prefix) binding(s); that is expected, not a regression. Final counts stated in the findings note.

## Tasks

### Task 1: format contracts — id 27/41/45 versions + per-cell valid descriptor (level-format)

Lock the on-disk contracts everything downstream compiles against. For `crates/level-format/src/delta_sh_volumes.rs` (id 27) and its siblings `direct_sh_delta_volumes.rs` (id 41) and `animated_direct_sh_delta_volumes.rs` (id 45): bump each section-internal version. Replace the fixed per-entry payload identity (`affinity_lights.len() × PROBES_PER_CELL × stride`, asserted in `to_bytes`/`from_bytes` and mirrored in `direct_sh_delta_has_valid_csr_shape`, `crates/level-compiler/src/pack.rs:216-221`) with a per-entry identity summed over entries: entry `e`'s payload length is `valid_count(cell(e)) × stride`, where `valid_count(cell)` is the popcount of that cell's stored valid-probe descriptor. (Naming, reconciled once: `FORMAT_PROBES_PER_CELL` is the bake-site name for the same 64 as `PROBES_PER_CELL`; `stride` == `tile_stride` == `delta_probe_f16_stride`.) For **id 45** specifically, this per-entry length identity is centralized in `AnimatedDirectShDeltaVolumesSection::validate_wire_contract` (`animated_direct_sh_delta_volumes.rs:104`), reached by both `try_to_bytes`/`to_bytes` and `from_bytes` — a single hard `Result`-returning site, unlike id 27/id 41's two body-local `debug_assert`s; make the id-45 edit there. Add the descriptor to the wire layout: **one 64-bit mask per affinity cell** (`affinity_cell_count` masks), carried in the section — the carrier is **resolved** to a self-validating per-section mask (not derive-and-cross-check), self-describing so the section validates its own payload length standalone. It must answer `is_valid(local)`, `within_cell_rank(local)`, and `valid_count(cell)`, and must let the loader cross-check against id-34 validity. Parse validates: known version, descriptor present and well-formed, per-entry payload length identity, CSR monotonicity and coverage unchanged, empty-cell/absence encoding unchanged. All version rejects use the existing named recompile-error shape (`from_bytes` version guard); no compat shim (`development_guide.md §1.6`). Within-cell storage order stays x-fastest, filtered to valid probes — pin that as the one canonical order the bake writes and the compose reads. Round-trip and reject tests per section, including a fully-valid cell (identical to today's 64-probe layout), a mixed-validity cell, and an all-invalid cell (zero stored tiles) fixture.

### Task 2: id 41 thin slice — bake dense-64 + compaction + direct compose + parity (level-format + level-compiler + render-cpu + renderer + WGSL)

Replace the hardcoded 64-probe length check in `direct_sh_delta_has_valid_csr_shape` (`pack.rs:216-221`) with the summed per-cell identity over the compacted section; `direct_sh_delta_covers_selection` and the dims/tile/border checks in `direct_sh_delta_is_usable_for_selection` (`pack.rs:224`) are validity-agnostic and carry over unchanged. **render-cpu** (`crates/render-cpu/src/sh_compose.rs`): `build_direct_delta_buffers` / `DirectDeltaComposeBuffers` carry the per-cell descriptor and the CPU-precomputed per-entry offset array (derived at load from the post-drop CSR in entry order == payload write order); `ComposeStorageFootprint` counts the compacted `delta_subblocks`. ### Task 3: id 27 — indirect delta compaction + compose (level-compiler + render-cpu + renderer + WGSL)

## Open questions

- **Cap-selection policy (owner decision).** The current cap is a hard error with no light selection; the task framing described a "cap that fits by dropping whole lights," which the shipped code does not do (`enforce_payload_cap` errors; `apply_exact_zero_drop_policy` drops only exact-zero entries). Compaction raises the ceiling that compiles under a fixed cap but does not add selection. Does the owner want a future drop-to-fit-by-selection policy (so a map over cap degrades gracefully instead of failing)? Out of scope here; it would change the quality-vs-bandwidth framing materially. Recorded, not resolved.
- **Descriptor sharing across the three sections.** Validity is a property of the base grid, identical for ids 27/41/45. Whether the three carry independent copies (simplest, self-describing) or share one derived-at-load structure is an implementation choice within the fail-loud constraint; the spec does not pin it. (The carrier itself is resolved — a self-validating per-section 64-bit-per-cell mask, carried, not derived-nothing; see Direction and Task 1. Only the cross-section sharing stays open.)
