# lightmap-penumbra-floor

Brief · compact · reads: `context/lib/build_pipeline.md` §Compiler pipeline (step 12), §Build Cache · `context/lib/rendering_pipeline.md` §Static direct · read at a0a2c0239

## Problem

Owner requirement, from the RTX-lite exploration (`context/research/gi-rtx-lite/`): shadow edges never show their storage lattice; soft is fine, chunky texel steps are not. Today a baked shadow edge narrower than a texel shows the texel lattice. Cause: each lightmap texel stores one visibility sample at its centre, and the bake knows nothing about occluder distance. So an edge where an occluder meets the receiver, or one cast by an authored hard light, snaps from 0 to 1 between adjacent texels. Bilinear filtering then draws diagonal edges as staircases. `lightmap-resolution` measured ~1 texel of penumbra at contact at the default 0.04 m density. Done means every baked shadow edge, for every static light and at any `_lightmap_scale`, ramps over the floor width in texels at the receiver. A compile-time detector reports neighbouring texels that still step.

## Decisions

- **The floor is a minimum edge width at the receiver, not a minimum emitter size, which cannot widen a contact edge (`research.md` §Why an emitter-size floor fails).** Each texel stores visibility filtered from geometry by a round kernel, a cone of one-texel radius around its centre. It matches bilinear's one-texel reach along every axis with exact round support, so texels beyond one texel of an edge keep exact 0 and 1, and it is the crispest kernel the owner accepts, judged by the manual capture against `_lightmap_density 0.01` (`research.md` §Footprint kernel). The floor width is the ramp this kernel gives a hard edge, computed analytically by the tests rather than tuned; widening the kernel needs the owner.
- **Footprint size follows the face's actual texel pitch.** It counts texels, so a face in a `_lightmap_scale` region or a `_lightmap_density` map keeps the same ramp in texels and a different width in metres.
- **The floor applies to every static light, including authored `_light_size 0` and `_angular_diameter 0` (owner ruling; pre-stable, so no compatibility shim).** `0` now means the crispest edge the lattice shows without stair-steps; the single hard ray stays as the emitter model. Every text that calls `0` hard, 1-texel or hard-pixel is rewritten (`docs/level_design.md`'s `light` and `light_sun` rows and static-vs-dynamic paragraph; the FGD `_light_size` and `light_sun` `_angular_diameter` help; the `MapLight::light_size` and `angular_diameter` docs and the `DEFAULT_LIGHT_SIZE` and `DEFAULT_ANGULAR_DIAMETER_DEG` comments; `build_pipeline.md`'s light-entity rows and step 12, which also drops the removed warning).
- **It diverges from `lightmap-resolution`, which found that bake-side subtexel AA "only masks" faceting and chose resolution as the root fix.** The owner's rule accepts soft edges, so masking cures the visible defect at default density, at a fraction of the cost of 0.01 m density's 16× texels. `_lightmap_density` stays the opt-in for crisper contact.
- **Scope is the texel outputs: the per-light layer record, which feeds the irradiance lightmap and the shadowmask's raw visibility, and the animated lightmap weight maps.** A light baked static and the same light baked animated both get the floor; their tracers already differ, so exact agreement is not the claim. Probe and scatter bakes (SH base, bounce and deltas, direct SH, billboard scatter) have no texel: probe-point callers keep today's output, so their stage versions do not change.
- **The same requirement's other half, "a crisp edge is crisp per scene pixel", is not this brief's.** The floor trades some blur on authored-hard edges for losing the lattice. Per-pixel crispness belongs to shadowmask-mode owners (RTX-lite build step 11, distance-to-edge masks) or finer `_lightmap_density`.
- **A `prl-build` switch disables the floor; default on.** It folds into the layer and weight-map cache keys, and is listed in `--help` but not documented in `docs/`. It provides the before/after captures and the detector's disabled-floor case without a second build, and it keeps the RTX-lite build order's "bake flag" reversal.
- **Bake-only.** No PRL section, GPU struct or shader changes; the runtime bilinear sampler already reconstructs a filtered edge. Cache invalidation goes through the stage versions of the layer record (`LAYER_FORMAT_VERSION`, which lightmap and shadowmask keys fold in) and the animated weight maps, per `build_pipeline.md` §Build Cache's bump rule.
- **Footprint samples never take visibility from inside solid or from across a wall**, at chart borders, at inside corners, or through walls thinner than the footprint.
- **The texel-step detector is an adjacent-texel jump invariant (`research.md` §Footprint kernel).** A step is two axis-adjacent texels on the parent texel grid, across face cuts, whose stored per-light visibility differs by more than the kernel's largest possible adjacent difference plus a sampling margin. It reads stored visibility only, so it checks every pair without tracing; it cannot see a thin line the bake missed entirely, which the thin-pole row covers. It is written against a per-light visibility grid on the lightmap lattice, so the static layer record and the animated weight maps use it now and later visibility masks (RTX-lite door channel, shadowmask-mode owners) reuse it.
- **The detector is warn-only, runs in the production lightmap and weight-map stages, and replaces `warn_sub_texel_penumbra_lights`, which the production lightmap stage never reaches.** Each warning names light and face. A warm compile replays the cold compile's warnings, as the shadowmask memo replays its report.
- **Deterministic.** Repeat and warm-vs-cold bakes stay byte-identical, across worker counts.
- **Non-goal: new compression gates.** BC6H irradiance keeps its gate (`lightmap-resolution`); BC5 shadowmask error is measured, not gated (`shadowmask-atlas-compress-at-rest`), and its recorded 0/255 figure depended on hard edges. This brief re-measures both encodes on floored output beside the recorded figures.
- **Non-goal: runtime promoted shadows.** Promoted slots hold entity-only depth, so world receivers never compare against world geometry (`rendering_pipeline.md` §Promoted static lights). The forward pass's union subtraction only scales `baked_vis`, so a softer baked edge leaves no seam.

## Acceptance

### Automated
Ramp width is the 10–90% span of visibility perpendicular to the edge, in texels at the receiver. The floor width is the ramp the same edge shows, at the same phase and angle, with exact one-texel round-kernel visibility at every texel; the test computes it analytically and never reads the bake's footprint constant.
- [ ] Hard point and spot lights (`_light_size 0`) and a `_angular_diameter 0` sun, each with a diagonal occluder touching the receiver, show no single-texel 0→1 jump. Along a long contact edge, mean ramp width is within 0.2 texels of the floor width, for these lights and for a default-size light at contact.
- [ ] Every footprint sample offset lies within one texel pitch of the texel centre, and their radial distribution matches the one-texel round kernel; a wider or square footprint fails this row.
- [ ] A default-size light whose occluder stands well clear of the receiver, so its penumbra already spans several texels: ramp width changes by under one texel, floor on vs off.
- [ ] Texels farther than the one-texel footprint radius from any edge keep exactly 1.0 when lit and exactly 0.0 when shadowed: the floor neither leaks light into deep shadow nor darkens open floor.
- [ ] A shadow narrower than the footprint, cast by a pole thinner than half a texel, survives the probe early-out for a hard light and a default-size light. Every texel whose centre ray is blocked stores less than 1.0, and the line has no lit gaps (P3).
- [ ] At the minimum soft-shadow sample count, where the probe set is the whole set and nothing escalates, the hard-light contact ramp's mean width stays within 0.2 texels of the floor width, the thin-pole line has no lit gaps, and the detector stays silent (P13).
- [ ] On a hard-light contact edge midway between texel centres, at every soft-shadow sample count from the minimum to 8, and at 12, 16, 24, the default and 64, with the probe early-out active, no axis-adjacent texel pair differs by more than the kernel's largest adjacent difference plus the sampling margin: the early-out never snaps a texel whose exact round-kernel visibility lies between 0.1 and 0.9 to hard 0 or 1 (P16).
- [ ] At an inside corner, hard-light shadow edges swept in angle and phase meet the wall's foot, at the minimum and default sample counts with the early-out active. No texel whose footprint is clipped by the wall early-outs on its surviving probes alone, and no axis-adjacent pair within one texel of the wall exceeds the bound plus the margin (P18).
- [ ] In a `_lightmap_scale` region, a face's hard-light contact ramp has a mean width within 0.2 texels of the floor width, the same texel count as an unscaled face's, and its world width scales with the texel pitch. Both hold with the two faces baked on one worker, in either walk order (P14).
- [ ] Inside corner (lit floor meeting a wall, light on one side): floor texels at the wall's foot gain no shadow from inside the wall. For a wall thinner than the one-texel footprint radius, floor texels on its shadowed side keep exactly 0.0 (P4).
- [ ] With the floor on, overlap texels are bit-identical across every face cut for a hard light and a soft one, and the cut-face owner estimate reads the floored visibility the walk bakes at each sample texel (P5).
- [ ] On the hard-light contact fixture, one light baked as a static layer and again as an animated weight map both have a mean ramp width within 0.2 texels of the floor width, and agree per texel within one shadow-sample fraction.
- [ ] SH base, bounce and delta, direct SH and billboard scatter sections of a fixture with hard and soft lights are byte-identical to the pre-change commit's, by a two-PRL compare in the manner of the reseed baseline check.
- [ ] With the switch off, every layer texel's raw visibility equals centre-point visibility, and weight maps match the pre-change commit's by the same two-PRL compare. Toggling the switch re-keys both stages and the `lightmap_section` and `shadowmask_atlas` memos built on them; a warm cache from the other setting is not served (P6).
- [ ] Repeat cold bakes are byte-identical, at one worker and several, on a fixture that mixes hard, default-size and directional lights; with the floor disabled, its texel-step warnings and their order also match across worker counts (P9). A warm bake matches cold. A cache written before the change is not served for the layer record or the animated weight maps: the layer record's format version and the animated weight maps' stage version each exceed their values at the read commit (diff gate).
- [ ] With the floor on and with it off, the production lightmap stage's section bytes equal the uncached reference bake's (P7).
- [ ] Moving an occluder that only a footprint sample can reach, beside a face coarse enough that its one-texel footprint radius exceeds the layer key's 0.5 m influence padding, at the edge of a point light's reach, re-bakes the layer on a warm build (P10). A fixture whose footprint cannot reach past the padding does not satisfy this row.
- [ ] A cold compile through the production lightmap stage of a hard-light contact fixture with the floor disabled reports the texel-step warning where the caller thread can read it, naming the light and face; the same light baked animated warns from the weight-map bake. With the floor on neither reports any, and no compile fails. A detector reachable only from the uncached reference bake fails this row (P1). With the floor disabled, a stepped edge however short, on a face whose other edges ramp smoothly, warns, and so does one crossing a face cut, warned once and naming the parent face (P17).
- [ ] A warm compile reports exactly the cold compile's texel-step warnings, none twice: when every memo hits, including `lightmap_section` (P2); when `lightmap_section` misses but every layer partition hits (P11); when only the shadowmask memo re-keys (P12); and when the weight-map cache hits. The detector threshold is a code constant folded into the `lightmap_section` and weight-map keys, so changing it never replays stale warnings (P15).
- [ ] With the floor on, the detector warns about nothing where a shadow edge meets a chart border or padding texels with no record, an N·L terminator at a convex edge, a spot cone's outer edge, a light's reach limit, an inside corner or a wall thinner than the footprint, where samples are clipped. A light with no shadow edge draws no warning (P8).
- [ ] On floored `shadowmask-groups-capture`, `soft_shadow_test` and `gate-heavily-lit`, report BC5 shadowmask and BC6H irradiance encode error (max and mean) beside the recorded pre-change figures, and the shadowmask owner report's peak face demand and drop count before vs after (measured, not gated). A light newly dropped from a face's owner set stops for the owner.
- [ ] `prl-build` with no floor flag bakes floored. `--help` lists the switch. Nothing under `docs/` names it (grep gate).
- [ ] The replaced sub-texel warning and its predicate are gone. No text in code, `docs/`, `sdk/` or `context/lib/` describes an authored `0` as a hard, 1-texel or hard-pixel shadow, or describes that warning, except comments on probe-side or per-ray code (the SH bake's probe comment, the hard-ray branch comment); plans and research are records and stay as written (grep gate).
- [ ] The diff changes nothing under `crates/level-format/` or `crates/renderer/src/shaders/` (diff gate).
- [ ] Lightmap stage wall time, cold, before vs after, on `stress-warren-hallway-inspection-mini` and on `shadowmask-groups-capture` (hard lights): report each ratio and the detector's share. Above 1.5× total or 5% detector share on either stops for the owner.

### Manual
- [ ] `cargo run -p xtask -- capture` at 2560×1440, camera 2 m from contact shadows on `soft_shadow_test` and `shadowmask-groups-capture`, floor off vs on, scene JSONs written for the stations: no texel staircase on any baked edge. The owner judges hard-light softness against the same scene baked at `_lightmap_density 0.01`. ## Path

- Seams: `lightmap_layer.rs` (`bake_light_layer_chart_controlled`), `light_texel_contribution_and_visibility_with` in `lightmap_bake.rs`, `animated_light_weight_maps.rs` (its `soft_visibility` call), `shadowmask_bake/estimate.rs` (re-runs the layer path for cut faces). Texel positions come from `chart_raster.rs::chart_texel_world_position`.
- Shape: jitter the visibility ray origin across the footprint, offsets distributed by the round kernel, inside the texel loop, with N·L and falloff still at the centre. Footprint offsets are fixed constants combined with the existing per-texel seed; offsets in the tangent plane alone can land inside a wall at an inside corner or past a thin one (P4). Rival: a post-bake blur of stored visibility. It is cheaper, but it bleeds across chart borders and inside corners and cannot see geometry.
- The probe-then-escalate early-out (`SOFT_PROBE_SAMPLES`, `probe_indices`) must spread its probes over both footprint and emitter, or a thin occluder slips between probes and keeps a hard edge (P3), the failure `probe_indices` already documents for emitter poles. Nor may it snap texels within the kernel's reach of an edge to hard 0 or 1 (P16); the four probes form a designed ring at every count, and a texel whose footprint the wall clips traces its full set (P18, `research.md` §Footprint kernel).
- The switch enters the per-light layer hash (`LayerKeyContext::light_prefix`), so the second-level memos re-key with it (P6), and reaches `LightmapConfig`, so the reference bake floors too (P7).
- Partition loads run on Rayon workers, which log capture does not reach. Run the detector over the partitions a `lightmap_section` miss bakes or loads, not inside the chart bake, so a layer-cache hit still reports (P11); replay it from that memo on a hit, even when the shadowmask pass then consumes partitions (P12). Return the report to the caller thread (or count it in a `#[cfg(test)]` counter), and store it with the memo (P1, P2, P15). No visibility grid survives the weight-map bake (`research.md` §Facts used): build one while baking and store its warnings with the `animated_lm_weight_maps` entry.
- First slice: the floored hard-light fixture plus the detector pair. Together they falsify the core claim before the animated path or docs move.
- `lightmap_bake.rs` is past 1,400 lines. Put the footprint and detector in a new module, not in it.
- Naming: `penumbra_floor()` already names a fixture in `lightmap_bake/face_cut/tests.rs`, and "runtime floor" names something else in `pipeline/tests/lightmap_runtime_floor.rs`. Choose distinct identifiers.
- Fixtures that rely on authored `0` being exact (`shadowmask_bake/tests.rs` `light_over`, integration maps with `"_light_size" "0"`) update to floored expectations. Never delete them to pass.
