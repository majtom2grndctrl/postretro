# camera-path-playback

Brief · resumable · reads: `context/lib/rendering_pipeline.md` §11, §12 (GPU Pass Timing, CPU Stage Timing, Machine-state confounders) · `context/lib/development_guide.md` §6.4, §6.5 · `context/lib/boot_sequence.md` §Settling · `context/plans/in-progress/streaming-drain-budget-spike/` · read at ecd9489e0 · evidence: `research.md`

## Problem
The agent running `streaming-drain-budget-spike` reported gaps the owner relayed. The spike cannot measure what a drain costs the GPU while the GPU is busy rendering: its install-cost row plans an offline drain test on an idle GPU. It also cannot measure frame-time spikes at each drain cap, which is the owner's stutter question. Both need the real renderer drawing every frame while a repeatable camera route streams new areas. No such route reaches the windowed engine (`research.md` §Near items, §The windowed camera). This is a capability for engine developers, and for modders' agents, measuring streaming and residency. When this is done, a measurement build flies the camera along a pose file, generated from the walk's cells or recorded in a live session, from an SDK bundle as from a checkout. A run either locks one pose to each rendered frame, so every run makes the same demand, or follows the route at its own speed. The drain cap is set at launch. The run writes a per-frame record of frame time and drain work, marks each frame so a Metal System Trace reduces per frame, emits a telemetry summary per window, and exits at the route's end.

## Decisions
- **Playback reads only pose files.** Playback never regenerates a route while it plays. A route regenerated at playback would follow the walk's RNG streams and the bake's cell ids, and would silently change with either (`research.md` §Serialize); a file pins it.
- **Route generation is a library function, shared with the walk.** One function over a loaded level's cells and portals, in a CPU crate the tool reaches, generates every route kind. The walk harness and `postretro-tool` call it, so a route an SDK user generates is the route the walk measures, and the harness needs no file writer of its own. The engine's non-test code never calls it; the spike's grep gate covers the walk override, its tallies and its levers, not path generation, so it holds.
- **Generation is a `postretro-tool` verb.** It reads a PRL and writes a pose file for a kind (exact far-point, exact random, smoothed), a seed, a step count, a pitch and a horizontal FOV defaulting to the walk's, and for smoothed a speed and turn cap; the header records them. Two runs on one PRL give identical bytes; from another path or a copy, the pose lines are identical and the header differs only in the recorded PRL path, size and modification time (`research.md` §Generated files). It needs no engine, adapter or feature, as `solve-weapon-mount` needs none. A `docs/` page gives the bundle-runnable commands for generating, recording and playing a route.
- **Two generated routes, one format.** Exact frames price a saturated drain; on a visible window they strobe. A smoothed route through the same cell sequence, at run speed with a capped turn rate and cut where the walk teleports, serves the vsync stutter rows and any visual read. Its speed and turn cap are never engine constants, because mods move at their own speeds.
- **Recording records the held view, before view feel.** A launch flag records a live session's camera to a pose file, so a person flies a route once and an agent replays it. View feel adds roll and per-frame FOV changes a pose cannot carry, and playback bypasses view feel, so the recorder writes the eye, yaw and pitch before view feel, at the base horizontal FOV. Replay draws the recorded route, not the recorded frames' bob, roll or FOV kicks (`research.md` §Recording).
- **A recording covers the first gameplay level.** It starts at that level's first world frame, so a frontend backdrop records nothing, and ends when the level ends by change, unload, reload or restart; Settling and frames that draw no world record nothing. The file is written when the level ends or the session exits, on every exit route, window close and a quit from the menu included. A launch with both the record and the playback flags refuses to start, naming both.
- **Recordings share the generator's clock.** Each pose is stamped with its frame's presented time, and the file is written resampled to the generator's 60 Hz cadence, so every pose file shares one clock whatever rate it was recorded at. A recording is a camera route through a world at rest, not a replay of the session: playback keeps the pawn at spawn, so doors the recorder opened stay as the level starts. Recorded poses carry no walk step or cell, and the header names the recorded origin.
- **The pose file is world space.** Each pose is an eye position, not a capsule centre, with yaw and pitch in engine radians, written exact so a replay is bit-equal. A walk-written pose also carries its walk step and cell, so a file reproduces the walk's pose fingerprints. A header carries the bake identity the walk records, the projection the poses were made for, and how they were made. Playback renders with the file's horizontal FOV at the window's aspect, Settling's held view included. The format extends the bake-gap record's radian frames, not the world-poses file's degrees, and adds no third pose dialect.
- **Pacing is a per-run option.** *Frame-locked*, the default, gives pose k to the k-th route frame that draws the world, at any frame rate, so every run makes the same demand, for cost and drain pricing. *Wall-clock* draws the pose at the elapsed time since route frame 0, at the file's 60 Hz cadence and interpolated between poses, so the camera keeps route speed when frames drop, for pop-in and lead-distance reads (`research.md` §Pacing). The record header names the mode. Engine demand is not the walk's in either mode (`research.md` §The windowed camera), so the engine's counts are never compared as equal to the walk's.
- **Placement: the binary owns playback and the renderer owns the frame marks.** Playback replaces the presented pose at the seam where the frontend menu already holds its camera, and bypasses view feel, so the render eye equals the route's pose. Streaming, visibility, render and the audio listener follow that eye unchanged. Streaming reads the camera only through visibility, so nothing streaming-specific is overridden and the drains measured are production drains.
- **The pawn stays at spawn; the sim keeps ticking.** Only the camera follows the route. Playback suspends gameplay input for the run, as Settling does, so nothing moves the pawn; diagnostic chords and the dev-tools panel stay live. The measured frame stays the production frame. The record logs any pawn life-state change.
- **Run lifecycle.**
  - Settling streams from the first pose through the camera and writes no rows.
  - Playback then holds the first pose for a launch-set number of frames, so a trace can attach and the settle tail drains. Hold frames are recorded, marked as hold.
  - After Settling, a frame that draws no world does not advance a frame-locked route. One that streams and drains without drawing writes a row marked no-draw carrying its drain work.
  - A vsync chord, a resize or window-mode change, a cap-slider move or a script hot reload persists, so it marks every row from the frame it lands on to the run's end. A hidden-window gap marks only the rows it spans. Marked rows stay in the record and leave the per-run figures, and the run continues.
  - After the last pose, playback writes the record and exits 0.
  - A level change, unload or reload, or a join to a host from the frontend, during playback ends the run: the record is written and marked aborted with its reason, and the process exits non-zero.
- **A stalled window fails fast.** If no frame of any kind presents within a launch-set timeout after launch, as when the display sleeps or the screen locks, the run exits non-zero naming a stalled window. A run whose window presents frames but reaches no world frame within the same timeout, such as one waiting on the first-run accessibility panel, exits non-zero naming the screen it waited on. Playback writes its record marked aborted with that reason; recording, which has no pose yet, writes no file.
- **Playback refuses to start on bad input or a connected client.** An empty, malformed or unreadable pose file stops the launch, as does one whose horizontal FOV lies outside the engine's accepted range, never clamped, or one that does not match the loaded level. A file matches on the id-51 hash and walk epoch only, the walk's own same-bake check. When the level has no id-51 hash, the file is accepted with a warning and the header marks its identity unproven. The error names the file and the reason. This departs from `--start-pose`, which warns and starts at the spawn, because a run that silently draws the spawn view reads as a result. Playback also refuses to start in a session launched with `--connect`.
- **The cap is the launch seed of the play drain budget's slider, in the budget's own unit.** The spike's dev-tools drain-cap slider takes the seed (`development_guide.md` §6.4: a seed ships with its surface). Its unit is decoded bytes today; if `streaming-drain-time-budget` makes the budget install time, the seed follows the slider. When unset, play uses the production cap, and Settling keeps its own cap either way. If the slider does not exist when this builds, this brief lands it with its seed under the spike's lever decisions: with levers unset, admission is identical. Neither the cap nor playback is ever a player setting.
- **Present mode is set at launch.** Vsync defaults to on and can be turned off at launch for the run. The record names the mode. With vsync on, frame intervals show the stutter a player sees. With vsync off, they show cost (`research.md` §Frame pacing).
- **The record is a per-frame file; telemetry gets per-window events.** Metal System Trace reduction needs per-frame rows, and one event per frame would void the per-window rate warrant behind the telemetry sink's per-line flush (`done/E20--streaming-telemetry`), so per-frame rows never reach the sink. Playback also emits one playback window event per window through the sink, built from the same rows: frame-time p99, frames over 33 ms, the drain stages' CPU max, late lightmap block-frames, late SH cluster-frames, and the window's pacing mode and cap. The kind follows `development_guide.md` §6.5: a log line from the same snapshot, absent values `null`, a final partial window when the run ends, and `run_start` naming playback's producer state.
  - The record's header holds what §12 requires of a performance run: revision, build profile and features, adapter, surface and scene extents, render divisor, window mode, present mode, pacing mode, cap, the pose file, both bake identities, both projections, the settle outcome (settled or timed out), and CPU and GPU timing availability.
  - Each frame row holds the frame index, the pose index (the route time under wall-clock pacing) or hold, the frame interval, and the CPU split with the streaming stages. On an adapter with timestamp queries, the row also holds the frame's drain-encoder and whole-frame GPU time, from the same query gate per-pass GPU timing uses (§12); without them the fields are absent and the Metal System Trace supplies GPU time.
  - Each frame row also holds admitted bytes and items per resource, whether a drain made a staging pool create a buffer (a cold drain), whether a drain grew a lightmap pool, and drawn-not-resident counts for both resources, the totals the spike's late-item cause buckets split.
  - Stages are absent, never zero, while CPU timing is off.
  - The record is filled without per-frame allocation or I/O and written once at the end.
- **GPU figures name their clock.** A GPU figure taken at an idle clock is only an upper bound (`rendering_pipeline.md` §12, Pin the GPU clock), so every GPU figure a run reports, from timestamp queries or a trace, names the GPU clock it ran at, or says the clock went unrecorded. Where the clock comes from is open (Open questions).
- **Gating: SDK bundles carry playback; player builds do not.** Agent-oriented development is part of the architecture, so playback, recording and the launch cap seed ship in SDK bundles, beside the tool's generate verb. A bundle's playback engine is its debug authoring engine, so SDK runs check routes, not timing; a measurement build is `--release` or `--profile profiling` with `dev-tools` (§12, Build profile). Playback and recording ride `dev-tools` only if inactive they cost nothing per frame; a per-frame cost the build cannot remove moves them to their own dependency-free feature that SDK bundles also enable. Release (player) builds carry neither.
- **Frames carry marks only during playback.** Each playback frame's GPU work can be attributed to its frame index in an exported trace. Outside playback, every encoder label stays as it is today, so per-encoder reducers keep their grouping.
- **One reducer in `tools/`,** with a unittest that preflight runs. It joins the record with an MST export and reports per frame: interval, drain-encoder GPU time, cold flag and pool-growth flag. Per run it reports interval p50, p95 and max, and frames over budget, with cold and pool-growth drains counted apart. It follows §12's per-encoder rules, and extends `gpu-pass-paired-ab`'s reducer rather than forking it if that lands first.
- **Non-goals:**
  - Input record and replay: roadmap Epic 20's candidate replays input through the sim; this brief replays no input, and the sim it leaves ticking reads none.
  - Offscreen or headless playback: capture owns offscreen rendering.
  - Authored routes, such as hand-placed waypoints. The file format admits them later.
  - Choosing the drain cap: the spike owns that.

## Acceptance
### Automated
**Route fidelity:**
- [ ] An exact-frames file the generate verb writes for both walks at the walk's defaults reproduces every frame's pose fingerprint of the harness's in-memory walk.
- [ ] A trip record the walk harness writes at the read commit pairs with one written after the move with no pose mismatch, for both walks at default steps: the move changes no frame of either walk.
- [ ] A smoothed file visits the walk's cells in the walk's order. Except across a marked cut where the walk teleports, every pose's eye locates in the walk's current cell or the next one, and between consecutive poses the eye moves no faster than run speed and turns no more than the turn cap. Away from turns the turn cap slows, the eye moves at the run speed the executor reports. Generated at two different speeds and turn caps, each file obeys its own, and its header names them.
- [ ] With frame-locked pacing over an N-pose file, the first world frame after the hold draws the first pose as route frame 0, and route frame k renders with an eye, yaw and pitch bit-equal to pose k, including when the followed pawn carries view feel and when it stands on a mover. Each pose is drawn exactly once as a route frame. Hold frames draw the first pose and are not route frames (pin P1).
- [ ] With wall-clock pacing, route frame 0 draws pose 0, and a route frame at elapsed time t draws the pose interpolated at 60t, pose k within float tolerance at t = k/60 s. A run whose frames are slowed still reaches pose k at elapsed time k/60 s, skipping poses between frames. The first route frame at or past the last pose's time draws the last pose and ends the route (pin P16).
- [ ] Every route frame renders with the file's horizontal FOV at the window's aspect, and the header records the file's projection and the rendered one.
- [ ] With and without a local pawn, every Settling frame's held view and the reveal frame use the first pose's eye, yaw and pitch bit-equal, and the file's horizontal FOV at the window's aspect (pin P5).
- [ ] After Settling, a frame that draws no world and runs no streaming step neither advances the route nor writes a row. A frame that streams and drains from pose k and then gets no surface writes one row marked no-draw carrying its admitted bytes, items and drain flags, and under frame-locked pacing the next world frame draws pose k (pin P9).
- [ ] A one-pose file settles, holds, draws that pose once as a route frame, writes the record and exits 0, in either pacing mode. A hold of zero frames starts the route on the first Running frame.

**Pawn and sim:**
- [ ] With a local pawn, the pawn starts at the map's normal spawn, and no playback frame sets its position or orientation; only the camera follows the route.
- [ ] A movement key held from Settling through the route leaves the pawn's position and the portal mask on every frame as they are on the same run without the key, while a diagnostic chord pressed meanwhile still acts, and one that changes a setting marks rows as a mid-route change does (pin P12).
- [ ] A pawn death or respawn during the route is logged in the record on the frame it happens, and the route continues (pin P11).
- [ ] With CPU timing on, every route frame's CPU split carries the fixed-step stage and its tick count as a play frame does. Playback never pauses the sim.

**Lifecycle and refusal:**
- [ ] An empty file, a file with a header and no poses, and a malformed or unreadable file each stop the launch with an error naming the file and reason, before any world frame. So does a file whose id-51 hash or walk epoch differs from the loaded level's, and one whose horizontal FOV lies outside the engine's accepted range, its error naming the value.
- [ ] A file whose id-51 hash and walk epoch match is accepted when the PRL is loaded from another path, or is a copy with another modification time, and the header records both full identities. On a level with no id-51 hash, the file is accepted with one warning and the header marks the identity unproven.
- [ ] Playback refuses to start in a session launched with `--connect`, and a launch with both the record and the playback flags refuses to start, each with an error naming the reason or both flags, before any world frame.
- [ ] A level change, an unload, a level reload or a join to a host from the frontend requested during Settling, the hold or the route writes the record marked aborted with its reason, keeps every row written before the request drained, and exits non-zero (pins P3, P4).
- [ ] A level change requested on the frame that draws the last pose leaves the run complete. The record holds the last route row with its own CPU split and drain counts, is not marked aborted, and the process exits 0 (pin P2).
- [ ] A vsync chord, a resize, a window-mode change, a cap-slider move and a script hot reload mid-route each mark every row from the first one the change touches to the run's end with that change. A hidden-window gap marks only the rows whose interval spans it. Marked rows stay in the record, per-run figures leave them out, and the run reaches its end and exits 0 (pin P10).
- [ ] A launch whose window presents no frame within the stall timeout exits non-zero naming a stalled window: playback writes its record marked aborted with that reason and no rows, and recording writes no file. A launch that presents frontend frames but no world frame within the timeout, such as the first-run accessibility panel, exits non-zero naming that screen. A first world frame before the timeout disarms it (pin P17).
- [ ] In a build without playback's feature, the playback flag and the recording flag each warn once naming the missing feature, and the run behaves as if the flag were unset.

**Cap and pacing:**
- [ ] With the cap seed set, every play drain from the first Running frame admits against the seeded cap, read in the slider's unit, and the dev-tools drain-cap slider shows the seeded cap at launch. With it unset, drains admit against the production cap. A settling drain uses the settling budget either way. A malformed seed warns once and keeps the production cap. A build without dev-tools ignores the seed.
- [ ] The present mode and pacing mode chosen at launch are the ones the run uses from its first frame, and the record names both.

**Record and reducer:**
- [ ] The record holds one row per hold, route and no-draw frame, in order. Settling frames write none, so the first row is the first hold frame, or route frame 0 with a zero hold. Its header holds every field the Decisions list, the settle outcome naming settled or timed out as Settling ended.
- [ ] On an adapter with timestamp queries, every route row carries drain-encoder and whole-frame GPU time; on one without, those fields are absent, never zero.
- [ ] Stage fields are absent with CPU timing off and present with it on. The frame interval, admitted bytes and items, drain flags and drawn-not-resident counts are present either way.
- [ ] A frame whose drain made either resource's staging pool create a buffer is flagged cold. A frame whose drains reused pooled buffers is not, nor is one whose only buffer creation served a per-frame upload.
- [ ] A frame whose drain grew a lightmap pool is flagged as pool growth, and the reducer counts it apart from warm drains, as it does cold drains.
- [ ] Filling a playback row allocates nothing (`alloc_probe`), and the record does no I/O until its one write.
- [ ] With playback and recording inactive, a frame allocates nothing for either, writes no frame mark, and every encoder label equals today's.
- [ ] With the telemetry sink set, each playback window event's frame-time p99, frames over 33 ms, drain-stage CPU max and late lightmap and SH counts equal the figures the record's route rows over the same frames give, and it names the pacing mode and cap. No event is written per frame. With CPU timing off, the drain-stage CPU max reads `null`, never zero.
- [ ] A run that completes or aborts mid-window writes a final partial playback window covering the rows since the last window, before `run_end`; `run_start` names playback's producer state (pin P18).
- [ ] Every GPU figure the reducer reports per run names the GPU clock it ran at, or says the clock went unrecorded; a record or trace with no clock never reads as pinned.
- [ ] The reducer's unittest summarizes a checked-in record and trace-export sample into the expected per-frame and per-run tables. A record with no matching frame marks is an error. The sample comes from one real playback run, and every route frame in it matches a frame mark.
- [ ] Preflight runs the reducer's unittest, and a failing reducer test fails preflight.
- [ ] In the reducer's unittest, a drain recorded on frame k and submitted before frame k's render work is attributed to frame k, and so is a frame-k drain the GPU runs after frame k + 1's work begins (pin P6).
- [ ] A trace export covering only part of the route gives per-run figures over the matched route frames and names how many route frames went unmatched. An unmatched frame never counts as zero drain GPU time, and hold frames before the trace attached are not an error (pin P7).
- [ ] The reducer's per-run interval figures and over-budget count cover route frames only. Hold, no-draw and change-marked rows are reported apart (pins P8, P10).

**Gating:**
- [ ] The SDK bundle's authoring engine builds with playback, recording and the cap seed, and the bundle's `postretro-tool` carries the generate verb. The SDK bundle's release engine and the player dist engine build with none of them.
- [ ] Grep gate: playback and recording build only behind `dev-tools` or playback's own feature. The shared route generator is called from `postretro-tool` and the walk harness, and the engine's non-test code never calls it. The walk override, its tallies and its levers stay in test code. No player setting or options UI names playback, recording, the pose file or the drain cap.

**Generation and recording:**
- [ ] For each kind and parameter set, two generate-verb runs on one PRL write identical bytes. Given another path to the PRL, or a copy, the pose lines are identical and the header differs only in the recorded PRL path, size and modification time. Pitch and horizontal FOV default to the walk's, and the header records the values used.
- [ ] The generate verb runs on a machine with no GPU and exits 0. An unknown kind, zero steps, a non-positive speed or turn cap, an unreadable level, and a level with no camera cells or no portal between them each fail before writing, naming the parameter or the level.
- [ ] An SDK bundle built by `sdk-dist` writes a valid pose file with its `postretro-tool` generate verb, using only bundle contents.
- [ ] A recording made while view feel adds bob, roll and FOV kicks holds, resampled, the eye, yaw and pitch each frame had before view feel, and its header holds the base horizontal FOV. Replayed, no route frame carries roll or an FOV offset.
- [ ] A route recorded at a steady 30 fps and one recorded at 60 fps over the same camera motion resample to the same 60 Hz poses within float tolerance. Played frame-locked, route frame k draws pose k of the resampled file bit-equal, and a frame-time hitch during recording leaves no pose jump beyond the camera's own motion.
- [ ] A recording writes no pose for Settling frames or frames that drew no world, does no I/O until its one write, and its header names the recorded origin and the bake identity.
- [ ] A recording launched into a frontend backdrop records nothing before the first gameplay level's first world frame (pin P15). A level change, an unload, a level reload or a restart during recording each write the file for the first level's world frames before the request and record nothing after it (pin P13). A session that exits before its first world frame writes no file and warns once.
- [ ] A recording is written when the session ends by window close, the quit chord or a quit from the menu, and the file is the same on each (pin P14).

### Manual
- [ ] First consumer: Mac perf target, `--release` or `--profile profiling` with `dev-tools`, campaign-test far-point routes, CPU timing on, `xctrace` attached during the hold. At the production cap and at least one other: drain GPU time per frame from the reducer on the exact frames with vsync off, and frame-interval stutter on the smoothed route with vsync on, both frame-locked. Machine state follows §12, and cold and pool-growth drains are counted apart.
- [ ] The same route on the showcase copy, when the spike's frozen copy is available, recording its hash.
- [ ] An SDK bundle built by `sdk-dist` records a route, generates one, and plays both with the commands `docs/` gives, using only the bundle.

## Path
- **Seams:**
  - The pose writer goes beside `world_poses/bake_gap.rs` `materialise` and its radian frame record (`write_record`, `parse_record`), and `trip_record.rs` `pose_fingerprint`. The writer and parser move out of test code with the format. The walk's `bake_identity` and `bake_token` (`baked_set.rs`) move with it; the same-bake check to follow is the walk's `id51`/`walk_epoch` comparison in `walk_measurement/mod.rs`.
  - The override goes in `render_aim_pose` (`main.rs`, beside `apply_menu_camera_pose`) and the view-feel driver choice in `redraw` (`frame_loop/mod.rs`, before `assemble_frame_eye`); the connected-client `life_state_eye` adjustment follows it. The file's FOV replaces `HFOV` in `RenderCamera::new` (`camera.rs`), whose clamp is the accepted range. Settling's held view reads `App::presented_pose` (`startup/presented_pose.rs`), the chokepoint the menu pose takes, and `held_view` builds its camera at `HFOV` today; the pawn's install is untouched.
  - Cap: the `admit_within` call in `session/level_streaming/mod.rs`. Admitted bytes per resource come from `SharedDrain` after admission.
  - No-draw rows: the streaming step runs before render in `redraw`, and the SH drain before surface acquire (`renderer_render_frame.rs`).
  - CPU rows: expose `CpuFrameTimer`'s composed `FrameRecord`, test-only today, rather than re-timing.
  - Cold flag: buffer creation in `renderer/src/render/uploads/staging_pool.rs`. Lightmaps, SH residency and per-frame uploads each own a pool (`lighting/lightmap/stream.rs`, `render/sh_streaming/gpu/setup.rs`, `render/uploads/mod.rs`); confirm which pool each drain's uploads draw from. Pool growth: `PoolTextures::new` and `copy_layers_into` in `lighting/lightmap/stream/execute.rs`.
  - Record shape: the capture `MeasurementReport` (`capture/report.rs`). Present mode: `Renderer::toggle_vsync` and the init-time `AutoVsync`.
  - Window events: a new kind in the `telemetry` crate's envelope (`crates/telemetry/src/envelope.rs`); the CPU timer's window event (`cpu_timing/frame_timer.rs`) is the precedent for a window built beside its log line.
- **Shape and rival:** the chosen shape is a file-driven pose override in the windowed binary, fed by a tool-hosted generator and an engine recorder. The rival for generation was an engine headless command; rejected because the engine's headless load compiles only with `observability`, a second headless entry, and generation needs only cells and portals. The rival is regenerating the route at playback from seed and map, rejected in Decisions.
- **Generator:** `walk_measurement/paths.rs` `camera_adjacency` and `walk_path` (far-point tour, random), `walk.rs` `Walk::build` and the run loop's per-frame `eye_point` stream read only `LevelWorld` (cells, portals, `locate_cell`) from `level-loader`, which `postretro-tool` reaches through `level-compiler`. `world_poses/bake_gap.rs` `materialise` duplicates that eye stream and frame yaw. Move them and the smoothed route into one function there; the walk harness keeps its override, tallies and levers and calls it, and so does bake-gap materialisation, leaving no second copy of the stream. `level-compiler`'s test-only `lightmap_residency_dry_run/camera_walks.rs`, the walk's original, can call it as well. Precedent: `solve-weapon-mount` runs a shared library solve from the tool.
- **Recorder:** the presented eye, yaw and pitch `assemble_frame_eye` takes (`FrameEyeInputs` `presented_eye`, `render_yaw`, `pitch`), before view feel, beside the playback override; resampling happens at the write. Every exit route reaches `App::exiting` (`main.rs`).
- **First slice:** a pose file of a few hundred far-point frames played on campaign-test with one frame-mark mechanism, then `xctrace export`. It falsifies the riskiest assumption: that an MST export can attribute the "Streamed Lightmap Drain" and "Streamed SH Upload Copies" intervals to a playback frame index (`research.md` §Frame marks).
- **Large files:** `main.rs` and `frame_loop/mod.rs` are past 800 lines. Put playback in its own module and add only calls there.

## Open questions
- The frame-mark mechanism: debug groups or markers are preferred, since they reach Metal System Trace, PIX and RenderDoc alike; a frame-indexed label on one once-per-frame encoder, or time alignment, only if debug groups do not show in a real Metal export. — **delegated**: the first slice proves one on a real export.
- Pose-file flag and seed names, the hold's default length, the playback window's length, and the stall timeout's default, which must outlast a load plus Settling's own timeout. — **delegated**.
- The smoothed generator's default speed and turn cap. — **delegated**: the executor picks defaults that read as play and reports them.
- Whether an over-budget frame interval is charged to its own row's drain only, or also to drains still in flight. — **delegated**: the reducer reports both, and the run's findings say which reading holds.
- Where the GPU clock comes from: an `ioreg` `PerformanceStatistics` poll during the run (§12), taken by the engine or by the script that attaches the trace, or another source; and what a run records on an adapter that reports none (`research.md` §GPU clock). — **delegated**: the first slice proves a source on the Mac and reports it.
