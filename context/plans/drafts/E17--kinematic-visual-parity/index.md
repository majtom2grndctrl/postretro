# E17-B — Kinematic Visual Parity

> **Epic:** 17 — Kinematic Geometry and Moving Platforms.
> **Depends on:** E17-A (kinematic platform foundation) ✓. Independent of E17-C (trigger/command surface) ✓.
> **Specular scope:** movers get specular under **promoted static lights** (the static lights that cast shadows from moving entities), reusing the runtime light loop the mover already runs — matching what static walls do (specular is a static-light term everywhere in the engine today). Dynamic-light specular is deferred to a future engine-wide spec (the diffuse-only dynamic path is incomplete, not intentional). One spec, one wave.

## Goal

Bring kinematic brush movers to the static world's visual contract. Movers already draw SH/dynamic-lit and already receive dynamic shadows; two gaps remain. Close them: the mover shader samples the same material slots static geometry does — normal maps, specular, and material shininess — and active movers cast into the runtime shadow pools, so a moving platform reads like the static geometry around it.

## Scope

### In scope

- **Material parity (shader).** The mover fragment shader samples the normal map, specular map, and per-material shininess from the shared material bind group it already binds, and forwards the tangent it already carries. Normal-map perturbation applies to the diffuse response under all of the mover's light sources (SH indirect, baked static-direct SH, runtime dynamic).
- **Shared material-shading WGSL.** The world shader's binding-agnostic material leaf helpers (Blinn-Phong, normal-map decode, octahedral decode, TBN reconstruction) become one shared snippet appended to the forward, skinned-mesh, and mover shaders, so the mover's material math is identical to the world's by construction — not a fingerprint-tested duplicate.
- **Specular under promoted static lights.** Blinn-Phong specular is computed inside the mover's existing runtime light loop, gated to the **appended promoted static-light records only** (the loop's tail past the dynamic-tier count). This matches the engine's current behavior — specular is a static-light term and no surface glints under dynamic lights. Each contribution is scaled by that record's attenuation, cone, and shadow-visibility factors and inherits the promotion crossfade weight `w` (pre-folded into the record's color). The gate needs one new `dynamic_light_count` field in the mover light-params uniform; no new binding. The baked static-direct SH atlas is diffuse-only, so runtime specular adds no double-count.
- **Movers drive static-light promotion.** An active mover's world bounds join the promotion-relevance set, so an eligible static light near a mover promotes into a shadow-pool slot — the shared enabler for both the static specular above and the promoted-slot casting below. Movers share the existing 8-spot / 2-cube promoted budget with skinned meshes through the existing ranker; no new budget.
- Diffuse Post-Retro filtering stays byte-identical to today (existing parity test unchanged).
- **Shadow casting.** A generic depth-only rigid-occluder pipeline — position-only, per-instance model transform, projected by the per-render light-space matrix — with kinematic movers as its first and sole caller this wave.
- Mover occluders record into every occupied slot the entity occluders already serve: dynamic spot slots, dynamic point cube faces, promoted-spot slots, and promoted-cube faces, with `LoadOp::Load` after the world/cached depth.
- Per-slot/face CPU cone cull of movers, using the conservative world-space mover AABB (movers are not in the world BVH).
- Mover→world, mover→mesh, and mover→mover shadows (mover-side shadow *receipt* already exists).

### Out of scope

- Specular under **dynamic lights** — deferred to a future engine-wide dynamic-specular spec. No surface in the engine has dynamic-light specular today (the dynamic light loop is diffuse-only); this is an incomplete area, not an intentional exclusion, and belongs in one pass across all surface types once its per-fragment perf cost is measured. See Open questions.
- Specular under **non-promoted static lights** (the full per-chunk static spec-light list). Deferred — see Open questions.
- Baked lightmap / SDF occlusion cast by movers. Moving objects never enter static bakes (roadmap invariant).
- Static lightmap sampling or lightmap-UV vertex attributes on movers; those bytes stay zeroed.
- Any change to mover motion, collision, carry, or networking (E17-A owns those).
- Scripting / `world.query` / mover command surface (shipped as E17-C).
- Rotation and angular carry (E17-D), doors/blocking (E17-E), visibility-bearing movers and moving shadow-casting lights (E17-F).
- Building the rigid-occluder pipeline out for absent future consumers (rigid props, debris, chunk clusters) — the seam is *shaped* to admit them, but only movers are wired this wave.
- Any new bind group, new required adapter feature, or raising `max_bind_groups` above 8. No new promotion-budget slots.

## Acceptance criteria

- [ ] A mover face with an `_n` normal-map sibling shows normal-mapped (bump) shading in its diffuse response; a mover and a static wall sharing the same material and lit by the same lights show consistent **diffuse + normal** shading at matching orientation. (Specular is a static-light term — see below.)
- [ ] A mover face with an `_s` specular sibling shows a Blinn-Phong highlight under a **promoted static light** — tighter with a shinier material (Metal), broader with a dull one (Concrete) — consistent with a static wall of the same material under that light, and suppressed where that light's shadow term occludes the fragment.
- [ ] A mover shows **no** specular highlight under a dynamic light (matching every other surface in the engine).
- [ ] The mover's specular highlight fades smoothly as its static light de-promotes (weight crossfade) rather than popping on or off.
- [ ] In a scene with an active mover and **no** skinned mesh, an eligible static light near the mover promotes into a shadow slot — observable as the mover casting a crisp shadow under it and receiving its specular — where before it would not have promoted.
- [ ] In a mixed scene where a mover and a skinned mesh both sit near bright static lights competing for promotion slots, promotion degrades gracefully via the existing ranker and existing entity-shadow tests pass unchanged.
- [ ] The existing mover diffuse Post-Retro filtering parity test still passes (no diffuse regression).
- [ ] An active mover casts a shadow onto world geometry under a dynamic spot light and under a dynamic point light.
- [ ] An active mover casts a shadow onto a skinned mesh standing beside it.
- [ ] With two movers, one casts a shadow onto the other.
- [ ] A mover casts a shadow onto world/mesh receivers under a promoted static light.
- [ ] The cast shadow tracks the mover each frame while it moves and is stable when the mover is docked/idle.
- [ ] A mover outside a light's shadow cone/frustum is not drawn into that slot (per-slot cull — assertable via the occluder submission count, mirroring the entity-occluder counters).
- [ ] Maps with no movers, and static maps generally, render unchanged.
- [ ] No new `unsafe`; no non-renderer module imports `wgpu` or creates GPU resources (grep/review gate).
- [ ] The mover material and occluder paths add no bind group (`max_bind_groups` stays 8) and require no new adapter feature or promotion-budget increase.

## Tasks

### Task 1: Shared material-shading WGSL snippet (behavior-preserving)

Extract the world shader's binding-agnostic material leaf helpers into one shared WGSL snippet: the Blinn-Phong specular function (`forward.wgsl` `blinn_phong`), the normal-map decode (`sample_normal`), the octahedral decode, and the tangent-space (TBN) reconstruction block. These take all inputs as arguments and declare no bindings — the §8 "share by concatenation" pattern. Append the snippet to the forward and skinned-mesh shaders in place of their inline copies (Task 4 appends it to the mover shader). This is behavior-preserving: the shared code is byte-identical to what it replaces, so the fixture-map render and existing render tests are unchanged. Land it alone so the refactor is verified independently of the mover feature. No new bindings, no pipeline changes.

### Task 2: Generic rigid depth-occluder pipeline

Add a renderer-owned depth-only pipeline and recorder for **rigid instance occluders** in a new module (working name `rigid_occluder_depth`), shaped generically so future rigid casters — E17-F moving shadow-casters, rigid debris, the roadmap's Chunk Primitive, rigid props/viewmodels — can become callers without a fork; kinematic movers are the sole caller this wave. Do **not** reuse the skinned depth path by faking a degenerate bone on brush geometry — a position-only rigid vertex path is simpler and more general than `skinned_depth.wgsl`. Match the skinned depth pipeline's frame integration otherwise: vertex-only, no fragment stage, `Depth32Float`, `depth_compare = Less`, the same depth bias the skinned occluders use, projecting `light_space_proj × (model × position)`. The recorder takes only a generic input set — a vertex buffer, per-instance model transforms, per-instance index ranges, per-instance world AABBs, the per-render light-space bind group (the existing spot `shadow_vs_bind_group` or cube `cube_shadow_vs_bind_group`) with its dynamic offset, and cone frustum planes — cone-culls each instance by its AABB (shared cone-frustum math), issues one depth draw per surviving instance over its index range, and returns the submitted count. Keep the seam thin: no per-material batching or instancing knobs for absent consumers. This requires a per-mover index-range table recorded at geometry install (the concatenation already knows mover boundaries; the beauty pass records per-material ranges — add per-mover ranges beside them). The recorder assumes the caller has opened the render pass and laid down world/cached depth; it never clears and never touches the promoted-depth cache — rigid occluders draw into the live pool each active frame, like entity occluders. Group 0 is the light-space uniform, plus one group for the instance transform buffer; no third bind group, no new adapter feature.

### Task 3: Movers drive static-light promotion

Add active movers to the promotion-relevance set so an eligible static light near a mover promotes into a shadow-pool slot, even with no skinned mesh present. Today the intersection gate (`selected_static_light_has_shadow_entity` in `renderer_light_slots.rs`) tests only the skinned-mesh frame plan; a mover-only scene never promotes. Thread the per-frame mover world-AABB set (transform × the mover's local geometry AABB) into that gate — either folding movers into the plan it iterates or adding a parallel mover-intersection check with the same closest-point-on-AABB / influence-radius test. Movers share the fixed promoted budget (8 spot / 2 cube) with skinned meshes through the existing score ranker: a mover-adjacent static light out-ranking and evicting a farther mesh-adjacent one is correct ranker behavior, not a regression — confirm existing entity-shadow tests still pass and mixed mover+mesh contention degrades gracefully. The mover AABBs threaded here are the same per-mover world bounds Task 2's cone cull and Task 5's wiring need — assemble them once game-side and share, and ensure they are set on the renderer before the light-slot update runs each frame.

### Task 4: Mover material parity + gated static specular

Extend the mover fragment shader to the world material contract using resources the mover pipeline already binds (the shared material bind group, group 1) and vertex data it already carries (the packed tangent at location 3), consuming Task 1's shared material-shading snippet so the math is identical to the world path. Declare the group-1 bindings the shader omits today — the specular texture, the material uniform (shininess), and the tangent-space normal map — at the forward shader's binding indices. Forward a world-space tangent and bitangent sign through the vertex shader, reconstruct the TBN basis (shared snippet), and perturb the shading normal from the normal-map sample before both the indirect and direct lighting terms. Add a Blinn-Phong specular term inside the runtime light loop (`accumulate_dynamic_direct`), gated to the **promoted static-light records only** — the loop's tail at index `>= dynamic_light_count`, a new count field added to the mover light-params uniform (the renderer already knows the dynamic light count; no new binding). Dynamic-tier records contribute diffuse only, matching every other surface. Each promoted specular contribution uses the specular map's red channel for intensity, `max(material.shininess, 1.0)` for the exponent, the camera world position for the view vector, and is scaled by that record's existing attenuation, cone, and shadow-visibility factors; the promotion weight `w` is pre-folded into the record's color, so multiplying the specular term by that color inherits the crossfade, and the diffuse-only baked static-direct SH atlas means nothing is double-counted. The camera position is already in the shared camera uniform buffer the mover binds at group 0 — declare that field in the mover's camera struct (a WGSL struct-declaration change; no Rust or bind-group change). Keep the diffuse Post-Retro sampling byte-identical (its parity test must still pass). This is shader-side plus the minimal Rust to declare the added material-group bindings and the `dynamic_light_count` param; the material BGL and per-material bind groups already carry all slots, so no upload-path or BGL change is needed.

### Task 5: Wire rigid occluders into the shadow record loop

Call Task 2's rigid-occluder recorder with the per-frame mover occluder set — per-mover model transform, world-space AABB, and index range (the same mover-AABB set Task 3 assembles) — so movers cast into every slot the entity occluders already serve. Thread that set from the game side into the shadow-pass recording path alongside the mesh frame plan; call-site wiring in `main.rs` only. In `renderer_shadow_passes.rs`, after the existing entity-occluder draw in each of the four occluder contexts — the dynamic spot pass, each dynamic cube face pass, the promoted-spot `LoadOp::Load` entity pass, and the promoted-cube `LoadOp::Load` entity pass — invoke the recorder with that slot/face's light-space bind group, dynamic offset, and cone planes (the same cone matrix the entity occluders cull against). Gate mover occluders on the same per-slot eligibility the entity occluders use. Keep these additions to call-site wiring plus a small cull invocation; if the recording functions cannot absorb the call sites without new logic, split the file along the spot/cube seam first (behavior-preserving), then add the wiring. Movers already sample the spot and cube pools as receivers, so no receiver-side change is needed — mover→mover shadows fall out of this task. The promoted-slot casting becomes observable once Task 3 promotes mover-adjacent static lights.

### Task 6: Demo map, verification, and docs

Extend a dev map (or the E17 platform dev map) with a moving platform authored against a material that has `_n` and `_s` siblings and a shiny material class, positioned under: a dynamic spot light, a dynamic point light, a bright static light with **no** skinned mesh nearby (to exercise mover-driven promotion), and a station where a mover and a skinned mesh both sit near bright static lights (to exercise promotion contention) — plus a static wall of the same material for parity comparison, a skinned mesh beside a mover, and two adjacent movers, so every acceptance criterion is directly observable. Verify: diffuse+normal parity against the static wall; the specular highlight under a promoted static light (and its absence under dynamic lights); the de-promotion crossfade; mover-driven promotion in the mesh-free scene; graceful contention (existing entity-shadow tests unchanged); and the moving shadow onto world, mesh, and the other mover. Update the durable contracts that changed: `context/lib/rendering_pipeline.md` §3 / §7.3 for the mover material path (now world-material parity with promoted-static specular, not albedo-only), the §4 promotion note (movers now drive static-light promotion; shared budget), and a new rigid depth-occluder note in §7.1 (movers, as the first rigid-occluder caller, cast into dynamic and promoted spot/cube slots via a position-only depth pipeline, cone-culled per slot, never into the static-depth cache).

## Sequencing

**Phase 1 (concurrent):** Task 1 (shared material snippet — behavior-preserving), Task 2 (rigid depth-occluder pipeline), Task 3 (movers drive promotion) — disjoint files: shared world/mesh shaders vs. new occluder module vs. light-slot promotion selection.
**Phase 2 (concurrent):** Task 4 (mover material/specular shader — consumes Task 1's snippet), Task 5 (wire occluders into the shadow passes — consumes Task 2's recorder and Task 3's shared mover-AABB plumbing) — independent of each other.
**Phase 3 (sequential):** Task 6 — demo, verification, docs; consumes Task 3, 4, 5.

## Open questions

- **Dynamic-light specular (deferred to a future engine-wide spec).** No surface in the engine has dynamic-light specular today — the dynamic light loop is diffuse-only. This is an incomplete area, not an intentional exclusion. Mover specular is therefore scoped to static (promoted) lights this wave, matching every other surface. Adding dynamic-light specular belongs in one pass across all surface types (world, mesh, mover), gated on measuring its per-fragment perf cost — its own spec. When it lands, movers get it nearly for free: they already loop the dynamic records; only the specular gate opens.
- **Specular under non-promoted static lights (deferred escalation).** Movers glint under promoted static lights (crisp, matching walls for those lights) but not under non-promoted static lights, where an adjacent wall does (walls use the full per-chunk spec-light list). The dominant lights promote, so the common case matches; dim/decorative fixtures are the gap. Because this wave gates specular to promoted records, mover specular is fully promotion-coupled — this escalation is the only route to promotion-decoupled static specular. Preferred escalation: **SH-dominant-direction specular** — extract a dominant light direction + intensity from the baked static-direct atlas the mover already samples, run one Blinn-Phong lobe, covering all static-baked lights decoupled from promotion, no new bindings. Grounded dependency: that atlas stores **octahedral irradiance per direction, not raw SH coefficients** (`sh_sample.wgsl`), so there is no L1 coefficient band to read — dominant-direction extraction needs a multi-tap reconstruction (weighted centroid/argmax over octahedral taps), extra cost and approximate, not a free read. Still cheaper than the per-chunk spec-light-list alternative (new static-light bindings + per-mover chunk resolution) but lower fidelity (one averaged lobe, no per-light crispness). Revisit only if the promoted-subset gap reads wrong in practice.
- **`renderer_shadow_passes.rs` split.** Whether Task 5's four call sites justify a behavior-preserving split of the 1141-line file is left to the implementer; the task instructs wiring-only additions first.
