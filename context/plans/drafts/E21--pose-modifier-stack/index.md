# Pose-Modifier Stack + Aim Fidelity

## Goal
Add a post-sample pose-modifier stack to the animation runtime: an ordered, per-bone-masked list of modifiers that transforms local joint poses AFTER clip sampling/blending and BEFORE the bone palette builds, consuming per-frame inputs computed in the game-logic tick. Land the stack alone first (headless, proven by scalar aim inputs), then ship aim-pitch spine bend and the upper/lower-body split on it. This is the load-bearing Epic 21 seam: get it right and aim bend, foot IK, recoil, NPC head-look, and executions all become additive modifiers rather than bespoke pose hacks.

## Scope

### In scope
- A pose-modifier stack in `crates/model` that runs over the per-joint local-TRS buffer between blend/sample resolution and palette composition. Wgpu-free and collision-free — modifiers consume externally-supplied inputs only, never query world state.
- Per-bone masking: each modifier is scoped to a named joint set derived from glTF `extras` tags at load, mirroring the hit-zone tagging mechanism.
- Two shipped modifiers: aim-pitch spine bend (distributes a scalar pitch across a tagged spine chain) and upper/lower-body split (upper joints track aim yaw, lower joints keep the sampled clip heading).
- Routing the single-clip sample path through a materialized local-TRS buffer so cross-joint modifiers see the whole pose (today it fuses sample+compose per joint).
- External-input plumbing: a per-entity pose-input side channel written in the fixed tick, read by the render collector, carried into the renderer's palette build.
- A behavior-preserving split of `crates/model/src/anim.rs` (~1437 lines) before it is extended.
- Headless determinism tests exercising the stack with scalar aim inputs.

### Out of scope
- Foot IK, ground probes, the locomotion descriptor, and `travelSpeed` calibration — the sibling plan `E21--foot-ik-locomotion-descriptor`, which depends on this one.
- Recoil, NPC head-look, execution/animation-lock modifiers — future modifiers on this stack; only the two above ship here.
- Any change to hit-zone authority. Hit-zone capsules keep reading the UNmodified world pose; the authoritative aim ray stays the replicated/game-logic pitch-yaw, never the bent spine. Aim bend is presentation only.
- Local first-person / remote avatar presentation and any wire change — the `E21` co-op-avatar plan.
- Bone sockets / attachments — a separate Epic 21 plan.
- State-gated aiming. Enemies aim the torso whenever a target is held (else no twist — the torso holds the body heading); gating aim to specific logical states (e.g. only in Attack) is a small follow-on that belongs with the locomotion descriptor in the sibling plan, not here.
- Descriptor-authored modifier order. The stack order is loader-pinned — upper/lower split before aim-pitch bend, so overlapping spine joints compose predictably. Authoring the order is deferred until a third modifier needs a different interleave.
- Per-render-frame interpolation of aim inputs. Aim inputs step at tick rate against the interpolated transform; interpolating the split per render frame is deferred.

## Acceptance criteria
- [ ] A model with no pose-modifier tags renders a bone palette byte-identical to the pre-change path (runnable equality test). *Review gate:* the empty-stack path takes the existing unmodified compose, adding no allocation.
- [ ] A model whose spine joints are tagged as an aim chain, fed a scalar aim-pitch input, renders with those joints rotated so the chain tip pitches by the input angle, the bend distributed across the chain; joints outside the chain are unchanged.
- [ ] With upper-body and lower-body joint sets tagged and fed differing aim-yaw and heading inputs, upper-body joints track the aim yaw while lower-body joints keep the clip heading; joints in neither set are unchanged.
- [ ] Two modifiers whose masks overlap compose in list order — the later modifier observes the earlier one's output — verifiable from the rendered pose.
- [ ] Aim inputs reach the pose, verified in two observable halves: the fixed tick writes correct `pose_inputs` for an AI entity that has acquired a target (sim-level determinism test, Task 6), and those inputs drive the modified sampler to bend the torso toward the target while the legs keep the travel heading (model unit test feeding the inputs through the sampler). The full in-engine GPU render path is confirmed manually, not headlessly.
- [ ] Given identical scalar aim inputs, the produced palette is identical across repeated headless runs.
- [ ] Hit-zone hit capsules are unaffected by an active aim-bend modifier — a bent spine does not move the authoritative hit geometry.
- [ ] After the `anim.rs` split, every pre-existing `postretro-model` test passes unchanged (runnable). *Review gate:* no resulting non-test source file materially exceeds the ~800-line soft bound; test files (including the extracted `anim/tests.rs`) are exempt from the bound.
- [ ] A model with an unknown/malformed `poseMask` value, or a non-chain `aimSpine` set (branching, disconnected, or empty), loads successfully with a logged warning and an empty (or partial) stack — never a hard failure; a non-chain `aimSpine` set drops the aim-pitch-bend entry.
- [ ] An entity whose target coincides with its own position, or that aims straight up or down, produces finite `PoseInputs` (never NaN) and no palette corruption.

## Tasks

### Task 1: Split `anim.rs` into a module directory (behavior-preserving)
`crates/model/src/anim.rs` is ~1437 lines and this plan extends it; split it first along seams already present, changing no behavior. Convert to an `anim/` directory with `mod.rs` re-exporting the current public surface (`sample_clip`, `sample_clip_looped`, `sample_blended`, `sample_clip_looped_world`, `sample_blended_world`, `capture_blend`, `Loop`, `LocalTrs`, `BlendSource`) so no downstream caller changes — the three importers of `postretro_model::anim` must keep resolving: `mesh_pass.rs` (renderer), and `hit_zones.rs` (`crates/postretro/src/scripting/systems/hit_zones.rs`) and `mesh_anim.rs` (both game-side). Suggested cuts: track-level sampling (`sample_local_trs`, `sample_local_pose`, `locate_span`, `sample_vec3_track`, `sample_quat_track`) into `anim/track.rs`; the hierarchy/palette core (`compose_world_pose`, `compose_palette`) into `anim/compose.rs`; the two-source blend machinery (`blend_local`, `resolve_blend_into`, `capture_blend`) into `anim/blend.rs`; the type/time layer (`Loop`, `LocalTrs`, `BlendSource`, `resolve_time`) into `anim/types.rs`; public samplers stay in `mod.rs`. Keep the existing in-file `#[cfg(test)] mod tests` as a single `anim/tests.rs`, and mark the private fns it exercises `pub(crate)` within the `anim` module so the test file reaches them across the new submodules — rather than re-scoping each private fn's visibility per submodule. The thread-local scratch buffers (`WORLD_POSE_SCRATCH`, `BLEND_LOCAL_SCRATCH`) stay accessible to the compose/blend submodules. All existing tests must pass with no assertion edits.

### Task 2: Pose-modifier stack core in `crates/model`
Add the stack primitives to `crates/model` (wgpu-free, collision-free). Define a per-bone mask type scoping a modifier to a set of joint indices (skeleton/topo order, ≤256 joints), a `PoseModifier` value type (start with the two variants Task 3 fills; leave the set open for later foot-IK/recoil variants), and an ordered `PoseModifierStack` of (mask, modifier) entries applied in list order. Add a per-frame `PoseInputs` POD carrying the aim inputs modifiers read (aim pitch, aim yaw, and heading yaw — the entity's body yaw — all radians; leave room for the sibling plan's foot-probe array). `PoseInputs` derives `Debug, Clone, Copy, PartialEq` (required by the `MeshComponent`/render-payload derives); a `Default` derive is optional and harmless — serde's `#[serde(skip)]` (Task 4) needs `Default` on the field type `Option<PoseInputs>`, which holds for any `T`, not on `PoseInputs` itself. `Serialize`/`Deserialize` are NOT needed because that field is serde-skipped. `PoseInputs` (the POD) lives in `postretro-foundation`, following the movement-substrate precedent — foundation owns the substrate, entities re-exports it. `postretro-model` adds a `postretro-foundation` dependency — a legal downward edge (foundation depends on neither crate, and the layering invariant constrains `entities`, not `model`) — so the modified samplers can name `PoseInputs`. `crates/entities` already depends on `foundation`, so `MeshComponent` holds `foundation::PoseInputs` (re-exported from entities if convenient) with NO new entities dependency and NO invariant change; `crates/render-cpu` reaches `PoseInputs` through its existing `entities`/`model` deps. Add modified sampler entry points that materialize the per-joint `LocalTrs` buffer, run the stack over it in order (each modifier mutates only its masked joints), then compose the palette — a blended variant reusing `resolve_blend_into`, and a single-clip variant that must first materialize a `LocalTrs` buffer per joint (the current single-clip path fuses sample+compose in a closure and never builds the buffer, so this is a real change). Empty stack or absent inputs must fall through to the existing unmodified compose with no added allocation or math. Modifiers operate purely on the local-TRS buffer; a modifier needing world-space joint positions (e.g. to distribute a bend) computes them by walking the masked chain's local transforms itself — it never calls collision or wgpu. Do NOT add a modified variant to the world-pose samplers (`sample_*_world`) used by hit-zones: those must keep returning the unmodified pose so hit-zone authority is untouched.

### Task 3: Aim-pitch spine bend and upper/lower-body split modifiers
Implement the two shipped `PoseModifier` variants from Task 2, operating on the masked local-TRS joints. Aim-pitch spine bend: given a scalar aim-pitch from `PoseInputs` and a spine-chain mask ordered root→tip, apply an incremental pitch rotation per chain joint summing to the input pitch, so the chain tip faces the aim pitch and the bend spreads smoothly across the chain; joints outside the mask are untouched. Upper/lower-body split: given an upper-body mask and a lower-body mask plus aim-yaw and the body yaw from `PoseInputs`, rotate upper-body joints so the torso tracks aim-yaw while leaving lower-body joints on their sampled heading. The applied upper-body twist is the delta `aim_yaw − body_yaw`, not absolute `aim_yaw` — applying the absolute value would double-count the clip's existing heading; the body-yaw frame keeps the twist correct while the AI's rate-limited facing slew lags the velocity direction. A joint tagged in BOTH the `upperBody` and `lowerBody` masks receives half the split twist (the multi-membership the Boundary inventory permits is the explicit boundary marker), so the twist ramps across the seam instead of stepping. Both modifiers must be no-ops when their mask is empty. Order is fixed: the split runs before the pitch bend so overlapping spine joints compose predictably; the loader pins this order in the stack it builds.

### Task 4: External-input plumbing — tick writes, collector reads, renderer applies
Wire game-logic-computed aim inputs to the stack across the wgpu-free boundary. Add `pose_inputs: Option<foundation::PoseInputs>` to `MeshComponent` (`crates/entities`), `#[serde(skip)]` — a new transient-field pattern for this component (its existing `animation`/`origin_offset` fields still round-trip). No new entities dependency: `entities` already depends on `foundation`, where `PoseInputs` lives (Task 2); the serde-skip needs `Default` on the field type `Option<PoseInputs>`, satisfied for any `T`. Written each fixed tick, read the same frame. In `simulate_tick` (`crates/postretro/src/sim/mod.rs`), alongside `update_brain_animation_playback_rates`, compute each animated entity's `PoseInputs`. `BrainComponent.acquired_target` is `Option<EntityId>` (not a position): when a target is held, look up that entity's `Transform.position` and derive aim pitch/yaw from `target.position − self.position`; when no target is held or the lookup misses (target despawned), `aim_yaw` falls back to the entity's body yaw (zero twist) and aim pitch to zero. Heading yaw is the entity's body yaw — its tick-end `Transform` rotation yaw, always defined — so the upper/lower split twist `aim_yaw − body_yaw` is the actual twist from where the body faces to where it aims. This stays correct while the AI's rate-limited facing slew (`FACING_TURN_RATE`) lags the velocity direction, and makes the stationary case well-defined: a stationary aimer's body yaw is defined, so no velocity-heading fallback is needed. Per-frame interpolation of the split against the interpolated transform is deferred (see non-goals). When the target direction's horizontal (XZ) component is near zero — a coincident target position, or aim pointing straight up or down — `atan2` is undefined, so `aim_yaw` falls back to `body_yaw` (zero twist) and pitch is clamped to a safe range, mirroring the AI facing guard (`yaw_rotation_toward` returns no rotation for a zero-length direction). `PoseInputs` must never carry NaN. This write stays in the tick because the render collector borrows the registry immutably. The collector `MeshRenderCollector::collect_inner` (`crates/postretro/src/scripting/systems/mesh_render.rs`) packs ONLY the entity's `pose_inputs` into the per-instance render input; the modifier stack is NOT carried per-instance. A model carrying a non-empty pose stack forces per-frame resampling (`resample = true`) in the collector, exactly as precise-hit-zone models already do — otherwise a pose-masked model in a far stride-distance time-slice bucket renders a stale bend while its target moves; pose-masked models thus opt out of stride-distance animation time-slicing, acceptable because they are the player and actively-aiming enemies, few on screen at once. Add a `pose_inputs: Option<PoseInputs>` field to `MeshInstanceInput` (a `Clone` payload) next to the existing sample params, AND to `PlannedInstance` — `mesh_pass.rs` reads per-instance data from `PlannedInstance`, so copy `pose_inputs` through the `MeshInstanceInput -> PlannedInstance` builders in `crates/render-cpu/src/mesh_instances.rs` (`plan_mesh_frame` / `plan_forward_visible_mesh_frame`). The renderer's mesh pass (`crates/renderer/src/render/mesh_pass.rs`) resolves the model's `PoseModifierStack` by `ModelHandle` (where it already resolves the per-model skeleton for `sample_instance`), and branches to the modified sampler from Task 2 when that stack is non-empty and the instance carries `pose_inputs`, else the unmodified sampler. Thread the stack from `LoadedModel` into that store deliberately: `load_skinned_model` (`crates/renderer/src/render/renderer_models.rs`) today destructures `LoadedModel` with `..` and calls `insert_model(...)`, which has no stack parameter — so a new `LoadedModel` field is silently dropped and the resolved stack stays empty (aim bend would never render, no compile error). `insert_model` gains a `PoseModifierStack` parameter (or the store gains a parallel `model_pose_stacks: HashMap<ModelHandle, PoseModifierStack>`), `load_skinned_model` destructures and forwards the new field, and `UploadedModel` (or the parallel map) holds it so `mesh_pass.rs` can resolve it beside `model.skeleton`. Enumerate and update those call sites.

### Task 5: Load-time joint-mask tagging from glTF `extras`
Extend the model loader (`crates/model/src/gltf_loader.rs`) to read per-joint pose-mask tags from node `extras`, mirroring `read_joint_zone` / `JointZone`: the per-node key is `poseMask` (string or string-array value), naming the mask(s) the joint belongs to (mask names `aimSpine`, `upperBody`, `lowerBody`; a joint may belong to several). Reindex the collected memberships through the same topo remap the loader already applies to `joint_zones`, producing per-mask joint-index sets parallel to `Skeleton::joints`. Each named mask (`aimSpine`/`upperBody`/`lowerBody`) resolves to one of these joint-index sets, and that resolved set becomes the `ModifierEntry.mask` the modifier is scoped to. From those sets, build the archetype's `PoseModifierStack` at load (convention-driven for this plan: an `aimSpine` mask yields an aim-pitch-bend entry; `upperBody`+`lowerBody` masks yield an upper/lower-split entry; absent masks yield an empty stack). The loader emits the upper/lower-split entry BEFORE the aim-pitch-bend entry — the load-bearing order for AC #4 and the fixed-order decision. Surface the built stack and mask sets on `LoadedModel` next to `joint_zones`, for the renderer's model store to hold and use at palette build (the game side computes pose inputs in the tick from Brain/Transform and never reads the stack). Malformed/unknown mask names are ignored with a load-time warning, never a hard failure. Spine-chain ordering (root→tip) derives from the skeleton parent links across the `aimSpine` set. If the `aimSpine` set is not a single connected parent-linked chain (branching, disconnected, or empty), log a load-time warning and drop the aim-pitch-bend entry — never a hard failure, mirroring the malformed-mask rule.

### Task 6: Headless stack tests with scalar aim inputs
Prove the stack headlessly. Add `crates/model` unit tests (CPU-only, like the existing `anim` tests) that build a synthetic skeleton with masked chains, apply the stack with scalar aim inputs, and assert: empty stack equals the unmodified palette; a tagged aim chain pitches its tip by the input while off-chain joints hold; upper/lower split twists only the upper mask; two overlapping modifiers compose in list order; repeated runs with equal inputs produce identical palettes; with an aim-bend modifier active, the world-pose samplers (`sample_*_world`, the hit-zone path) return the unmodified pose — a bent spine does not move the hit geometry. Add one sim-level headless test in the determinism harness (`crates/postretro/src/sim/determinism_tests.rs`, following `simulate_tick_scales_walk_rate_...`) that drives `simulate_tick` for an AI entity with an acquired target and asserts the tick writes deterministic aim inputs onto the mesh component. No GPU/window in any test.

## Sequencing

**Phase 1 (sequential):** Task 1 (split `anim.rs`) → Task 2 (stack core) → the `crates/model` portion of Task 6 (headless stack unit tests). This is the whole epic's foundation: the stack lands alone and is proven by scalar aim inputs before any renderer or game-logic wiring.
**Phase 2 (concurrent after Phase 1):** Task 3 (aim modifiers), Task 5 (load-time mask tagging) — disjoint files. Task 3 depends on Task 2's variant enum; Task 5 depends on Task 2's stack type.
**Phase 3 (sequential):** Task 4 (plumbing across tick → collector → renderer) — consumes Task 3's modifiers and Task 5's per-model stack. Then the sim-level test in Task 6.

## Rough sketch
- New in `postretro-foundation`: `PoseInputs { aim_pitch: f32, aim_yaw: f32, heading_yaw: f32 }` (POD, `Copy`; `heading_yaw` carries the entity's body yaw; the sibling plan adds a foot-probe array). `postretro-model` gains a `postretro-foundation` dep so the samplers can name it; `crates/entities` re-exports it for `MeshComponent`.
- New in `crates/model` (in the `anim/` module or a sibling `pose_mod.rs`): `JointMask` (a joint-index set over ≤`MAX_JOINTS` joints), `PoseModifier { AimPitchBend { .. }, UpperLowerSplit { .. } }` (open for later variants), `ModifierEntry { mask: JointMask, modifier: PoseModifier }`, `PoseModifierStack(Vec<ModifierEntry>)`. New samplers: `sample_blended_modified(a, b, weight, skeleton, stack, inputs, out)` and `sample_clip_looped_modified(clip, skeleton, time, loop_policy, stack, inputs, out)`, both inserting the stack at the current `sample_blended` seam — right after the `Vec<LocalTrs>` buffer is resolved and before `compose_palette`.
- Loader: a `PoseMaskExtras` deserialize shape and `read_pose_masks(node.extras)` beside `read_joint_zone`; `LoadedModel.pose_masks: PoseMaskSet` and `LoadedModel.pose_stack: PoseModifierStack`.
- `MeshComponent.pose_inputs: Option<foundation::PoseInputs>` (serde-skip). Writer: a new `update_pose_inputs(registry, ...)` step in `sim/mod.rs` next to `update_brain_animation_playback_rates`, reading `BrainComponent.acquired_target` and the entity's tick-end `Transform` yaw (the body yaw): `heading_yaw = body_yaw`, `aim_yaw` from the target direction and falling back to `body_yaw` when the target is absent or the direction is degenerate — never NaN.
- Renderer instance payload (`MeshInstanceInput` in `postretro-render-cpu`, a `Clone` payload): a `pose_inputs: Option<PoseInputs>` field only — the stack is NOT carried per-instance. `mesh_pass.rs` resolves the model's `PoseModifierStack` by `ModelHandle` (beside the per-model skeleton) and branches to the modified sampler when that stack is non-empty and `pose_inputs` is present. A model with a non-empty stack forces `resample = true` in the collector (like precise-hit-zone models), so a time-sliced instance never renders a stale bend.

## Boundary inventory
Pose-mask tags cross the glTF-authoring boundary only (no TS/Luau/wire surface in this plan). Casing is authoring-facing camelCase, mirrored to Rust mask identifiers.

| Name | glTF node `extras` key/value | Rust |
|---|---|---|
| pose-mask membership | key `poseMask`, string or string-array value | `read_pose_masks` → `PoseMaskSet` |
| aim spine chain | `poseMask: "aimSpine"` | mask name `"aimSpine"` → `JointMask` index set |
| upper body | `poseMask: "upperBody"` | mask name `"upperBody"` → `JointMask` index set |
| lower body | `poseMask: "lowerBody"` | mask name `"lowerBody"` → `JointMask` index set |

Existing precedent: hit-zone tags use node `extras` keys `hitZone` / `hitZoneRadius` (`gltf_loader.rs` `JointZoneExtras`). Follow the same per-node read + topo-remap path.
