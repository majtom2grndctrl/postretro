# E16--damage-types-and-defense-layers

Brief · resumable · Epic 16 · reads: `context/lib/scripting.md` §1, §2, §5, §10.4, §10.5, §10.8, §11, §12 · `context/lib/entity_model.md` §1, §Components · `context/lib/networking.md` §What gates, and what replicates instead, §Version gates · `context/lib/testing_guide.md` §Resource bounds · read at 44881f79

## Problem
The owner wants to prototype Borderlands-style combat: shields that soak damage and recharge after a delay, armor that resists some damage types and is weak to others, and gear or leveling that changes how a defense performs. None of it can be authored today:
- **The damage chokepoint goes straight to health.** It subtracts health first and only then fires impact policies, so a defense can only refund health after a hit, never absorb it before.
- **Hits carry no damage type.** The damage payload holds an amount and an impulse, nothing else.

When this is done, a mod:
- **Declares the vocabulary.** It names its damage types and defense layer kinds by the bindings it declares them under.
- **Stacks layers on descriptors.** Each descriptor stacks layers that drain before health on every damage source, scaled per damage type.
- **Authors recharge.** Each layer's capacity and recharge are literals or expressions over the mod's state.

HUDs, the enemy overlay, impact policies and enemy brains can all read the result.

## Decisions
- **Defense layers are an engine-owned noun with author-named instances:** the engine owns each layer's current value and its drain and recharge system, and authors name layer kinds mod-wide and attach them to descriptors. This follows `entity_model.md` §1 (shields are an engine noun) and `scripting.md` §11 ("the engine ships the component and its per-tick system; the author ships the policy"), and deliberately diverges from the roadmap's per-entity `@state` home (`research.md` §Layer home). Author `@state` shields keep working where they're read today (the overlay), and the engine never drains them.
- **Vocabulary handles are named by their binding, through the compiler's binding-name sugar:** `defineDefenseLayer` and `defineDamageType` join `defineStore`, `defineImpactEvent` and `definePresentationTemplate`, so TS `export const shock = defineDamageType({ … })` is named `shock` at build; TS may also pass the name explicitly, a computed one included, as `defineStore` allows (`defineDamageType(name, matrix, options?)`, `defineDefenseLayer(name, options?)`), and Luau, whose source runs raw, always passes it: `Postretro.defineDamageType("shock", { … })`. Every handle carries its name from creation, as a store ref carries its dotted name, so level scripts and repeated Luau `require`s reference it by name. This diverges from the explicit name fields ghost styles and fluids keep because map files reference them (`scripting.md` §2): here the one map reference, `crush_damage_type`, names the binding (`research.md` §Handle naming).
- **`defineMod({ defenseLayers: [shield, armor], damageTypes: [shock, …] })` registers the vocabulary, as `stores: [...]` registers stores, and every reference resolves by the name its handle carries.** The declaration the mod manifest registers is the one in force; a level script or a repeated `require` that re-runs a declaration only gets handles, as a re-run `defineStore` only supplies slot refs. Each handle crosses as `{ kind: "defenseLayer", name }` or `{ kind: "damageType", name }`, its accessors and methods kept off the wire as a store ref's `byPlayer` is, so a bad reference (a name no list registers, a bare string, or a handle of the other kind where a layer or type handle is expected) is caught by the surface that holds it: it fails load, naming the key path, on a descriptor or a descriptor expression (`layers`, `damageType`, a layer parameter, a brain guard); drops that one definition at install with a log naming it on a reaction (`grantLayer`, `.damage`'s `type`), impact policy, crossing or player-event condition, level-local ones included; warns once at tree build on a UI binding, as an unknown slot does (`ui.md`); and skips that shield pair with a warning at overlay install on an overlay callback, as a malformed overlay is skipped.
- **Load fails, naming the key path,** on a layer named `health`; two entries with one name in one `defineMod` list (`research.md` §Handle naming); a bare string, or a handle of the other kind, in a `defineMod` list; a `defaultDamageType` that is not a type handle its `damageTypes` lists; a name that is not 1–64 bytes of `[A-Za-z0-9_-]` (`grantAmmo`'s type grammar, `scripting.md` §10.8, without `.` and `:`, because names compose into dotted slot and input paths); a matrix key naming neither a registered layer nor `health`; a `resist` key, on `health` or on a layer entry, naming no registered type; or a layer kind listed twice in one descriptor's `layers`. The `health` block now rejects unknown keys; today it silently ignores them.
- **Layers live inside `health`, in drain order.** Each entry is `{ layer, capacity, rechargeDelayMs?, rechargeRate?, resist? }`; omitted, the delay is 3000 and the rate 0, and rate 0 never recharges, which is armor. Literal ranges are capacity [0, 1e6], delay [0, 60000] ms, rate [0, 1e6] points/s and each resist value, on a layer entry or on `health`, [0, 64], and a literal outside its range rejects load.
- **A layer parameter (capacity, delay, rate, or a resist value on a layer entry or on `health`) is a literal or a Number expression, so it changes by derivation, not by writes.** This follows `assistable.radius` / `holdMs` (`plans/done/E18--player-revive-assist`): leveling and gear raise a store slot the expression reads, so persistence and co-op stay single-source and no write verb exists. The scope reads global store values, the entity's own `@state.*`, and, on the player entity only, its seat's per-owner store slots, as plain reads; a per-owner read on any other descriptor rejects load, and a per-player engine-slot read rejects load on every descriptor.
- **Parameters are host-evaluated, and a store change shows by the next tick.** Results clamp into the literal ranges. Lowering capacity clamps the current value down; raising it never fills the layer on its own.
- **An expression fault, a non-finite result included, keeps that entity's last good value.** This sets a new precedent: assist falls back to 0, and this deliberately diverges because falling to 0 would clamp a live layer to zero. Before any good value, a faulted parameter uses that field's omitted default (1 for a resist), or 0 for capacity; the warning fires once per descriptor and field, and hot reload re-arms it.
- **Authors refill layers with an additive grant that matches its siblings exactly:** `grantLayer(layer, amount?)` joins `grantHealth` and `grantAmmo` (`scripting.md` §10.8) through the one grant chokepoint, with a literal finite amount on group and subject tokens and a Number expression on `impact.source`; an omitted amount fills to capacity, a negative amount warns and does nothing, and a recipient without that layer warns and is skipped. A grant evaluates the layer's capacity when it applies, so an impact policy's grant sees that policy's earlier writes, and that evaluation holds from then on, for later hits and as the entity's last good value: the value clamps to it, then the grant adds.
- **A reaction body's store writes, grants and damage land in body order on every source and every machine, because authors read a body top to bottom, and a body that ran differently on a client is one a modder cannot see or test from one machine.** This changes engine behavior (`scripting.md` §10.4): on a reaction fired by address (crossings, `levelLoad`, `fire` targets, UI presses), store writes (`addSlot`, `setState`) apply at dispatch, as `grantHealth` and `.damage` do, not at the frame-end drain, wherever the reaction runs (host, single player, or a connected client firing its own-state or host-mirrored reactions) and behind each machine's existing write gates, so a connected client still refuses `addSlot`. A write to a seat released earlier in the frame now warns and is skipped, where the drain skips it silently today (`research.md` §Body order).
- **A mod-wide matrix plus pool-local resistances decide how much a typed hit drains (`research.md` §Matrix and resist):** `defineDamageType({ <layer> | health: m })` sets how much one raw point of that type takes from each pool kind, where m is a multiplier in [0, 64] or, on a layer only, `"bypass"`; a missing entry is ×1, and `health: "bypass"` rejects load. A layer entry's `resist: { <type>: m }` scales that type on that layer only (the equipment), and `health.resist` scales it on health only (the body, so entity-wide on an unlayered entity); a missing key is ×1. A pool's multiplier is its matrix entry × its own resist, no multiplier spans pools, and a `"bypass"` pool stays bypassed whatever its resist.
- **Drain order and spillover are engine rules in the damage chokepoint, for every producer (owner: every source drains, Borderlands lean).** The incoming amount, after hit zones as today, meets each layer in order: a layer above zero takes raw × its multiplier, when it empties only the raw remainder it could not absorb moves on (`research.md` §Matrix and resist), and a layer at multiplier 0, by matrix or by resist, absorbs all raw that reaches it while above zero, draining nothing. `"bypass"` passes a layer untouched, a zero-valued layer is skipped whatever its multiplier, health takes the remainder × its multiplier, and the death latch, the sweep and `target_was_live` keep reading health only.
- **Spillover, recharge shape and no-fill-on-raise are engine taste points.** `scripting.md` §1 says the engine owns no game's taste and §11 places recharge curves in author policy; these defaults diverge because each ships a Borderlands-correct rule a novice can use untouched. Each grows along a named axis whose extensions default to today's rule: spillover and recharge shape along the authored-policy axes in Non-goals, fill on raise through `grantLayer`.
- **Every producer carries a type, or the mod's default.** Weapons carry a weapon-level `damageType` (hitscan, projectiles, splash, NPC ranged attacks and traps), NPC melee attacks carry `attacks.<name>.damageType` (beside `weapon` it rejects load, as inline contact stats do), movers carry the FGD KVP `crush_damage_type`, a type's name that warns once per unknown name per level load and counts as absent, and the script verb `.damage(amount, options?)` takes the damage-type handle as `options.type`. The optional `defineMod({ defaultDamageType: ballistic })` types every producer that names none, and `@impact.type.<name>` reports it on those hits. Without it, untyped damage is ×1 on every pool, no resist applying, so a mod without types or layers keeps today's drain (`research.md` §Default type).
- **The dev arsenal exercises the matrix:** `reference_plasma_bolt` names `plasma`, energy strong against shields and weak against armor, and `reference_rocket` names `explosive`, strong against armor and flesh; its splash, which is its only damage, deals it to the struck target and every target in radius. Every other dev weapon names `ballistic`, which stays the dev mod's `defaultDamageType` (`research.md` §Default type).
- **Recharge is an engine per-tick host step at tick start, so every hit in tick N lands after that tick's recharge.** Any hit with a positive incoming amount, wherever it lands, restarts every one of the entity's layer delays, even one fully absorbed, blocked or bypassed. The last-hit stamp is live state that only a hit sets: time spent latched counts toward the delay, hits on a latched entity still restamp, and spawn, respawn, carry and grants never touch it, so a layer below capacity with no hit since arrival recharges from its first tick.
- **Recharge skips any entity at health ≤ 0, latched or not, though a lowered capacity still clamps its layers.** Respawn refills every layer to capacity, and `setHealth` and `grantHealth` leave layers alone.
- **The layer step's per-tick cost is bounded by construction, with no cap on layered entities (`context/lib/index.md` §1.1: "Measure, don't assume").** A literal parameter binds to a constant and is never evaluated per tick, as `assistable`'s literal fields bind; an expression parameter takes the depth-32 / 256-node cap `assistable` and weapon scale expressions carry, and one past it rejects load; and the step visits only entities carrying layers and allocates nothing (`scripting.md` §11). The step reports as its own CPU stage, and the plan of record reports a stress measurement (`research.md` §Per-tick cost).
- **A layer parameter that reads only global values evaluates once per descriptor per tick (owner amendment, 2026-11-05).** The stress run measured 29.3 ms per tick with every parameter at the node cap reading a global slot, against 0.124 ms with literal parameters (plan of record §Stress measurement). An expression whose reads are all global store slots and constants (no `@state.*`, no per-owner value) gives one result for every entity of its descriptor at tick start. So the tick-start step evaluates it at most once per descriptor and field, and applies that result to each of the descriptor's entities, clamped into range. A fault leaves each entity its own last good value and warns once per descriptor and field, as today. An expression that reads the entity's own state or a player's per-owner value still evaluates per entity. Every evaluation outside tick start — spawn, respawn, seat bind, a grant's capacity, hot reload — stays per entity and on demand, so a grant still sees a store write made earlier in its body.
- **Layer values follow health's lifecycle:** spawn fills every layer, and a fresh co-op join arrives full at its seeded capacity, while a layer not full at its pre-seed capacity when the seed lands keeps its value. Level change, same-map restart and rejoin carry each value only when health carries, clamped to the arrival capacity evaluated with the seat's per-owner values. Hot reload keeps each layer's value by name, clamps kept layers, fills added ones and drops removed ones.
- **One quantity, "points dealt", means damage everywhere downstream of the chokepoint.** Points dealt is the total drained from layers plus health after type multipliers and resistances, and `@impact.amount` is points dealt, matching `research/combat-events.md`'s post-mitigation `damage`, because the plain name serves the common reader: damage numbers, lifesteal, stagger. `@impact.raw` is the incoming amount after hit zones and before type and layers (combat-events' `rawDamage`), `@impact.absorbed` is the layers' share of points dealt, and `healthBefore` / `healthAfter` stay health-only, so an unfloored `healthAfter` still yields overkill.
- **`@impact.broke` is true when this hit took some layer from above zero to zero, and each registered type adds a Bool, so type identity never enters the IR as a value (`research.md` §Commitments touched).** The contributor ledger, kill credit and brain threat record points dealt, so a player who only stripped a shield is a contributor. Brain damage recency resets on any hit to a live target with a positive raw amount, and a hit on a target that is not live (latched, or at health ≤ 0) credits no contributor and leaves brain memory as the lethal hit froze it, while its impact facts stay truthful, so rewards gate in policy.
- **A layer handle's `.current` / `.capacity` is a per-player read over the player's owner-private layer slots:** a plain read means the local player wherever a plain per-player read does (HUD `Bar`, store, crossings, plain impact-policy reads), and the evaluated player in a player-event condition. It takes `byPlayer` with `impact.source` and `on.player` only, and a layer read inside an interaction-pair expression rejects load, so pair-scope layer reads stay a non-goal.
- **Reads of a specific entity go through per-scope accessors that follow each scope's `state(name)`:** `impact.target.defense(h)` in an impact policy, the free function `defense(h)` in a brain guard (the brain's own entity), and `entity.defense(h)` in the overlay's `damagedEnemies` callbacks, each yielding `.current` / `.capacity` in that scope's value form. The overlay's "hide at full" counts its own shield pair: an entity is full only when health and that pair are both full.
- **The player's layer slots are owner-private:** `player.defense.<name>` and `player.defense.<name>.capacity`, keyed by layer name, read absent for a pawn without that layer. Registering a layer changes the state-schema fingerprint, not `WIRE_VERSION`, as the owner-private weapon-sample slots did (`networking.md` §Version gates).
- **Damage over time and shield types will enter through this brief's surfaces:** `defineDamageType`'s options argument is reserved for status options and `defineDefenseLayer(options?)`'s for roadmap `shields + shield types`, each empty today, and an unknown key in either rejects load; `.damage(amount, options?)` takes an options object so later fields (`source`, `status`) fit, and an unknown key in it drops that reaction at install with a log, per the reaction rule (`research.md` §Damage over time).
- **Non-goals:**
  - Status effects and damage over time: roadmap `status effects / DoT` owns them, and depends on this brief.
  - Crits: roadmap `crit math` owns them.
  - Shield special effects (nova, spike, absorb-to-ammo): roadmap `shields + shield types`, narrowed to special effects, owns them.
  - Authored recharge and overflow (per-layer `overflow`, recharge-scope inputs, a per-layer recharge expression): roadmap `authored defense-layer recharge and overflow policy`, added at promotion, owns them.
  - Per-action damage types. Weapon-level only; augments may add one later (`research/weapon-model.md` §3).
  - Teammate shield bars: a roadmap item added at promotion owns them. Owner-private values never leave their owner; a teammate HUD is its own replication decision.
  - Client prediction of layer values. Host samples are enough for a bar.
  - Impact policies for script and environmental damage. Roadmap "DoT / environmental death policy" owns that; layers still drain on those paths.
  - Pair-scope layer reads: the roadmap item "Per-entity state reads in interaction-pair expressions" owns them, reworded toward layer reads.

### Scripting surface
```ts
// scripts/defenses.ts — layer kinds; each is named by its binding at build
import { defineDefenseLayer } from "postretro";
export const shield = defineDefenseLayer();
export const armor = defineDefenseLayer();

// scripts/damage-types.ts — named by binding; the matrix keys are layer names or health
import { defineDamageType } from "postretro";
// bullets: armor shrugs off a fifth. The dev mod's default, so anything that names no type (bare melee, crushers, `.damage(n)`) deals it
export const ballistic = defineDamageType({ armor: 0.8 });
export const plasma = defineDamageType({ shield: 1.5, armor: 0.5 }); // energy: strips shields, halved by armor
export const explosive = defineDamageType({ armor: 1.5, health: 1.25, shield: 0.75 }); // cracks armor and flesh
export const shock = defineDamageType({ shield: 2, armor: 0.5, health: 0.75 });
export const corrosive = defineDamageType({ shield: 0.5, armor: 2 });
export const flechette = defineDamageType({ shield: "bypass", armor: 0 }); // slips past shields; standing armor stops it whole

// every file below, level scripts included, imports handles from those two modules
import { armor, shield } from "./defenses";
import { ballistic, corrosive, explosive, plasma, shock } from "./damage-types";
import { defense, defineEntity, defineImpactEvent, defineReaction, defineTriggerEvent,
  npcs, read, when, type PlayerEventParams, type TriggerEventParams } from "postretro";
import { Bar, damagedEnemies } from "postretro/ui";
// gains per-owner `shieldCapacity`, `shieldTech` and the gear level `shockWard`, each shaped like `xp`
import { progression } from "./combat-lifecycle";
import { leveling } from "./leveling";
// Each new persisted slot needs a minted identity entry, as `progression.xp` has: `postretro-tool mint-identity dev`.

// player.ts components — capacity and recharge read per-owner progression; the shield's own shock ward is gear
health: { max: 100, layers: [{
  layer: shield, capacity: read(progression.shieldCapacity).plus(50),
  rechargeDelayMs: 2500, rechargeRate: read(progression.shieldTech).times(4).plus(20),
  resist: { shock: read(progression.shockWard).times(-0.25).plus(1) }, // this layer only; ward 4 reaches 0, immune, and higher clamps there
}] },

// reference-enemy.ts components — armored, its flesh shock-resistant (health only), a corrosive claw, retreats once its armor breaks
health: { max: 70, layers: [{ layer: armor, capacity: 120 }], resist: { shock: 0.5 } },
behavior: { /* … */
  attacks: { /* jab, slam */ claw: { damage: 15, damageType: corrosive, maxRange: 2, cooldownMs: 800 } },
  transitions: { engage: [{ to: "retreat", when: defense(armor).current.le(0) }] }, // own layer, as `state(name)` reads own state
},

// reference-projectiles.ts — the plasma bolt deals plasma; the rocket's splash, its only damage, deals explosive
weapon: { /* reference_plasma_bolt's stats */ damageType: plasma },
weapon: { /* reference_rocket's stats, splash included */ damageType: explosive },
// reference-pistol.ts — every other existing dev-mod weapon, `enemy_rifle` included, names ballistic explicitly
weapon: { /* existing stats */ damageType: ballistic },

// the triangle playtest's content: a shock gun, a corrosive gun, and a shielded reference-enemy variant
const arcRifle = defineEntity({ canonicalName: "arc_rifle", components: { weapon: { damage: 12, damageType: shock, /* … */ } } });
const acidRifle = defineEntity({ canonicalName: "acid_rifle", components: { weapon: { damage: 12, damageType: corrosive, /* … */ } } });
const shieldedEnemy = defineEntity({ canonicalName: "reference_enemy_shielded", components: { /* reference enemy's, with */
  health: { max: 70, layers: [{ layer: shield, capacity: 60, rechargeRate: 15 }] } } });
// typed script damage
const overload = defineReaction("turret.overload", npcs({ tag: "turret" }).damage(40, { type: shock }));

// player-events.ts — the existing level-up also raises capacity, then fills health and shield to the new capacity
const levelUp = defineReaction("leveling.levelUp", (on: PlayerEventParams) => [
  on.player.addSlot(leveling.level, 1), /* …its existing steps */
  on.player.addSlot(progression.shieldCapacity, 25), on.player.grantHealth(100), on.player.grantLayer(shield),
]);

// combat-lifecycle.ts — a booster pad adds 25: a mod-global rule over every volume tagged shield_booster
export const booster = defineReaction("combat.shieldBooster", (on: TriggerEventParams) => on.activators.grantLayer(shield, 25));
export const boosterPads = defineTriggerEvent({ tag: "shield_booster", event: "enter", fire: [booster] });

// hud.ts — the local player's shield bar
const shieldBar = Bar({ bind: shield.current, max: shield.capacity, fill: [0.3, 0.6, 1, 1], background: [0.05, 0.07, 0.1, 0.9] });

// combat-presentation.ts — damagedEnemyOverlay's source gains a shield pair over each enemy's layer
over: damagedEnemies({ lingerMs: 2_500, hideAtFull: true,
  shield: { value: (entity) => entity.defense(shield).current, max: (entity) => entity.defense(shield).capacity } }),

// combat-lifecycle.ts — refund the attacker a share of a shock hit that breaks a layer and leaves a live target's shield empty; mark a target whose armor is gone
export const shieldBreak = defineImpactEvent("shield-break", { tag: "enemy" }, (impact) => [
  when(impact.broke.and(impact.type(shock)).and(impact.target.defense(shield).current.le(0)).and(impact.target.healthBefore.gt(0)),
    [impact.source.grantLayer(shield, impact.absorbed.times(0.25))]),
  when(impact.target.defense(armor).current.le(0), [impact.target.setState("exposed", 1)]),
]);

// start-script.ts — registration lists each handle, as `stores` does; the default must be one of them
import { defineMod } from "postretro";
import { armor, shield } from "./scripts/defenses";
import { ballistic, corrosive, explosive, flechette, plasma, shock } from "./scripts/damage-types";
import { booster, boosterPads, shieldBreak } from "./scripts/combat-lifecycle";
export default defineMod({ defenseLayers: [shield, armor], damageTypes: [ballistic, plasma, explosive, shock, corrosive, flechette],
  defaultDamageType: ballistic,
  reactions: [/* … */ booster], triggerEvents: [/* … */ boosterPads], events: [/* … */ shieldBreak], /* … */ });
```
Luau mirrors every name, passing each declaration's name explicitly and with each accessor following its `state(name)` twin: `local shield = Postretro.defineDefenseLayer("shield")`, `local shock = Postretro.defineDamageType("shock", { shield = 2, armor = 0.5, health = 0.75 })`, `resist = { shock = 0.5 }`, `damageType = ballistic` on every Luau dev-mod weapon, `return Postretro.defineMod({ defenseLayers = { shield, armor }, damageTypes = { ballistic, plasma, explosive, shock, corrosive, flechette }, defaultDamageType = ballistic, … })`, `shield.current`, `defense(armor).current:le(0)`, `impact.target:defense(armor)`, `entity:defense(shield)`, `impact.type(shock)`, and so on. Both runtimes ship.

## Acceptance

### Declaration and validation
- [ ] A mod that declares layer kinds and damage types and registers them in `defineMod` lists loads, in TS named by binding and in Luau named explicitly, producing identical descriptors, each layer and type named by its binding and each handle reference crossing as exactly its `kind` and `name`. A Luau descriptor module that `require`s the defenses module again references the registered layers by name and loads.
- [ ] A level script that imports the handles references registered names: a `setupLevel` impact event gated on `impact.type(shock)` runs on a shock hit, and a `setupLevel` reaction's `.damage(n, { type: shock })` drains by shock's matrix.
- [ ] A level script that re-declares `shock` with a different matrix, and a Luau `require` that re-runs the damage-types module, get handles that drain by the registered matrix: the manifest's declaration stays in force.
- [ ] In TS, `defineDefenseLayer()`, `defineDefenseLayer({})` or `defineDamageType(matrix)` fails with the binding-name sugar diagnostic outside a direct top-level binding declaration (`const`, `let` or `var`) whose callee is the bare imported name, and `defineDamageType(m)` with the matrix in a variable fails with it anywhere, since the sugar takes only an object-literal first argument. `defineDefenseLayer("shield")`, `defineDamageType("shock", matrix)` and `defineDamageType(SHOCK, matrix, {})` with a computed name load anywhere, named by the string. In Luau, either without a name string errors.
- [ ] Load fails, naming the key path, for each of: a bad reference on a descriptor (a name no `defineMod` list registers, `layer: "shield"` or `damageType: "shock"` as a bare string, a type handle in `layers` or in a brain guard's `defense(h)`, a layer handle as a `damageType`), whether in `layers`, a weapon's or attack's `damageType`, a layer parameter or a brain guard; two `defenseLayers` entries, or two `damageTypes` entries, with one name; a type handle or a bare string in a `defenseLayers` list, and a layer handle or a bare string in a `damageTypes` list; a `defaultDamageType` that is a bare string, a layer handle or a type `damageTypes` does not list; a layer named `health`; a Luau name that is empty, longer than 64 bytes, or contains `.`, `:` or `@`; a matrix key naming no registered layer and not `health`; a `resist` key, on `health` or on a layer entry, naming no registered type; a matrix value that is neither a multiplier in [0, 64] nor `"bypass"`; `health: "bypass"`; an unknown key in `defineDamageType`'s or `defineDefenseLayer`'s options; `damageType` on an attack that names a `weapon`; a layer kind listed twice in one descriptor's `layers`; an out-of-range literal, a resist of 65 included; an unknown key inside `health`. A valid sibling of each loads, including one descriptor listing two different layer kinds, a matrix mixing multipliers, `0` and `"bypass"`, and a descriptor whose layer entry and `health` each carry a `resist`.
- [ ] A bad reference (a name no `defineMod` list registers, a bare string, or a handle of the other kind) read in an impact policy, a crossing or a player-event condition, or passed to a reaction (`grantLayer(shock)`, `grantLayer("shield")`, `.damage(20, { type: shield })`, `.damage(20, { type: "shock" })`, or an unregistered handle in either), mod-global or level-local, drops that one definition at install with a log naming it and the reference, its siblings install, and load does not fail. In a HUD binding it warns once at tree build. In an overlay callback, overlay install skips that shield pair with a warning. An unknown key in `.damage`'s options drops that reaction at install with a log.
- [ ] A layer expression with a per-owner read, a `health.resist` expression included, loads on the player entity and fails load on an enemy descriptor.
- [ ] An unknown FGD `crush_damage_type` warns once per unknown name per level load, two crushers naming it included, and crushes as a crusher without the KVP does: the default type, or untyped without one.

### Drain
Rows and pins that say *untyped* run in a mod without `defaultDamageType`.
- [ ] A mod with no types, layers or `defaultDamageType`: health results and every existing impact fact are identical to before, so the existing chokepoint, contributor-ledger, impact-policy and overlay tests pass unmodified, except where hide-at-full now also counts an overlay's shield pair.
- [ ] A mod that never sets `defaultDamageType` keeps today's result on every untyped hit: ×1 on every pool, every resist ignored, and no type Bool true. With `defaultDamageType: ballistic`, an NPC melee attack and a frame-end `.damage(n)` that name no type, and a crusher with no `crush_damage_type`, each drain as ballistic, and the melee impact reports `impact.type(ballistic)` (R-P36).
- [ ] In the dev mod, every existing weapon, TS and Luau, names a type: `reference_plasma_bolt` names `plasma`, `reference_rocket` names `explosive`, and every other names `ballistic`. A ballistic dev gun's hit on an armored target drains the armor at ×0.8 and reports `impact.type(ballistic)`. A plasma bolt for 30 against shield 30 and health 100 empties the shield on 20 raw and leaves health 90, with amount 40, absorbed 30 and `impact.type(plasma)`; one for 20 against armor 50 leaves armor 40.

### Recharge
- [ ] Nothing recharges before the delay. After it, the layer ramps at the rate and stops at capacity.
- [ ] A hit mid-ramp restarts the delay; so does a fully absorbed, blocked or bypassed hit. A rate-0 layer never recharges. A delay of 0 starts recharging on the next tick.
- [ ] An entry that omits rechargeDelayMs first recharges 3000 ms after a hit, and one that omits rechargeRate never recharges.
- [ ] A delay lowered mid-delay, by a store write or a hot reload, applies from the next tick against the original hit: a hit on tick N, then a delay cut from 3000 to 500 ms on tick N+60, first recharges on tick N+61 (R-P20).
- [ ] A hit on the tick the delay expires: that tick's recharge applies first, the hit then drains, and the delay restarts.
- [ ] An expression parameter tracks a store change on the next tick. Lowering capacity clamps the value; raising it does not fill. A faulted expression keeps each entity's own last good value and warns once per descriptor and field: two faulting entities of one descriptor warn once, and a second faulting field warns again. One that faults before any good value reads its field's omitted default (a resist reads 1), or 0 for capacity, and a hot reload re-arms the warning.
- [ ] A capacity whose expression faults at spawn spawns the layer at 0 / 0 and warns once; once it evaluates to 80 that evaluation reads 0 / 80, and at rate 60 points/s the tick ends at 1 / 80. It fills only by recharge, which starts that tick with no hit to wait on, or a grant (R-P17, R-P19).
- [ ] A capacity reading the entity's own @state.tier tracks an impact policy's setState on the next tick. A layer parameter reading an engine per-player slot, a layer's own current or capacity included, fails load on every descriptor, the player's included. So does a `defense(h)` read of any layer, the entity's own included.
- [ ] An entity latched at zero health does not recharge, and neither does one at zero health that is not yet latched, such as a pawn killed by frame-end script damage. Respawn refills every layer. Its capacity still tracks the store, and a lowered capacity clamps it (R-P23).
- [ ] A pawn revived after lying latched longer than the delay starts recharging on the first tick that begins with it above zero health, while a hit taken while latched restarts the delay from that hit (R-P14). A carried layer below capacity starts recharging on the first tick after arrival (R-P13).
- [ ] A hit after the tick restarts the delay exactly as a hit inside the tick does: a flushed client hit and frame-end script damage each first recharge on the same tick as a weapon hit, in co-op and in single player (R-P2).
- [ ] Only a hit sets the last-hit stamp: a pawn killed on tick N and respawned at 100 / 100 before its delay expires, whose capacity then rises to 150, reads 100 / 150 and first recharges 180 ticks after the lethal hit, by rate × dt (R-P27).
- [ ] Delay expiry is tick-exact: a 3000 ms delay at 60 Hz first recharges 180 ticks after the hit, by rate × dt, and does the same after long uptime (R-P3).
- [ ] A respawn fills to the capacity in force that tick, even when the store raised it the tick before. A capacity lowered mid-tick by a store write alone, with no grant after it, applies from the next tick, so a hit later in the same tick drains against the old capacity (R-P4).
- [ ] Expression results clamp into the literal ranges: a capacity of 2e6 evaluates as 1e6, −5 as 0, a delay of 90000 ms as 60000, and a resist of 70 as 64. A non-finite result is a fault and keeps the last good value.
- [ ] A connected client runs no layer recharge and evaluates no layer parameter. Its layer reads come only from the host. A parameter that faults warns on the host and never on a connected client.

### Per-tick cost
- [ ] Literal parameters skip per-tick evaluation: over 600 ticks with all-literal layers mid-recharge, a test counter of parameter evaluations reads 0 while recharge still ramps at the literal rate.
