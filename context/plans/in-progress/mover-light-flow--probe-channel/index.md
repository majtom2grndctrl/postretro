## Problem

Brief 1 of 2 in mover light flow, for the set-pieces the product makes first-class: monster closets, scripted reveals, a wall that slides, a room that rises (`context/lib/index.md` §1). Every probe bake runs with every mover absent (id 43): the direct-SH bakes movers and entities light themselves from (ids 35, 41, 45), the SH base (id 34) every surface takes its static bounce from, and the probe depth (id-34 moments, id-59 tiles) the sampler weights probes by. The compose has no input from mover state. So, on `mover-setpiece`, the risen room's interior is lit by the arena's baked lights as if its walls weren't there, and an entity behind the closed sliding wall stays lit. A dark closet sealed by a door glows with the bright room's bounce near the doorway, as if the door were open: closet probes hold open-door bounce, and bright-side probes, whose depth never saw the door, lend their light past it. And promotion pops today on a closed closet door (`drafts/animated-promotion-direct-sh-pop.md`: 145 at w = 0, 186 at w = 1). When this is done, a gated light's direct term reaches mover and entity receivers only where it would with the mover in place; static bounce and probe depth near a mover match a bake with the mover in place; all three follow the mover's position along its path, and back on reversal; and a gated light hands off to promotion with no pop beyond what the same light's ungated arms show today.

## Decisions

- **Driven by mover state, never by light state.** Neither half recomposes because a light changed. Any compose gate is framed as residency or visibility. The channel stores per-light direct visibility and per-mover absolute static bounce, never a swapped ambient or AO layer (`ip-check.md` §Piece 7). The bounce half sums static lights only, so it never covers a light that carries a curve. On the 2026-11-03 claim chart both halves lack '451 claim 1's light-source change and its changed-light coefficient (`ip-check.md` §Tencent US12293451B2). Engineering reading for counsel.
  - **Several movers at one probe (owner, 2026-11-08).** Id 34 plus their lerped bounce differences is the base + delta shape `ip-check.md` §Tencent design rules avoid. It stays: '451 claim 1 needs a light-source change, and these weights follow mover position over static lights only, so that element is absent however states combine. The counsel packet carries it.
- **Commitments this reverses (owner, 2026-11-03).** The bounce half overturns "doors change direct light only" (`gi-rtx-lite/index.md` §Hybrid stack; the foundation's bounce non-goal) and settles the research's open "is door bounce worth its bytes" by taking static door bounce now. Summing per-mover bounce differences is the accepted approximation for doors in series (`gi-rtx-lite/index.md` §Diagnosis of today's GI), so redesign gate item 1 stays not required. The rest of the hybrid stack stands.
- **Direct half: one scalar per state.** Per (mover, terminus, light, valid probe) the section stores q_k, the fraction of the light's baked soft visibility there that survives with the mover posed at terminus k, from the bake's own samples and seed. Warrant: `bake_probe_direct_rgb` stores one light at one probe as one lobe × radiance × one visibility, so the terminus state is exactly S_k = q_k × T, T being the light's per-probe tile.
  - T comes from the light's id-41 or id-45 entry when that entry is stored per probe. Under gated probes id 41's storage level is capped like ids 34/35's (below), so T is never rebuilt from corners. Where no entry survives, the section carries T.
  - Compose puts lerp(S₀, S₁, t′) in place of the light's mover-absent term. With q ≡ 1 the atlas equals today's.
  - Several movers gating one light at one probe multiply their lerped visibilities: never brighter than any one leaves it, never negative.
- **Bounce half: absolute static bounce per state.** Per (mover, terminus k, affected valid probe) the section stores S^b_k: id 34's own content (every static light's bounce one plus `_bounce_fill` × later bounces) re-baked with that mover's brushes posed at terminus k and every other mover absent. Animated lights' bounce (id 27) is not in it.
  - A probe is affected when its value at either terminus differs from id 34's by more than that probe's own round-trip error: its dense id-34 tile BC6H-encoded alone and decoded, independent of atlas placement and neighbours, so the bar is local, deterministic and memo-safe (exact match under `--uncompressed-irradiance`). The domain is derived, never sampled.
  - **Perceptual floor (owner, 2026-11-08).** The round-trip bar alone admits nearly every probe for a big mover: 11,420 of 11,942 on `mover-setpiece` with the wall closed, up to 34 m away. So a probe is affected only when its change also clears a fixed perceptual floor, which stays local and deterministic. Far probes keep id 34's bounce, as today. The floor's value is set at Stop 2 from a sweep with captures and bytes.
  - Compose puts lerp(S^b_0, S^b_1, t′) in place of id 34 at affected probes; several movers at one probe add their lerped differences from id 34. Compose clamps the sum so evaluated irradiance is non-negative in every direction. Id-27 deltas add on top as today.
  - Every reader of the composed indirect atlas inherits it: world surfaces, movers, entities, fog, billboard ambient and fluid surfaces.
  - Memory: everything the bounce bake holds resident is charged to the SH memory gate before any ray; overage is the named error, never coarsening (`development_guide.md` §1.4).
- **Bounce bake cost is gated before format work.** The bounce slice measures cold and warm mover-only cost on the full hallway; the owner sets the gate then. If over it, the fallback is to re-bake bounce one per pose and keep id 34's later bounces.
- **Reference closet (owner, 2026-11-07).** The closed mover door is held to the closet with its door as a static brush at the closed pose, built with id-59 tiles: station 3 reads 0.033 there against 0.495 untiled (`plans/done/direction-aware-probe-visibility/`). Its faint door-edge outline, whose source was not isolated and which persisted when a spike lowered the floor to 0.003, is part of the reference. The closet is never held to a looser bar than that reference.
- **Closed-pose depth blends with travel (owner, 2026-11-07).** Per (mover, terminus k, valid probe whose gather rays the posed mover changes) the section carries a bordered depth tile D_k, binned from the posed re-gather's own rays exactly as id 59 bins the base gather's.
  - **Significance floor, CPU-held (owner, 2026-11-08).** On `mover-setpiece`, the probes whose rays a posed mover changes number 11,566, with 39,990 closed-pose tiles. So a probe carries mover depth only when id 59's own visibility-change score, comparing its closed-pose tile with its mover-absent moments, clears a floor. Mover tiles that pass are still reserved first. The CPU holds closed-pose tiles, and the GPU holds only id 59's tiles and live tiles. The floor's value is set at Stop 2 from the same sweep.
  - Each such probe gets a renderer-owned live tile in the tile texture, beside id 59's. The renderer points the probe's reference at it and writes lerp(D₀, D₁, t′) into it on the first frame after install, on frames its mover's t′ changes, and on the next recording frame after a change no frame wrote. Depth moments mix linearly, so the live tile is always one continuous moment set and the shader is unchanged.
  - With no section, the frame is byte-identical to today's. With the section but no state supplied for the mover (owner, 2026-11-08), the probe's reference and texels keep its id-59 tile or averaged moments bit for bit, and the frame is within 2 levels per channel of the same PRL with no depth block.
  - Live tiles, and closed-pose tiles wherever they are held, are priced in the SH ledger and the build summary, as id 59's are. The tile texture's count (id 59's, live tiles, and closed-pose tiles if the GPU holds them) stays within the 15-bit tile reference. Mover depth is reserved first (owner, 2026-11-08): id 59's ranking cap shrinks by the mover tile count, and id 59 drops its lowest-ranked tiles and logs them as it does today. Mover tiles alone past the range are a named compile error, never a dropped mover tile.
- **IP design rules bind depth too** (`ip-372-direction-aware-visibility.md` §Design levers). Mover state blends moment sets; it never sets a per-probe occluded flag, forces a weight to zero, or excludes a probe. The 0.03 floor stays non-zero and the tile tap bilinear.
- **Closet water and fog.** Promotion never reaches fluids or legacy billboards: they sample the promotion-free direct atlas (`rendering_pipeline.md` §4, Baked direct for dynamic receivers), so the closet's water is judged with the rest of the closet. Fog takes no promoted lights and reads no depth, so closet fog at the door is judged as dark as the reference's fog (owner, 2026-11-08).
- **Promotion pop (owner, 2026-11-08, revising 2026-11-03).** Root-caused in this brief: the baked arm's representation reads below the runtime arm facing the light and above it at grazing angles, for id 41 and id 45 alike. The causes are the octahedral tile's 4×4 interior, L2 truncation and probe interpolation (`drafts/animated-promotion-direct-sh-pop.md`, Diagnosis). There is no bake or sampler bug. The fix that removes the pop outright gets its own brief: the baked arm reconstructed at the fragment from a per-probe visibility scalar × the runtime's n·l, falloff and cone. This brief adds no pop beyond today's ungated arms. A gated term lives inside the baked arm of both direct atlases (`rendering_pipeline.md` §4): the handoff atlas gives movers and skinned meshes (1 − w) × the gated term + w × the runtime term, whose slots already draw movers as casters (`RigidOccluderDepthPass::record_kinematic_movers`); the promotion-free atlas gives fluids and legacy billboards the gated term at every w. No receiver sums a light twice. If the fix grows past this brief, stop and report.
- **Lights in scope.** Static lightmap lights (id 35), directional included, and animated-baked lights (id 45). SDF-shadow lights, static or animated, are not gated: SDF shadows are soft-deprecated (`plans/done/mover-light-flow--foundation/`).
- **Blend scalar.** t is the mover's arc-length fraction along its path, 0 at the first waypoint and 1 at the last, derived on each peer from the final post-tick phase the blocked-portal rebuild reads. Phase already replicates (`WireKinematicMoverState`), so there is no wire change. Physics derives t; game hands the renderer one (mover id, t′) per present mover each frame, naming no SH concept; the renderer owns every GPU write. A mover with no supplied state is ungated.
- **Author ramp.** Two `kinematic_mover` keys reshape t into t′ = clamp((t − s) / (e − s), 0, 1): `light_ramp_start` (s, default 0) and `light_ramp_end` (e, default 1). Parse rejects anything outside 0 ≤ s < e ≤ 1, naming the mover. The section carries a per-mover ramp record for every mover with entries; id 43 is unchanged, so a map whose movers change no lighting keeps its parent's bytes. No section type reaches the game side: the loader hands the mover a plain (s, e). The ramp is keyed to position, never a timer. A runtime script method is deferred until a map needs one.
- **PRL section.** `MoverProbeChannel`, id 57: optional, whole-resident outside id 50, as ids 47/48 are. Absent, frames render today's output, where today's means the same PRL without id 57: a map whose id 59 was trimmed for mover depth keeps that trim (owner, 2026-11-08); malformed or unresolved, it is a load error. Its cells, direct and bounce, cap base storage levels as grid-matched delta entries (`sh_density::storage_level_ceilings`), and cap id 41's levels under gated probes. A map with no movers, or whose movers change no direct term, no probe beyond the bar above and no probe's gather rays, packs byte-identical. The section's GPU buffers are priced in the SH allocation ledger. The owner sets a resident byte bar at the bounce-cost stop; past it, the bounce payload streams with id 50's cells instead of staying resident, which extends the source lists of ids 49 and 50.
- **Cache: warm equals cold.** The direct half keeps a per-light memo shaped like `mover_light_probes`. The bounce half keeps a per-mover memo keyed on id 34's whole volume key plus the mover's posed brushes at both termini (and their materials, if they become patches); closed-pose depth tiles ride it, since they come from the same posed gather. Anything that re-bakes id 34 re-bakes every mover's bounce states; a mover-only edit re-bakes only that mover's.
- **Per-frame cost.** A travelling mover recomposes only rows carrying its entries and rewrites only its own live tiles; pass membership is tracked per mover, so a held mover's rows recompose nothing. This binds the streamed planner. The budget is ≤ 0.2 ms per travelling mover per frame on the 5300M, stricter than research step 5's per-door-event gate because a rising room travels for seconds. The t pass allocates nothing per frame.
- **Capture poses movers.** Capture scenes gain a forced mover t that sets the mover's whole pose (drawn geometry, shadow casters and occluder bounds), not the lighting alone, so the promoted arm's casters agree with the gated term. With capture's existing `force_promotion` pins on static and animated lights, promotion and A/B stills at mid-travel are then reproducible.
- **Non-goals.**
  - World-surface masks (lightmap texels, shadowmask, id-25 weights): brief 2, which consumes this brief's mover-state input. Until it lands, an entity behind a closed mover goes dark while the lightmapped floor under it stays lit by the same light; research build order steps 5 and 6 land in reverse, accepted.
  - Scatter billboards (valid scatter, ids 47/48) read no direct SH, so one behind the closed wall stays lit. The next roadmap leg owns it. A billboard without valid scatter samples direct SH and inherits the channel.
  - Animated lights' bounce (id 27) behind a mover: per-light bounce for a curve-driven light is the risky '451 shape; it waits on counsel's answer on id 27.
  - Per-light bounce states for static lights: rejected, far larger for no visible gain, since static lights never change.
  - Light → cell reach and slab shadows: pool and slab shadows own dynamic-tier lights (`gi-rtx-lite/index.md` §Door classification), and these set-pieces need neither.
  - Spinners, and intermediate waypoints as states: the foundation analyses termini only.
  - A script-side binding to mover progress.
  - Fog volumes' depth visibility: fog skips it today (`rendering_pipeline.md` §4), so live tiles do not reach fog.
  - Moving probes off the lattice: the roadmap's probe relocation entry.

Blend scalar:
- [ ] t reads 0 docked at the first waypoint and 1 at the last. It reads the arc-length fraction mid-travel, and that fraction at the middle waypoint of a three-waypoint path whose two segments differ in length. A wait or a blocked stop holds t.
- [ ] With default ramp keys, t′ = t at every sample above. With s = 0.6, e = 0.9: t′ is 0 at t = 0.6 and below, 1 at t = 0.9 and above, and 0.5 at t = 0.75, both rising and after a reversal. - [ ] A reversal mid-travel, in either direction, continues from the current t with no jump.

## Wire format

`MoverProbeChannel`, id 57. Mirrors id 41's (`DirectShDeltaVolumes`) header and per-affinity-cell CSR; the depth block mirrors id 59's (`ProbeDepthTiles`) tile bytes.

| Item | Pin |
|---|---|
| Endianness, version | Little-endian. First byte is a `u8` section-internal epoch, exact-match |
| Header | `affinity_factor` (`u8`, 4), `affinity_dims` (`u32` × 3); must equal id 35's grid |
| Cell index | `u64` valid-probe mask per affinity cell; `u32` × (cells + 1) CSR offsets, last = entry count. No cell-level array: every cell is L0 |
| Entry record, in order | `u32` mover id (id 43 `mover_id`); `u8` light namespace (0 = id-18 AlphaLights index, 1 = id-45 roster index); `u8` flags (bit 0 = carries its own tile, others 0); `u16` reserved 0; `u32` light index |
| Entry order | By cell, then mover id, then namespace, then light index; no duplicates |
| Visibility payload | Per entry, per valid probe in x-fastest order: `u8` q₀ then `u8` q₁, where q = byte / 255 |
| Own tiles | For flagged entries only, in entry order: one compact RGB f16 tile per valid probe, id 41's stride and tile dimension |
| Empty | The section is omitted when the direct, bounce and depth blocks all have no entries, never written empty; any one may be empty alone |
| Bounce index | A second CSR over the same affinity cells: per cell, entries of `u32` mover id, `u32` reserved 0, ordered by mover id, no duplicates; each entry carries its own `u64` affected-probe mask |
| Bounce payload | Per bounce entry, per affected probe in x-fastest order: the S^b_0 tile then the S^b_1 tile, id 27's compact RGB f16 octahedral tile stride and dimension |
| Depth index | `u32` record count, then per record, ordered by mover id then probe index, no duplicates: `u32` mover id, `u32` dense probe index (a valid id-34 probe) |
| Depth payload | Per depth record, in record order: the D₀ tile then the D₁ tile, each id 59's bordered tile (edge 8, border 1), `[f16 E[d], f16 E[d²]]` per texel, row-major |
| Ramp record | Per mover with entries in any block, ordered by mover id: `u32` mover id, `f32` s, `f32` e; brief 2 extends the rule to its own entries |
| Sentinels | None. An unresolved id, an index out of range, a reserved bit set, or trailing bytes is a load error |
