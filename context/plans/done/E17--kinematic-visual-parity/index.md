# E17-B — Kinematic Visual Parity

> **Epic:** 17 — Kinematic Geometry and Moving Platforms.
> **Depends on:** E17-A (kinematic platform foundation) ✓. Independent of E17-C (trigger/command surface) ✓.
> **Specular scope:** movers get specular under **promoted static lights** (the static lights that cast shadows from moving entities), reusing the runtime light loop the mover already runs — of the same character static walls show (specular is a static-light term everywhere in the engine today). Dynamic-light specular is deferred to a future engine-wide spec (the diffuse-only dynamic path is incomplete, not intentional). One spec, one wave.
> **Terminology:** an **active mover** is one present and drawn this frame, including docked/idle movers — it is *not* "in motion." Idle movers keep casting shadows.

## Goal

Bring kinematic brush movers to the static world's visual contract. Movers already draw SH/dynamic-lit and already receive dynamic shadows; two gaps remain. Close them: the mover shader samples the same material slots static geometry does — normal maps, specular, and material shininess — and active movers cast into the runtime shadow pools, so a moving platform reads like the static geometry around it.

## Scope

### In scope

- **Material parity (shader).** The mover fragment shader samples the normal map, specular map, and per-material shininess from the shared material bind group it already binds, and forwards the tangent it already carries. Normal-map perturbation applies to the diffuse response under all of the mover's light sources (SH indirect, baked static-direct SH, runtime dynamic).
- **Shared material-shading WGSL.** The world shader's material leaf helpers — Blinn-Phong, normal-map decode, and TBN reconstruction — become one shared snippet appended to the **forward and mover** shaders (not the skinned-mesh shader, which is diffuse-only and has none of them), so the mover's material math is identical to the world's by construction, not a fingerprint-tested duplicate. They share by concatenation (§8): `blinn_phong` and the TBN block are argument-only, and `sample_normal` resolves the module-scope `aniso_sampler` both shaders already declare at group 1 binding 5 — the same mechanism `sh_sample.wgsl` uses. Octahedral decode stays each shader's own copy (it is not part of the material surface, and the mover already defines it).
- **Specular under promoted static lights.** Blinn-Phong specular is computed inside the mover's existing runtime light loop, gated to the **appended promoted static-light records only** (the loop's tail past the dynamic-tier count). This matches the engine's current behavior — specular is a static-light term and no surface glints under dynamic lights. Each contribution is scaled by that record's attenuation, cone, and shadow-visibility factors and inherits the promotion crossfade weight `w` (pre-folded into the record's color). The gate needs one new `dynamic_light_count` field in the mover light-params uniform, fed the renderer's dynamic-tier count; no new binding. The baked static-direct SH atlas is diffuse-only, so runtime specular adds no double-count.
- **Movers drive static-light promotion.** An active mover's world bounds join the promotion-relevance set, so an eligible static light near a mover promotes into a shadow-pool slot — the shared enabler for both the static specular above and the promoted-slot casting below. Movers share the existing 8-spot / 2-cube promoted budget with skinned meshes through the existing ranker; no new budget.
- Diffuse Post-Retro filtering stays byte-identical to today (existing parity test unchanged).
- **Shadow casting.** A generic depth-only rigid-occluder pipeline — position-only, per-instance model transform, projected by the per-render light-space matrix — with kinematic movers as its first and sole caller this wave.
- Mover occluders record into every occupied slot the entity occluders already serve: dynamic spot slots, dynamic point cube faces, promoted-spot slots, and promoted-cube faces, with `LoadOp::Load` after the world/cached depth.
- Per-slot/face CPU cone cull of movers, using the conservative world-space mover AABB (movers are not in the world BVH).
- Mover→world shadows under **dynamic** lights (world surfaces sample the dynamic pool), and mover→mesh and mover→mover shadows under **both** dynamic and promoted-static lights (meshes and movers already sample those pools). Mover-side shadow *receipt* already exists.

### Out of scope

- Specular under **dynamic lights** — deferred to a future engine-wide dynamic-specular spec. No surface in the engine has dynamic-light specular today (the dynamic light loop is diffuse-only); this is an incomplete area, not an intentional exclusion, and belongs in one pass across all surface types once its per-fragment perf cost is measured. See Open questions.
- Specular under **non-promoted static lights** (the full per-chunk static spec-light list). Deferred — see Open questions.
- **Exact** specular match to a neighboring static wall. The wall shades a static light through the baked per-chunk path; a mover shades the same light through the runtime-promoted record (its own falloff, scaled by the promotion weight `w`). Parity is same-character, not pixel-identical — see AC and Open questions.
- Mover→world shadow *receipt* under **promoted static** lights. World surfaces do not sample the promoted-static pool (their static shadow stays baked in the lightmap); that is the separate deferred `static-light-shadowmask-world-receipt` follow-on. Mover→world under dynamic lights is in scope.
- Baked lightmap / SDF occlusion cast by movers. Moving objects never enter static bakes (roadmap invariant).
- Static lightmap sampling or lightmap-UV vertex attributes on movers; those bytes stay zeroed.
- Any change to mover motion, collision, carry, or networking (E17-A owns those).
- Scripting / `world.query` / mover command surface (shipped as E17-C).
- Rotation and angular carry (E17-D), doors/blocking (E17-E), visibility-bearing movers and moving shadow-casting lights (E17-F).
- Building the rigid-occluder pipeline out for absent future consumers (rigid props, debris, chunk clusters) — the seam is *shaped* to admit them, but only movers are wired this wave.
- Any new group in the shared world/material bind-group layout, new required adapter feature, or raising `max_bind_groups` above 8. No new promotion-budget slots. (The rigid-occluder pipeline owns its own small layout — light-space uniform + instance transforms — within the device's 8-group ceiling.)

## Acceptance criteria

- [ ] A mover face with an `_n` normal-map sibling shows normal-mapped (bump) shading in its diffuse response; a mover and a static wall sharing the same material and lit by the same lights show consistent **diffuse + normal** shading at matching orientation. (Specular is a static-light term — see below.)
- [ ] A mover face with an `_s` specular sibling shows a Blinn-Phong highlight under a **promoted static light** — tighter with a shinier material (Metal), broader with a dull one (Concrete) — of the **same character** as a static wall of the same material under that light (an exact match is not expected: the mover shades the light through the runtime-promoted path with its own falloff and crossfade weight), and suppressed where that light's shadow term occludes the fragment.
- [ ] A mover shows **no** specular highlight under a dynamic light (matching every other surface in the engine).
- [ ] The mover's specular highlight fades over the de-promotion window rather than popping off in a single frame (manual QA — the fade rides the promotion crossfade weight).
- [ ] In a scene with two adjacent movers and **no** skinned mesh, an eligible static light near them promotes into a shadow slot — observable as the movers receiving specular and one casting a crisp shadow onto the other (world does not receive under a promoted static light) — where before the light would not have promoted.
- [ ] In a mixed scene where a mover and a skinned mesh both sit near bright static lights competing for promotion slots, promotion degrades gracefully via the existing ranker and existing entity-shadow tests pass unchanged.
- [ ] The existing mover diffuse Post-Retro filtering parity test still passes (no diffuse regression).
- [ ] An active mover casts a shadow onto world geometry under a dynamic spot light and under a dynamic point light.
- [ ] An active mover casts a shadow onto a skinned mesh standing beside it.
- [ ] With two movers, one casts a shadow onto the other.
- [ ] A mover casts a shadow onto a skinned mesh (and onto another mover) under a promoted static light. World surfaces do not receive it under a promoted static light — they don't sample the promoted-static pool (deferred `static-light-shadowmask-world-receipt`).
- [ ] The cast shadow tracks the mover each frame while it moves and is stable when the mover is docked/idle (a docked mover stays in the occluder set — "active" means present, not in motion).
- [ ] A mover outside a light's shadow cone/frustum is excluded from that slot's occluder draw — assertable headlessly via the GPU-free cone-cull's surviving set/count (mirroring `instance_casts_into_cone`), not the GPU-only occluder counters.
- [ ] Maps with no movers, and static maps generally, render unchanged — the forward-shader snippet extraction keeps existing render + skinned-mesh + shader-fingerprint tests green (no golden-pixel diff exists, so a subtle shading regression relies on the fixture-render manual QA).
- [ ] No new `unsafe`; no non-renderer module imports `wgpu` or creates GPU resources (grep/review gate).
- [ ] The mover material and occluder paths add no group to the shared world/material bind-group layout and do not raise `max_bind_groups` above 8, and require no new adapter feature or promotion-budget increase.

## Tasks

### Task 1: Shared material-shading WGSL snippet (behavior-preserving)

Extract the world shader's material leaf helpers into one shared WGSL snippet (e.g. `material_shading.wgsl`, added at the shader-concatenation site in `pipeline_layout.rs` where forward's source is assembled): the Blinn-Phong specular function (`forward.wgsl` `blinn_phong`) and the normal-map decode (`sample_normal`), both already standalone fns, plus a new TBN-reconstruction helper factored out of forward's `fs_main`. The TBN code today is *inline* in `fs_main` inside an `iso != 4u` guard with nested degenerate-length guards — extract only the `T`/`B`/`TBN`/`N_bump` assignment into an argument-only helper; the `iso` guard and the `sample_normal` call stay at the `fs_main` call site (lifting the guard would change forward's behavior). `blinn_phong` and the TBN helper are argument-only; `sample_normal` reads the module-scope `aniso_sampler` (group 1 binding 5) every consumer already declares — the §8 share-by-concatenation pattern (as `sh_sample.wgsl` does). Do **not** extract `sample_post_retro`: `sample_normal` calls it, but each consumer keeps its own copy (forward and the mover both already define one). Append the snippet to the forward shader in place of its inline copies (Task 4 appends it to the mover shader). Do **not** append it to `skinned_mesh.wgsl` — that shader is diffuse-only and defines none of these helpers; appending would create unresolved references and fail pipeline creation. Do **not** include the octahedral decode in the snippet — each shader keeps its own `oct_decode` (the mover already defines one; folding it in would collide). This is behavior-preserving: the shared code is byte-identical to what it replaces, so the fixture-map render and existing render tests are unchanged. Land it alone so the refactor is verified independently of the mover feature. No new bindings, no pipeline changes.

### Task 2: Generic rigid depth-occluder pipeline

Add a renderer-owned depth-only pipeline and recorder for **rigid instance occluders** in a new module (working name `rigid_occluder_depth`), shaped generically so future rigid casters — E17-F moving shadow-casters, rigid debris, the roadmap's Chunk Primitive, rigid props/viewmodels — can become callers without a fork; kinematic movers are the sole caller this wave. Do **not** reuse the skinned depth path by faking a degenerate bone on brush geometry — a position-only rigid vertex path is simpler and more general than `skinned_depth.wgsl`. Match the skinned depth pipeline's frame integration otherwise: vertex-only, no fragment stage, `Depth32Float`, `depth_compare = Less`, the same depth bias the skinned occluders use, projecting `light_space_proj × (model × position)`. Group 0 is the light-space uniform (the existing spot `shadow_vs_bind_group` or cube `cube_shadow_vs_bind_group`, per-slot/face dynamic offset); a second group binds the per-instance model-transform buffer. **Recorder input contract:** the geometry lives inside `KinematicBrushPass`, whose vertex/index/instance buffers and `movers`/`active_draws` are private — expose `pub(crate)` accessors on that pass for the shared vertex and index buffers, the per-instance model-transform buffer the beauty pass uploads, the `active_draws` map, and a **new per-mover index-range table** (start + count into the shared index buffer) recorded at `install_geometry` beside the existing per-material sub-ranges; the recorder reads them through those accessors. **Keying:** the index-range table and `active_draws` are keyed by `mover_draw_index` (the pass's existing handle), **not** by `mover_id` — the caller's AABB entries carry `mover_id`, which resolves to `mover_draw_index` via the pass's `movers` list (do not assume `active_draws` is `mover_id`-keyed). From the *caller* the recorder takes only per-frame data: the per-mover world-space AABB set (Task 3, each entry tagged with `mover_id`), the per-render light-space bind group + dynamic offset, and the cone frustum planes. **Split the cull from the draw:** a **GPU-free** cone cull (mirroring `instance_casts_into_cone` in `render-cpu`) takes the AABB set + cone planes and returns the surviving movers; the recorder then, per survivor, resolves `mover_id`→`mover_draw_index`→index range + packed `instance_index` and issues one depth draw. Because the cull is a pure function, its surviving-set/count is headless-testable — add a headless test asserting a mover outside a slot's cone is excluded (mirror `instance_casts_into_cone`'s existing test; the GPU-only `*_entity_occluders_submitted` counters have no headless harness). Keep the seam thin: no per-material batching or instancing knobs for absent consumers. The recorder assumes the caller has opened the render pass and laid down world/cached depth; it never clears and never touches the promoted-depth cache — rigid occluders draw into the live pool each active frame, like entity occluders. No third bind group, no new adapter feature.

### Task 3: Movers drive static-light promotion

Add active movers to the promotion-relevance set so an eligible static light near a mover promotes into a shadow-pool slot, even with no skinned mesh present. Today the intersection gate (`selected_static_light_has_shadow_entity` in `renderer_light_slots.rs`) tests only the skinned-mesh frame plan; a mover-only scene never promotes. **Expose the mover AABBs:** `KinematicMoverRenderCollector` (`crates/postretro/src/runtime_movers.rs`) currently computes each mover's world AABB for cell culling and discards it — have it retain and expose the per-mover world AABB (`transform × local geometry AABB`) tagged with `mover_id`. **Hand it to the renderer via a single per-frame setter** (a new `set_mover_occluder_aabbs`-style method plus a stored field, precedent `set_fog_aabbs`), called from the mover-collect site in `main.rs` before `render_frame_indirect`; the renderer stores it and **both** the promotion gate and the Task 5 shadow-cast recorder read that one field — do **not** also thread it as a call parameter. **In the gate, add a parallel mover-intersection check** rather than folding movers into the mesh `plan`: reuse the same closest-point-on-AABB / influence-radius test against the stored mover-AABB field, and keep `selected_static_light_has_shadow_entity`'s existing 3-argument signature intact — changing it would break `selected_static_entity_gate_uses_planned_instances_only` and violate AC "existing entity-shadow tests pass unchanged." `update_dynamic_light_slots` reads the new mover-AABB field directly. Movers share the fixed promoted budget (8 spot / 2 cube) with skinned meshes through the existing score ranker: a mover-adjacent static light out-ranking and evicting a farther mesh-adjacent one is correct ranker behavior, not a regression — confirm existing entity-shadow tests still pass and mixed mover+mesh contention degrades gracefully.

### Task 4: Mover material parity + gated static specular

Extend the mover fragment shader (`kinematic_brush.wgsl`) to the world material contract using resources the mover pipeline already binds (the shared material bind group, group 1) and vertex data it already carries (the packed tangent at location 3), consuming Task 1's shared material-shading snippet so the math is identical to the world path (the mover keeps its own `oct_decode`; the snippet supplies `blinn_phong` / `sample_normal` / TBN only). Declare the group-1 bindings the shader omits today — the specular texture (binding 2), the material uniform / shininess (binding 3), and the tangent-space normal map (binding 4). Forward a world-space tangent and bitangent sign through the vertex shader, reconstruct the TBN basis (shared snippet), and perturb the shading normal from the normal-map sample before both the indirect and direct lighting terms. Add a Blinn-Phong specular term inside the runtime light loop (`accumulate_dynamic_direct`), gated to the **promoted static-light records only** — the loop's tail at index `>= dynamic_light_count`. **Plumbing:** add `dynamic_light_count` to the mover light-params uniform, fed the renderer's **dynamic-tier** count (`full.light_count`) — not the total; the existing loop-bound field stays fed `full.total_light_count`, so feeding the new field the total would break the gate. Extend `write_light_params` with the new argument and update its one call site (`renderer_render_frame.rs`). The params struct grows from 4 fields to 5 (adding `dynamic_light_count`): the WGSL struct, the Rust serializer (`build_light_params_bytes`, currently 16 bytes), and the `light_params_buffer` allocation in `KinematicBrushPass::new` (currently sized 16) must all change in lockstep under uniform 16-byte alignment — the 5-field struct uploads padded to 32 bytes. Dynamic-tier records contribute diffuse only, matching every other surface. Each promoted specular contribution uses the specular map's red channel for intensity, `max(material.shininess, 1.0)` for the exponent, the camera world position for the view vector, and is scaled by that record's existing attenuation, cone, and shadow-visibility factors; the promotion weight `w` is pre-folded into the record's color, so multiplying the specular term by that color inherits the crossfade, and the diffuse-only baked static-direct SH atlas means nothing is double-counted. The camera position is already in the shared camera uniform buffer the mover binds at group 0 — declare that field in the mover's camera struct (a WGSL struct-declaration change; no Rust or bind-group change). Keep the diffuse Post-Retro sampling byte-identical — its parity test asserts `fs_main` computes the `dpdx`/`dpdy` derivatives before `sample_post_retro` and makes no bare `textureSample` call, so route the new normal and specular sampling through `sample_normal` / `sample_post_retro`, not a raw `textureSample` in `fs_main`. Beyond the shader, the Rust is: declaring the added material-group bindings, the `write_light_params` change above (new argument + call site), and the `light_params_buffer` 16→32-byte allocation bump; the material BGL and per-material bind groups already carry all slots, so no material upload-path or BGL change is needed.

### Task 5: Wire rigid occluders into the shadow record loop

Call Task 2's rigid-occluder recorder so movers cast into every slot the entity occluders already serve. The per-mover world-AABB set the recorder needs is the field Task 3 stores on the renderer (via its `set_mover_occluder_aabbs`-style setter); the shadow passes are `Renderer` methods, so they read that field directly — no new `main.rs` threading. The recorder pulls the mover vertex/index/instance-transform buffers and the per-mover index-range table from `KinematicBrushPass` through its accessors. In `renderer_shadow_passes.rs`, after the existing entity-occluder draw in each of the four occluder contexts — the dynamic spot pass (`record_spot_shadow_depth`), each dynamic cube face pass (`record_cube_shadow_depth`), the promoted-spot `LoadOp::Load` entity pass, and the promoted-cube `LoadOp::Load` entity pass — invoke the recorder with that slot/face's light-space bind group, dynamic offset, and cone planes (the same cone matrix the entity occluders cull against). Gate mover occluders on the same per-slot `slot_entity_eligible` the entity occluders use — note that for a *dynamic* light this already folds in the light's `casts_entity_shadows` flag, so a mover casts under a dynamic light only when that light is authored to cast entity shadows (a demo-authoring dependency for the dynamic-light casting ACs; see Task 6). Keep these additions to call-site wiring plus a small cull invocation; if the recording functions cannot absorb the call sites without new logic, split the file along the spot/cube seam first (behavior-preserving), then add the wiring. Movers already sample the spot and cube pools as receivers, so no receiver-side change is needed — mover→mover shadows fall out of this task. The promoted-slot casting becomes observable once Task 3 promotes mover-adjacent static lights.

## Open questions

- **Dynamic-light specular (deferred to a future engine-wide spec).** No surface in the engine has dynamic-light specular today — the dynamic light loop is diffuse-only. This is an incomplete area, not an intentional exclusion. Mover specular is therefore scoped to static (promoted) lights this wave, matching every other surface. Adding dynamic-light specular belongs in one pass across all surface types (world, mesh, mover), gated on measuring its per-fragment perf cost — its own spec. When it lands, movers get it nearly for free: they already loop the dynamic records; only the specular gate opens.
- **Exact wall-parity for static specular (deferred escalation).** Movers glint under promoted static lights of the same character as walls, but not pixel-identically (the mover uses the runtime-promoted record's falloff × `w`; the wall uses the baked per-chunk `spec_lights` loop's linear falloff) — and not at all under non-promoted static lights, where an adjacent wall does. The dominant lights promote, so the common case reads right; dim/decorative fixtures and the falloff difference are the gap. Because this wave gates specular to promoted records, mover specular is fully promotion-coupled — this escalation is the only route to promotion-decoupled static specular. Preferred escalation: **SH-dominant-direction specular** — extract a dominant light direction + intensity from the baked static-direct atlas the mover already samples, run one Blinn-Phong lobe, covering all static-baked lights decoupled from promotion, no new bindings. Grounded dependency: that atlas stores **octahedral irradiance per direction, not raw SH coefficients** (`sh_sample.wgsl`), so there is no L1 coefficient band to read — dominant-direction extraction needs a multi-tap reconstruction (weighted centroid/argmax over octahedral taps), extra cost and approximate, not a free read. Still cheaper than the per-chunk spec-light-list alternative (new static-light bindings + per-mover chunk resolution) but lower fidelity (one averaged lobe, no per-light crispness). Revisit only if the promoted-subset gap reads wrong in practice.
- **`renderer_shadow_passes.rs` split.** Whether Task 5's four call sites justify a behavior-preserving split of the 1141-line file is left to the implementer; the task instructs wiring-only additions first.
