# level-load-pipeline

Brief · resumable · Epic 25 U1 · reads: `context/lib/boot_sequence.md` §1 (Loading screen, Settling), §2, §3, §4, §6 · `context/lib/rendering_pipeline.md` §4, §12 · `context/lib/networking.md` §Admission and content parity · `context/lib/testing_guide.md` §Resource bounds · `context/plans/done/level-load-perf/` · `context/plans/drafts/E25--map-transitions/` (Goal, D1, D7, D8, U1, U3, AC 1–2) · read at a2e1f4b

## Problem
Developer-raised, from measured cost (`research.md` §2, lavapipe at a2e1f4b) and Epic 25's seam order (hub D1). Since the reveal gate, the install redraw hands off to Settling instead of rendering the first level frame or reading the spawn lightmap. It still freezes the main thread for ≈ 0.63–0.81 s on lavapipe, first load and change, on both measured maps. Cause: everything but the PRL parse runs serially in that redraw (CPU preparation, GPU resource creation, and the rebuild of level-invariant pipelines and models), because `boot_sequence.md` §2 limits the worker to the parse. Meanwhile the bar can't move, the co-op transport poll stalls, and the parse worker idles. Nor can that install run beside a live level, which the seam order needs: the renderer keeps each level resource in one slot every install replaces, and unload clears them all by installing an empty level. When done, one pipeline serves both commit orders. Its stages run off the main thread, behind the loading tree or beside a running level, and the main thread pays one short commit. A level change pays nothing a first load doesn't.

## Decisions
- **One pipeline, two commit orders** (hub D1). The loading-screen order still unloads before its load starts (`boot_sequence.md` §4). The pipeline never assumes the previous level is gone: its stages may run while a level is installed and running, and nothing they create reaches the frame path before commit. Diverges from `boot_sequence.md` §8 "multiple simultaneously resident levels", rewritten at U3 promotion.
- **Per-load renderer resources.** Renderer level resources are keyed per load, not per catalog id, so a seam into its own map can hold two copies. Releasing a level drops only its own load's resources and creates none.
- **Commit holds only main-pinned work.** The commit frame keeps resource hand-back and the script-VM and registry stages, in the `boot_sequence.md` §3 order. Sprite-collection registration stays there as a named, counted exception. Any other pipeline, texture, buffer or bind-group creation (fog targets included), `.prm` or glTF parse, sound decode or SH derivation happens there only as a counted fallback.
- **Renderer owns GPU** (`index.md` §2). The upload stage lives in the renderer crate and is the only off-main code that creates GPU objects. It touches only resources not yet published to the frame path, and its writes are submitted before the first frame that draws them presents. Diverges from the `boot_sequence.md` §2 row that puts all GPU work on the main thread. Streaming's budgeted main-thread install (`rendering_pipeline.md` §4) stays as it is for in-play streaming.
- **Staged pipeline** (research Floor B′, which the owner re-confirmed over Floor B). The parse emits ordered hand-outs as section groups decode. Prep and upload consume each as soon as its inputs exist, and the main thread commits once the bundle is complete. Diverges from `boot_sequence.md` §2 ("PRL parse only") and `plans/done/loading-screen` "phases are sequential", both rewritten at promotion.
- **One bounded engine pool.** CPU prep runs on one size-capped, engine-owned pool with boot lifetime. No async runtime; streaming keeps its own threads (`plans/done/sh-streaming--warm-set-and-io-contract.md`). It answers `plans/done/loading-screen` "no thread pool until measurement demands one"; whether today's numbers still demand it is the owner question below.
- **Metal is proof, not a gate.** Owner choice: build to the lavapipe floors (`research.md` §2.3), then report Metal. Diverges from `plans/done/level-load-perf/contract.md`, which sent GPU-dependent candidates to the Mac first, and from `index.md` §1.1 "measure, don't assume".
- **Pipelines once per renderer.** Every install-time pipeline is built once per renderer, off the main thread, starting after full init, and kept. SH compose keeps its pipeline, not its instance, like every other family. Commit and release create none; a load that needs an unfinished pipeline waits for it off the main thread.
- **Model cache.** Parsed and uploaded models, with their hit-zone and clip source, outlive the load that made them. The key covers file content and every install-time parameter that shapes the result, and a hit is indistinguishable from a fresh load. Entries are shared, not a load's own: a release frees none, and each commit frees those no resident level or uncommitted bundle references. A failed or cancelled load leaves the cache as it found it. At most two levels' sets are resident, one copy per shared model. Diverges from the §4 clear-on-unload table and `resource_management.md` "the level owns everything", rewritten at promotion.
- **Predict models, then fall back exactly.** Prep predicts the model set. A miss takes today's synchronous path at commit and is counted, so correctness never rests on a prediction.
- **Settings and scene extent, dispatch to commit.** Tiers are snapshotted at dispatch, and every stage reads the snapshot. A tier change on a Running frame never reaches the bundle, and the live Surface Depth rewrite touches only installed materials. The commit compares the extent the bundle was built at with the current one and rebuilds the extent-bound groups once, counted.
- **Failures before commit.** A parse, prep or upload failure, including late parse validation after hand-outs went out, is one load failure: reported once, every stage joins, nothing commits. In the loading-screen order a runtime load then goes to Frontend and a CLI boot load exits non-zero. Beside a running level, that level stays Running with its cache entries intact. An upload failure is an error wgpu reports synchronously on the upload thread; device loss stays out of scope. The streamed-SH init `panic!` and the streaming-session checks prep now reaches (streaming mode, a streamed level's id 49) become ordinary load failures.
- **Cancellation.** A superseding request, a queued unload request, or suspend cancels a load that has not committed. Releasing the running level beside a ready bundle cancels nothing, and the bundle then commits. A cancelling unload request enters Frontend; a backdrop arrives only through the load a return to frontend already queues. Generations never overlap, on the streaming retirement precedent (`boot_sequence.md` §4). A runtime request during a CLI boot load is still refused.
- **Loading screen on supersede.** It keeps its tree and UI clock, shows the new level's name, and restarts the bar at 0. Diverges from `boot_sequence.md` §1 "UI clock from zero each load".
- **Progress covers the whole load.** `loading.progress` stays monotone within a load, weighted across parse, prep, upload and settling, and reaches 1.0 at reveal; the parse no longer owns the Loading share alone. It stays "honest and coarse" (`plans/done/mod-loading-screen-contract.md`): every phase credits real units of its own work, and the counter stays in the level-loader or below.
- **Co-op unchanged in shape.** Parity, relevel id and join seed publish at commit (`networking.md` §Admission and content parity). The transport polls on every Loading frame.
- **Line C gains marks**, log-only, as in `plans/done/level-load-perf`.
- **Non-goals.** The seam swap, pre-commit settle and per-load level streaming state: hub U3 owns them, so streaming sessions are still created at commit. A boot pipeline (early CLI-map parse, parallel `Session::build`, parallel full init or mod-init decodes): each crosses the causal two-frame rule or the first-launch hold (`boot_sequence.md` §1). A wgpu pipeline cache: wgpu implements it for Vulkan only, not Metal, the perf target (`research.md` §8). Post-commit fatal streaming exits (Settling and in-play): a failure after registry mutation has no defined state, and U3's pre-commit settle moves those reads before commit. A multi-frame install, or moving parity publication. Relevel at host request: a failed host parse would strand clients (`research.md` §6 Q9); hub U4's speculative prefetch answers it instead. A cross-level world-texture cache: world textures are per-level content at ~80–96 MiB, so keeping them doubles resident texture memory across a change. Caching sounds or moving them to mod lifetime: each level reloads the whole `sounds/` directory, and the saving is unmeasured (no audio device here).

## Acceptance
### Automated
**Off the main thread**
- [ ] With the upload stage held at its first creation, Loading frames keep painting and the transport polls on each. Across those frames the commit row's count source reads no level pipeline, texture, buffer or bind-group creation beyond the loading tree's own UI images, and no `.prm` or glTF parse, sound decode or SH derivation runs on the main thread. Released, the load reaches bundle-ready.
- [ ] The commit creates no pipeline, bind group, texture or buffer and parses or decodes nothing, on a fixture with a baked texture, a model and a non-default fog pixel scale. The exceptions are sprite-collection registration and the counted fallbacks (a model prediction miss, an extent rebuild). Counts come from a device-wide source: wgpu's internal counters with the cargo feature that makes them count, or a chokepoint a grep gate proves every creation call uses. The same source reads nonzero across the main-thread oracle's install, so a source that counts nothing fails the row.
- [ ] The commit never waits on a stage thread or the GPU (grep gate: no blocking receive, thread join or device wait on the commit path). A Loading step whose bundle is not ready paints instead.
- [ ] The upload's last write is submitted before the first frame that draws it presents, also when a frame's surface acquire is skipped (pin P13).
- [ ] On a streamed fixture with a baked texture, texture prep starts before the parse's last section read and upload starts before the parse returns; the test holds the parse at each point, and a hold that times out fails. No stage reads the SH manifest's cluster topology before the parse installs it (pin P19). A map with no textures and a map with no SH manifest each reach reveal.
- [ ] Install-time pipelines build once, off the main thread, after full init. Commit and release create none, a second load reuses every one (SH compose's included), and a load dispatched before they finish waits off the main thread. A frontend-only boot builds them without blocking a frame. Cancelling a load mid-build neither cancels nor restarts the build (pin P5).
- [ ] Load stages start no threads beyond the engine pool, the upload thread and the existing streaming threads (grep gate). The pool is built once per boot: a second load starts no thread, and the pool never exceeds its cap.

**Per-load resources**
- [ ] Releasing a level creates no GPU object (the commit row's count source) and leaves another load's resources bound and drawable. Two loads of the same map hold separate renderer resources; releasing either leaves the other's draw unchanged.

**Beside a running level**
- [ ] A load runs to bundle-ready while another level is installed and running, both streamed-SH fixtures, with the running level's in-play drains installing and composing meanwhile. The running level draws and simulates unchanged on every frame, nothing the stages created is bound or drawn before commit, and the load starts no loading screen and moves no `loading.progress` on the running level's frames.
- [ ] With a bundle ready beside a running level, releasing the running level frees nothing the bundle holds and cancels nothing. The bundle then commits with no model miss or re-upload and its fog target and extent-bound groups intact, and its commit frees the model entries only the released level referenced. Holds when both levels are the same map (pin P30).
- [ ] Cancelling a load beside a running level: every stage joins through retirement polled on the running level's frames, never on the event-loop thread, and the running level draws and simulates every frame. The model cache keeps every entry the running level references, including those the load hit, and none of the load's own (pin P28).
- [ ] A load failing beside a running level is reported once, every stage joins, nothing commits, and the running level stays Running with its cache entries intact (pin P31).
- [ ] A mod hot reload committed on a Running frame while a load runs beside the running level: the load installs the reloaded descriptors' models, a model only the reload added logs one miss and loads correctly, and the running level keeps its models until its release (pin P26).
- [ ] A Surface Depth change and a shadow-tier change on a Running frame while a load runs beside the running level do not reach the load: its bundle matches one dispatched at the old tiers, and the live rewrite changes only the running level's materials (pin P27).

**Settings and extent**
- [ ] Tiers are read at dispatch, not when the request is queued: a tier changed on the frame a request is queued reaches its level (pin P21). A tier change on the commit frame applies after commit through the live path, and the shadow tier waits for the next level (pin P17).
- [ ] A scene-extent change between dispatch and commit, on a Loading frame or a Running frame beside the running level: the commit rebuilds the bundle's extent-bound groups and fog target once and counts it, and the first frame binds the new extent's views. Two changes on different frames rebuild once, and the running level's resize rebuilds only its own (pin P16). A resize recorded after the last Loading paint is applied by the first level frame's ordinary resize, and the commit counts none (pin P23).

**Equivalence**
- [ ] On every fixture, the staged parse's hand-outs together equal the monolithic parse's level data, and each equals that parse's final data for its sections, including sections a parse-end step rewrites (pin P25).
- [ ] On fixtures with at least one baked texture and one model, pipeline install and the main-thread oracle produce the same renderer resource summary (texture count, sizes and formats; buffer sizes; SH residency state; lightmap pool plan), entity-id order, and clip and hit-zone tables.
- [ ] Existing order guards stay green against the pipeline's commit path, not only the oracle: range rejection precedes all state mutation; light entity ids precede fog entity ids; pinned-seed trigger restart.
- [ ] Sounds register in sorted path order whatever order the pool decodes them, and the same file wins a shared key. A missing or bad sound file warns and the level loads; no sounds directory, or an empty one, loads with none.

**Failure**
- [ ] An injected error and an injected panic in each of parse, prep and upload, and a real wgpu validation error on the upload thread (a write past a buffer's end), each end the load as one failure with no registry mutation and no parity publish: Frontend at runtime, a non-zero exit at boot, and the process never aborts.
- [ ] Late parse validation rejecting after hand-outs went out, on a cross-section check and on a cluster directory naming a cell past the cell table: one load failure, every stage joins, no stage thread panics on the unvalidated hand-out, nothing commits, and no cache entry from the load remains (pin P18).
- [ ] The parse failing while prep runs, or two stages failing together, reports exactly one failure; every stage joins and nothing commits (pin P10).
- [ ] A streamed-SH init error, a disallowed streaming mode and a streamed level with no id 49 each fail the load like any other failure, Frontend at runtime, with no panic and no process exit.

**Cancellation**
- [ ] Suspend during prep, upload and the pipeline build: every stage thread joins through retirement, also on frames before the resumed renderer exists, never on the event-loop thread. Nothing commits, the resumed load starts its stages only after they join, and no pipeline from the old device reaches the resumed renderer, which builds its own once (pins P6, P22).
- [ ] A cancelled load reports nothing: its stages' errors, the cancel included, never reach the failure path. After suspend during a CLI boot load, the resumed boot load installs and the process does not exit (pin P20).
- [ ] A superseding request mid-pipeline: the old load never commits and the new one installs. Three loads requested on successive frames, each before the previous cancelled one has joined: only the last installs, the middle runs no stage, and no two loads' stages overlap (pin P4).
- [ ] A request already queued when its frame finds the bundle ready cancels the load (pin P1). A request the same frame's transport poll receives is handled on the next frame, after commit, through the ordinary unload (pin P2).
- [ ] An unload request queued behind an in-flight load cancels it, and the game enters Frontend with no backdrop unless a load was queued (pin P3). A load and a return to frontend on one tick with a backdrop declared: the load never starts, and the backdrop installs (pin P24).
- [ ] A runtime request during a CLI boot load is refused with a warning and cancels nothing, in parse, prep or upload. A runtime request during a runtime load no longer waits for it to install (pin P8).
- [ ] No stage work starts while a request only waits in the queue: none during the first-launch hold or the OS-preference wait, and in the loading-screen order none before the old level's unload (pin P12).
- [ ] A superseded load keeps its loading tree and UI clock, shows the new level's name and restarts the bar at 0; the old load's stages credit nothing to the new bar.

**Models**
- [ ] On every dev-mod map, baked first and run on demand, the prediction misses zero times; the result goes in the plan of record, since the gate does not run it. On a connected-client fixture a host-replicated placement's model misses zero times. A forced miss (a model only the registry adds) loads correctly and logs one miss.
- [ ] In the loading-screen order, a hot reload that changed a mesh block, then a load: the load predicts the new model with zero misses, and the old level kept the old model until its unload (pin P9).
- [ ] A same-content level change hits every shared model, with no re-parse or re-upload. Changed file content misses. A Surface Depth tier change between loads still hits every model whose materials the tier does not shape.
- [ ] A release frees no entry. A commit frees every entry no resident level or uncommitted bundle references and keeps the rest. A failed or cancelled load leaves the cache as it found it, and the next commit still frees what nothing references (pin P11).
- [ ] A cancelled load whose upload inserts a model after the cancel: the next load, dispatched on the frame the cancelled one joins, finds the cache as it was before that load and never commits a model it inserted (pin P29).
- [ ] Suspend clears GPU entries. A bundle ready but uncommitted at suspend never reaches the resumed renderer, and the first load after resume re-uploads every model it uses and is correct (pin P7).

**Progress, co-op, marks**
- [ ] Progress never decreases within one load. On a streamed-manifest map it moves before the parse's first section read. Sampled at each stage boundary, it rises during prep, upload and settling as well as the parse, stays below 1.0 until reveal, and is exactly 1.0 at reveal, a timed-out reveal included. A near-empty level and an empty prep set reach 1.0 (pin P15). No crate above the level-loader defines its own counter (grep gate).
- [ ] On a host level change, parity, the relevel id and the join seed are unset on every Loading frame and set on the commit frame, after the range and collision checks (pin P14).
- [ ] Line C names each new stage, the progress-membership capture, the commit-frame mark and the reveal, and still adds up.

**Gate**
- [ ] Every row above that needs a renderer runs on an adapter-present run, and the gate confirms those tests ran rather than skipped: app-crate renderer tests honor `POSTRETRO_REQUIRE_GPU` as the renderer crate's harness does, so a missing adapter fails the run.

## Path
- Shape: staged parse, prep on the pool, one upload thread in the renderer, a short commit (Floor B′). Rivals, numbers in `research.md` §2.3: Floor B (prep from delivery) has the same commit but serializes prep and upload behind the parse; Floor A (GPU creation still in the commit) leaves the GPU-device and level-invariant classes on the commit frame; a budgeted main-thread upload across Loading frames needs no cross-thread GPU seam but adds its budgeted wall time to every load and, in the seam order, spends the running level's frame budget; time-slicing the install breaks the one-frame commit (`research.md` §6 Q3).
- Per-load keying: each load builds a private resource set, commit publishes it as the active set, and release drops one set. The mesh pass resolves model handles through the active set rather than one renderer-wide table; the add-only sampler maps merge at commit. Rival: single slots swapped at commit, which leaves no way to release the running level beside a ready bundle without touching the bundle.
- First slice: split pipelines out of each compose constructor and build them once on a background thread after full init; replace the empty install in `release_level_resources` with dropping a set. Then split `load_textures` into a CPU and a GPU pass and run the GPU pass on a cloned queue off-main. That falsifies the riskiest assumption: no validation errors, and the writes land before first use.
- Split first, behavior-preserving, own commits: `startup/lifecycle.rs`, `render/mesh_pass.rs`, `level-loader/src/prl_loader.rs`, `render/renderer_types.rs`, `render/loaded_texture.rs` and `render/renderer_resources.rs` are past ~800 lines.
- Staged parse: `load_prl_from_container` decodes in a fixed order (`research.md` §8); the cluster-directory and cross-section checks at its end can reject after hand-outs. Cancellation is a cooperative flag checked between stages, never inside a positional read. rayon is already a workspace dependency.
- Off-main CPU work needs CPU-only renderer entries (no wgpu types) for SH residency derivation and texture prep, or a lower crate. Catch upload errors with an error scope on the upload thread. Fog's extent-sized target moves into the upload stage. The `per-frame-upload-batching` drift guard needs a class for off-main writes. The renderer already depends on the level-loader, so it can credit progress. wgpu's counters need its `counters` feature, which the workspace does not enable; a renderer-owned creation chokepoint may be the cheaper proof.
- Seams: `Renderer::install_level_geometry`, `install_textures`, `load_textures`, `load_model_diffuse_texture`, `release_level_resources`, the mesh pass's model tables, `mip_count_aniso_samplers`, `full.sh_compose`, `set_fog_pixel_scale`, `register_smoke_collection`, `ShResidencyState::from_manifest` and `initialize_gpu`, `UploadQueue::installation`, `install_level_payload`, `finish_level_payload`, `install_level_streaming_sessions`, `load_level_sounds`, `distinct_mesh_models`, `spawn_level_worker`, `drain_level_requests`, `begin_loading_screen`. Keep-across precedent: `spot_shadow_pool_needs_rebuild`. Retirement precedent: the SH async worker pool. Prepared products assert `Send` at compile time, like `LevelPayload`. Keep the main-thread path and the monolithic parse callable from tests as the oracle until landing (`plans/done/level-load-perf` Invariants).
- Session-verified facts and ordering pins: `research.md` §8–§9.

## Open questions
- **The engine pool.** Its warrant was "prep alone exceeds the parse", which no longer holds (`research.md` §2.2). Per-level prep is ≈ 118 / 71 ms (first load / change) against a ≈ 276 / 284 ms parse on campaign-test, and ≈ 333 / 272 against ≈ 817 / 827 on stress-warren-lit; a cold first load's descriptor-model CPU (≈ 130) still leaves it under the parse. (a) Keep one bounded pool. (b) One extra prep thread beside the parse, the pool deferred until a measurement demands it. Either way the seam order needs prep off the main thread. — owner — **blocks build**
