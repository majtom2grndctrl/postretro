## Goal

Meet the Game Accessibility Guidelines basic tier and the common FPS accessibility failures as engine mechanisms. Mods author where content must (theme variants, captions); OS accessibility settings seed defaults; menus reach native screen readers; gamepad menu navigation meets console conventions.

## Scope

### In scope

- **U1 Preferences and comfort floor** — accessibility preference substrate with OS seeding and readonly live `accessibility.*` slots, engine accessibility panel, flash limiter on the screen-effect channels, reduce motion, per-bus volume, mono audio. The source-level floor for every other primitive that can flash follows U1 (`drafts/E23--photosensitivity-source-floor`; D4).
- **U2 Visual accessibility** — theme variants, tokenized engine visuals, authored focus visuals, contrast diagnostic, text scale.
- **U3 Gamepad and input** — console menu conventions, full remapping, gamepad look options, hold/toggle.
- **U4 Screen reader** — engine accessibility snapshot projected to native assistive technology.
- **U5 Hearing and directional cues** — captions, subtitles, a damage-bearing fact the mod HUD draws, sound-direction cues.

### Out of scope

- Co-op text chat / ping system — a new capability, not an accommodation over an existing one; no chat exists to make accessible. Sibling roadmap item.
- Aim assist — owned by roadmap Epic 16 §Weapon Feel.
- Difficulty and game speed — scripts own difficulty (`scripting.md`, "engine owns the floor; scripts own the taste").
- Self-voicing TTS — door kept open behind U4's snapshot, not built.
- Reading OS flashing-lights, caption on/off, mono audio, or the Windows screen-reader flag — no safe API (`research.md` §3); in-game options only.
- Whole-UI reference-space scaling — owner chose text scale.
- Mod-declared input actions — the action set stays engine-closed.
- The focus-group defect — fixed by a pre-epic direct build; the epic builds on it (Invariant I5).

## Direction

**Problem.** The UI epic built the authoring side of accessibility (G2 metadata: names, roles, `Announce`, selected/checked) and deliberately deferred its consumption. No epic owns player-side accommodations. So the metadata has no reader, and the mechanisms only the engine can supply do not exist: OS preference seeding, a photosensitivity floor, an assistive-technology bridge, rebinding, captions, gamepad menu conventions.

**Alternatives rejected.**
- *Screen reader only* (the literal Epic 13 deferred line) — leaves every GAG basic-tier gap open.
- *Self-voicing TTS instead of native AT* — overrides the player's own screen-reader voice and rate, and duplicates what AccessKit exposes. Kept as an open door behind the same snapshot.
- *Mod-opt-in authority for preferences* — cannot guarantee photosensitivity safety; the engine floor does, at every primitive content drives (D4).
- *Frame limiter on the composited frame* (withdrawn from U1 by owner decision, 2026-09-28) — the only design that sees every source, combined sources included. U1 built it as a GPU measure-and-limit pass over 16×9 cell means. A motion test found cell means read ordinary camera motion as flashes: pans, turns and shake presented held cells as visible boxes. Fixing it needs motion compensation that no shipped limiter documents, and it cost 0.24 ms at 1080p on the Mac. The engine owns every primitive a mod can strobe with, so a source-level floor covers the realistic threat at negligible cost. A frame limiter may return as a consumer of a motion and reprojection layer (`drafts/motion-reprojection-layer`). Evidence: `E23--preferences-comfort-floor/plan.md` §Corrections, owner decision C.
- *Live `options.*` slots for accessibility fields* — blurs honoring a preference with editing it, and diverges from the menu-scoped working-copy model of `player_options.md` §4. The readonly `accessibility.*` namespace separates the two.
- *Mod menus only for accessibility settings* — a mod whose menus omit a setting strands the player, and a script-writable limiter lets content disable the floor. The engine panel, opened by an engine-owned global input, guarantees reach; its limiter action, honored only from the panel, keeps the floor out of content's reach (D11).
- *Origin-gated `setState` on a limiter working copy* — a `setState` write carries no originating tree, and the panel's boolean and enum fields still need engine-owned button actions; one reserved action family covers both.
- *Engine-appended entries in mod menus* — rewrites mod-authored layout; a global input reaches the panel without touching mod trees.
- *Engine-drawn damage indicator behind an engine option* — puts hit presentation policy in the engine; a bearing fact lets each mod's HUD decide what a hit shows.
- *Whole-UI reference-space scale* — owner chose text scale.
- *One monolithic spec* — five subsystems and several executors exceed one execution contract.
- *Independent per-unit plans with no index* — the preference model, OS seeding, and authority rules would be re-decided in every unit.

## Cross-cutting decisions

**Preference model (D2).** An `accessibility` group in `PlayerOptions`. Each OS-seedable field stores *unset* until the player changes it. Unset resolves to the OS value, else the engine default. OS change events update unset fields live. Stored values use a tolerant format: an unknown value falls back for that field alone; the file is never discarded. Resolution order is Invariant I1. Two slot surfaces expose the group:
- `accessibility.*` — engine-owned, readonly, always live. Each slot carries its field's resolved value, current during play whether or not a menu is open. Mod content reads it to honor a preference in its own content (reduce motion, captions); no script writes it (Invariant I11).
- `options.*` — the writable working copies of `player_options.md` §4: seeded when a menu opens, written by menu controls, bridged back to the store. Every accessibility field except the flash limiter has one (D11). A mod options menu that surfaces an accessibility field writes its `options.*` working copy exactly like an existing option. An engine write to the store — a panel action (D11), the OS reader's first reply, or an OS change to an unset field — reseeds the matching working copy that frame, so an open menu shows the new value and the reseed never reads back as a menu write, yet a panel write still persists (D11). A menu control's write or a panel action marks its field player-set; an OS value leaves it unset. Session build seeds every accessibility working copy once as well, so a mod menu under any tree name — not only `frontend.options`, the one tree whose push seeds today — shows resolved values.

Accessibility preferences are presentation-only and client-local: honored only where presentation runs on the affected player's machine — UI trees, screen effects, audio, captions — and never fed to simulation (Invariant I9). U1 builds the substrate and the `accessibility.*` projection; later units add their own fields to both.

**Authority (D3).** Mods present accessible variants of their theme; players enable them in options; OS settings are the default before the player chooses. High contrast with no mod variant → an engine high-contrast token set layered over the mod theme. Layering: engine default → mod base → selected variant (mod's, or the engine fallback). Applied at the single theme chokepoint and preserved across staged reload (Invariant I6).

**Photosensitivity floor (D4).** Engine flash limiter, on by default, enforced at the sources content drives rather than on the composited frame (owner decision, 2026-09-28; Alternatives rejected). The player may disable it from the engine panel (D11); mods cannot. The limiter reads its enable flag fail-safe: an absent, non-boolean, or `true` flag leaves it on; only an explicit `false` turns it off. It advances its history on presented-frame time, never UI time, which pauses with game logic (`ui.md` §3) while frames keep presenting. Its rules: ≤ 3 flashes in any 1 s window, a flash being a pair of opposing transitions (WCAG 2.3.1); saturated-red transitions (R/(R+G+B) ≥ 0.8) desaturated over budget; intensity change capped as a rate per second. Windows and rates run on presented-frame time, not frame count, so a strobe limits the same at 30 Hz and 240 Hz, and a hitch never turns the intensity cap into one step. An over-budget flash is suppressed at its onset, so a limited strobe rests at its pre-flash level, never at its peak. Enabling the limiter starts its history that frame; no earlier transition counts. A window resize never resets the flash budget.
- *Channel clamp* (U1): `screen.flash` and `screen.vignette` values are limited as they pack into the resolve's effect uniform. It is CPU-only and costs no GPU time.
- *Source floor* (follow-up, `drafts/E23--photosensitivity-source-floor`): the same rules at every other primitive content can strobe with, such as light animation, scripted light writes, emissives, UI color and visibility, sprite flipbooks, camera cuts and level-load loops, plus a preference that disables engine-owned flash effects. Until it lands, those sources reach the screen unlimited.

Placement: every limit applies to the value a primitive presents, on the presenting machine, never to a slot a script reads (I9). A source clamp cannot see how much of the screen its source covers, so it assumes the worst: a strobe faster than 3 Hz whose change reaches the threshold is limited whatever its size. Sources that are each within limits can still strobe together; the follow-up weighs whether a shared budget earns its cost. The dev-tools egui overlay stays outside the floor, the carve-out Invariant I2 names.

**Settings reach (D11).** An engine-owned accessibility panel is the floor: a `core/ui/` descriptor opened by the reserved UI action `ui.openAccessibility`. Its registry name is reserved and cannot be shadowed: a mod- or level-scope registration under it is rejected with a load-time diagnostic and the engine panel remains (Prior commitments, `ui.md` §1.1). Every field in the `accessibility` group appears in the panel; each unit adds its fields there as it adds them to the substrate, and U1 adds any group field that landed before the panel existed. Mods may surface the fields other than the limiter in their own menus through their `options.*` working copies (D2). The panel resolves theme tokens, so it follows the mod's look. Panel reach is Invariant I10.
- *Write path.* Every panel control writes through a closed family of reserved `ui.*` actions that toggle, cycle, or step a named accessibility field (names and shape pinned by U1 brief). Buttons fire them. Numeric group fields (screen-shake scale, view-feel scale, text scale, caption background opacity; bus volumes and gamepad look sensitivity and dead zone if their briefs place them in the group) use an engine-routed slider: the App intercepts each step of a `Slider` in an engine-tier tree bound to a readonly `accessibility.*` slot, at the buttons' interception point, and routes it to that field's step action, keeping gamepad left/right and hold-repeat. Only engine-tier trees get this routing; a mod slider bound to a readonly slot still warns and no-ops. The App intercepts the family before named-reaction dispatch, as it does `ui.exitToDesktop`, and writes `PlayerOptions` directly; the panel shows each field from its `accessibility.*` slot. A panel write persists through the same settled save as a menu write (mechanism pinned by U1 brief). No panel control depends on a mod-registered reaction, so the panel works under a mod that registers none. A family action fired from a mod tree writes its field as the panel's control does — except the limiter's.
- *Limiter.* The flash limiter has no script-writable working copy: no `options.flashLimiter` slot exists, and `accessibility.flashLimiter` is readonly. The App honors the limiter action only from a control of the engine panel while the panel is the active tree, and ignores it with a warning otherwise; the modal stack's top at activation cannot attribute the press, so attribution is pinned by U1 brief (`research.md` §Brief pins). That check is the mechanism behind D4's "mods cannot"; the verdicts are in the table below.
- *Global input.* An engine-owned input opens the panel from any menu, a text-entry modal included, or from gameplay: `nav.options` (gamepad Select/Back), plus a keyboard default (F1; pinned by U1 brief). No tree claims it: a focused slider whose `capturesNav` names `nav.options` neither steps nor swallows it. U3's raw-capture prompt is the one exception: while a capture is armed, the prompt receives the global input's key or button as the input to bind. Pressed while the panel is the active tree, it closes the panel; pressed while the panel is open beneath another tree, it does nothing; pressed on a splash or Loading frame, which draw no UI, it does nothing, then or later. While the panel is the active tree, `nav.cancel` and a close button firing `ui.closeDialog` also close it: over the frontend, during gameplay, and at the first-launch hold. Any UI input pressed on a splash or Loading frame is dropped, never delivered later, so a buffered gamepad cancel cannot close the first-launch panel on its first frame. Routing is pinned by U1 brief (`research.md` §Brief pins). U1 ships the defaults. U3 makes them remappable. Its guard lets a remap move the input but never leave it unbound, and never bind its keyboard entry to a key text entry consumes (a printable key, Backspace, Enter, Escape): the global input reads ahead of text entry, so that key could no longer be typed.
- *Menu entries.* The engine fallback frontend and pause menus carry an entry to the panel; a mod menu reaches it through `ui.openAccessibility`. When a mod- or level-scope tree registers as the frontend menu or `pauseMenu` without a `ui.openAccessibility` button, a load-time warning names that tree. Each tree is checked on its own; a tree that carries the button draws no warning.
- *First launch.* With no stored record that the panel was shown, boot shows the panel once mod init completes and the splash clears, before any frontend backdrop, CLI boot-map, or host-named level load starts (`research.md` §2, first launch). A `--connect` client stays connected through the hold, admitted but not participating (`networking.md`). A map its host names during the hold, or during the splash's wait for the OS reader on any launch, is the level the client loads when the hold ends or the splash clears; the frontend backdrop never displaces it. Mechanism pinned by U1 brief (`research.md` §Brief pins). No level runs and no sound plays until the player closes it; boot then presents the frontend or loads the boot map as on any launch. Opening first is not enough: a capturing modal pauses neither simulation nor audio (`ui.md` §4). The record is written when the player closes the panel by any close path, so a launch that quits or crashes with the panel open shows it again. Later launches boot normally. When the settings file cannot be replaced (unreadable, or not valid TOML), the record cannot be written, so the panel shows on each launch until it can; that is the fail-safe. The hold diverges from `boot_sequence.md` §1 (Prior commitments).

Limiter write verdicts (AC 7):

| Input | Verdict |
|---|---|
| Limiter action from a control of the engine panel (engine tier, reserved name) while the panel is the active tree | Toggles the limiter |
| Limiter action from a panel control after the active tree changed earlier in the frame | Ignored; warns |
| Limiter action from a control of any other tree — mod- or level-tier, or an engine tree other than the panel — including a tree popped earlier in the same frame that leaves the panel on top | Ignored; warns |
| `setState` on `accessibility.flashLimiter` | Readonly: warns, no-op |
| A reaction, manifest data, or any other slot | No path to the setting |

### U1 — Preferences and comfort floor

**Purpose.** The substrate every other unit writes into, plus the comfort mechanisms that need no UI rework.

**Contents.**
- `accessibility` group in `PlayerOptions`; readonly, always-live `accessibility.*` slots carrying resolved values; menu-scoped `options.*` working copies; unset/OS/default resolution (Cross-cutting: preference model).
- Tolerant per-field storage for every `PlayerOptions` field, not only the group: U1 replaces `PlayerOptions::load_with_status`'s whole-document `toml::from_str` and rewrites the test `an_out_of_vocabulary_surface_depth_state_falls_back_to_defaults`, which asserts the whole-document fallback, to assert that the bad field alone falls back (Invariant I7).
- OS reader: `mundy` for contrast (seeds U2's `highContrast` variant) and reduced motion (seeds reduce motion); OS color scheme seeds no field and is not read. Windows `TextScaleFactor` (seeds U2's text scale) through a new Windows-only direct `windows` dependency (0.62, already in the lock through `wgpu-hal`, `cpal`, and `gilrs-core`; `UI_ViewManagement` feature). The reader sits behind an app-side seam a test replaces with a fake (AC 1). U1 exposes the contrast and text-scale readings on that seam; U2 binds them to its fields. Change events update unset fields live. The reader starts at session build. The splash clears only after it reports initial values or a bounded wait (pinned by U1 brief) expires; a reply after that applies as a live change.
- Flash limiter channel clamp on `screen.flash` and `screen.vignette`, CPU-only, plus a GPU timing pair for the resolve (AC 6; the pair is pinned by the U1 brief) (Cross-cutting: photosensitivity floor). The frame limiter was withdrawn on 2026-09-28 (D4).
- Engine accessibility panel and `ui.openAccessibility` (Cross-cutting: settings reach): the `core/ui/` descriptor; its reserved non-shadowable registry name; the reserved field-action family its controls fire, with the limiter action honored only from the panel; engine-routed sliders for its numeric fields; a name and role on every control (AC 32); `nav.cancel` and close-button close paths; the `nav.options` global input and its keyboard default; the missing-entry warning; entries in the fallback frontend and pause menus; and the first-launch boot hold, `--connect` deferral included.
