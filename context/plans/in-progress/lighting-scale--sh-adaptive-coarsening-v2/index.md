# SH Adaptive Coarsening — production activation (v2, storage/bandwidth)

## Goal

Turn on the landed-but-inert composed-error SH delta coarsening for shipped bakes, with the author controls and validation that make it safe to default on. The mechanism (per-4×4×4-brick L0/L1/L2 levels in delta sections id 27/41/45, classified from composed-receiver error, reconstructed in the compose shaders) already exists and is exercised only behind the default-off `--sh-coarsen` flag. This spec productionizes it: a shipped default, a mapper-authored protection volume, a reconciled fail-loud cap (no silent retry), an independent per-map uniform-grid opt-out (an author disable, not a cap recourse), and a measured net-runtime-savings gate on an arena-warren fixture. It realizes the **storage/bandwidth** half of the adaptive-SH-density line; variable base-probe *density* (the bake-time win) is a separate deferred spec (Direction).

## Scope

### In scope

- **Production activation** of SH delta coarsening: a shipped default (currently `--sh-coarsen` defaults off, `main.rs`), and a per-map uniform-grid opt-out that bakes L0-everywhere loudly rather than silently.
- **Mapper-authored protection**: an FGD brush entity whose world-AABB forces intersecting bricks to L0, augmenting the `--sh-protect-aabb` measurement stand-in for production use (the two AABB sources are **unioned**, not swapped). The map-side `sh_protect_aabbs` carrier is unioned with the CLI source via `combined_protect_aabbs` into the classifier's `protect_aabbs` parameter that `classify_section_levels` consumes (it delegates to `classify_levels`).
- **Cap reconciliation**: settle the production delta-payload cap against the committed two-tier posture (64 MiB bake knob / 128 MiB WebGPU loader floor) vs. the current 256 MiB default (`DEFAULT_MAX_PAYLOAD_BYTES`, `delta_sections.rs`); add loader-side binding-floor re-validation with a fail-loud reject (absent today). The cap fails loud with no silent retry; the per-map uniform-grid opt-out is a separate, independent author disable (above), not a recourse for a cap overage.
- **Operating-point settling**: the coarsening gate thresholds (`CoarsenParams`: `rel_p95_max` 0.10, `rel_max_max` 0.25, `darkness_frac` 0.02, currently hardcoded) settled as the justified `CoarsenParams::default()` production operating point, tunable only via a bake-time parameter override (dev-tools/xtask), never a live runtime or user-facing setting (per `experimental_spikes.md`).
- **Validation gate + findings**: measured before→after per-frame delta traffic, resident bytes, and compose dispatch time on an arena-warren fixture, with per-brick error and seam metrics inside precommitted limits, and the composed-atlas output invariant held. Feeds promote/no-promote.

### Out of scope (non-goals)

- **Variable base-probe density / the bake-time win.** Skipping dense probe bakes in coarsenable regions. **Foreclosed here in source by a validation rule:** `OctahedralShProbe.density_level` (`sh_volume.rs`) is **rejected-nonzero on parse** — `from_bytes` returns an error (`density_level … is reserved for adaptive density; v9 requires 0`) for any nonzero value, so no bake can emit and no runtime can load a variable-density base grid today. Context for why nothing produces the case: the base bake allocates and emits the full uniform grid (`sh_bake.rs` `probe_grid_layout` sizes `probe_positions`/`validity`/atlas to `dims.x*dims.y*dims.z`; `bake_sh_volume` bakes all probes in one flat par-iter) and the runtime reads a regular lattice. Delivering the win requires a base-grid format change plus a renderer-side variable-density sampler — a separate foundational spec on a one-way door. This spec touches none of that surface, and its delta `cell_levels` are orthogonal to base-grid `density_level`.
- **Any wire-format section change or version bump.** Warranted: ids 27/41/45 already carry `cell_levels` + `valid_probe_mask` + kept-rank payloads at their shipped versions (5/3/3 — confirmed in source: `DELTA_SH_VOLUMES_VERSION`, `DIRECT_SH_DELTA_VOLUMES_VERSION`, `ANIMATED_DIRECT_SH_DELTA_VOLUMES_VERSION`), the encoder already emits coarsened payloads under `--sh-coarsen`, and all three compose shaders already reconstruct L0/L1/L2 — so activating coarsening writes bytes the current versions encode and the current runtime decodes. Verified: agent grounding of `delta_sh_volumes.rs`, `direct_sh_delta_volumes.rs`, `animated_direct_sh_delta_volumes.rs`, `sh_reconstruct.rs`, and `direct_sh_compose.wgsl`/`sh_compose.wgsl`/`animated_direct_sh_compose.wgsl`.
- **The indirect vs. direct classifier math, the three-level scheme, the f16/f32 Pascal contract.** Landed and inherited unchanged.
- **Adaptive packing of base atlases id 34/35.** Their pressure is a 2D-dimension limit, not the storage-buffer wall; consumed as-is (composed-atlas output invariant I1).

## Direction

**Problem.** The SH delta payload scales ~n^2.4–2.95 in probe density; at the 1.0 m shipping default the direct compose alone streams up to ~2.4 GiB/frame (~81% of a GTX 1060's bus), and per the read-equivalence, stored payload equals per-frame compose traffic restricted to active lights. The coarsening that removes most of it is **built but inert** — `--sh-coarsen` defaults off, so every shipped bake writes uniform L0 and pays the full cost. The cause is not a missing mechanism; it is that the mechanism ships disabled and lacks the author controls (protection, fallback) and the validation to turn on safely.

**Prior commitments.** The coarsening mechanism itself landed via `context/plans/done/lighting-scale--delta-sh-probe-coarsening` — the composed-error classifier, three-level scheme, delta `cell_levels`, compose reconstruction, and the `sh_protect_volume` protection entity all ship today, gated off. That spec's owner ruling: acceptance is correctness, not a shrink percentage; magnitude is not gated. This spec re-opens one runtime question that ruling left open — the net-runtime win after the L1 reconstruction cost, on the default-on path — as a *sign* gate (is it safe to default on?), not a magnitude threshold. This realizes the storage half of the measurement-first v2 the superseded `lighting-scale--adaptive-sh-probe-density` and archived `adaptive-base-probe-density` plans anticipated, and inherits their retained material by reference: the Measured basis, read-equivalence, three-level-vs-two-vs-tree rescope, drop-as-co-primary analysis, f16-storage/f32-arithmetic Pascal contract (no WGSL `enable f16`), two-tier cap posture, and industry survey. It honors the archived plan's binding corrections: classify from **composed receiver error** (landed in `classify_levels`, not surface distance), measure seams as **actual shared-face reconstruction differences** (`sh_analyze` `SeamStats`), attribute compaction / exact-zero drop / density coarsening **separately** (`SectionBytes`), require a **per-map uniform-grid fallback** (never silent coarsen-to-cap), and add a **mapper-authored protection** mechanism (protected bricks always L0). `AFFINITY_FACTOR = 4` is locked (compose workgroup-coupled). Pre-release no-compat-shim posture (`development_guide.md` §1.6): a bump, if ever needed, rejects stale sections — but this spec needs none. **Divergence:** the current cap default is 256 MiB, not the committed 64/128 two-tier; this spec reconciles that rather than inheriting it silently.

**Alternatives rejected.** *Keep coarsening as a CLI opt-in* (`--sh-coarsen` stays a power-user flag): rejected — the uniform default cost is the whole problem, and an opt-in nobody flips ships that problem to every map. *Content-authored opt-in* (default off; the mapper sets `_sh_coarsen "1"` on the open/arena maps where the coarsenability spike concentrates the win): a real rival, not defeated by the opt-in-nobody-flips argument — a content KVP travels with the map and open-map authors have direct reason to set it. Rejected on the merits: default-on with a content opt-*out* dominates it — same per-map control, but the safe default becomes the win rather than the cost, and the uniform cost shipping to every lit map is the problem the spec exists to fix. A wrong default is bounded by the fail-loud cap, mapper protection, within-limits error, and the opt-out escape hatch; a forgotten opt-in silently ships the full cost. *Couple in the bake-time win* (variable base-probe density in the same spec): rejected — it is a foundational base-grid + renderer change on a one-way door with unproven forward-predictor efficacy; coupling it to this near-done storage win lets a stall on the unproven half hold the proven half hostage. It is the deferred sibling spec, and this spec preserves the composed-atlas output invariant so that later work meets the same seam.

**Placement.** Build-time compiler (`level-compiler` emits coarsened sections) + format (`level-format` wire, unchanged) + a thin mapper-authored control (FGD → parse → the existing `protect_aabbs` sink). No renderer change — the compose already reads variable levels. The protection control belongs in the map, authored by the mapper, not in a build flag; moving it there is the archived plan's placement correction (measurement stand-in → authored entity).

**Foreclosure / reversibility.** Enabling by default changes shipped `.prl` bytes for every lit map (no longer byte-identical to uniform) and sets the default quality/size operating point. Reversible at low cost (flip the default, re-bake — pre-release, no migration owed). It forecloses nothing for the deferred base-density spec: the composed-atlas output shape is preserved (I1), so that work meets an unchanged seam.

## Acceptance criteria

- [ ] A shipped bake with no coarsening-related flags produces coarsened delta sections (non-uniform `cell_levels`) — coarsening is active by default, verifiable by a smaller-than-uniform delta payload logged at bake and a non-all-zero `cell_levels` histogram. On a fixture that legitimately gates all-L0 (high receiver variance everywhere), the histogram equalling the classifier's output — not a nonzero count — is the pass condition (N=0-coarsenable is not a failure).
- [ ] A per-map uniform-grid opt-out (`_sh_coarsen "0"`) **short-circuits classification** — the pipeline evaluates the opt-out and skips `apply_coarsen_classification` entirely (effective gate `default_on && !uniform_grid_optout`), never classify-then-flatten — so every affinity cell stays L0 and the emitted payload is byte-identical to the retained pre-activation uniform baseline (Task 1's off→ "before" capture); the bake logs one line that coarsening was disabled for the map. No silent behavior.
- [ ] A mapper-authored protection volume placed in a `.map` forces every brick intersecting its world-AABB to L0 in every present-and-grid-matched delta section (ids 27/41/45), verifiable by those bricks' `cell_levels` reading 0 while unprotected bricks coarsen. Protection (Phase C) runs **before** seam smoothing (Phase D) and wins over automatic classification; because L0 is the monotone-demote floor, smoothing cannot lift a protected brick (I2) and instead demotes its coarser face-adjacent neighbors — a one-cell L1 halo around each protected boundary (I5).
- [ ] A protected L0 brick face-adjacent to an otherwise-L2 brick yields `cell_levels` `[L0, L1]`, never `[L0, L2]` — the ≤1-level seam bound holds across the protection boundary, verified on a fixture with a protected region abutting coarsened bricks (pin P1).
- [ ] The delta-payload cap fails loud: a bake whose coarsened **aggregate** payload across ids 27/41/45 (the `delta_subblocks` f16 halves, per `enforce_payload_cap`) exceeds the production bake cap exits non-zero with a named error stating the per-section and total bytes and the cap — it never silently coarsens harder to fit. The cap is measured **after** compaction, so coarsening's savings count toward fitting.
- [ ] The loader rejects any delta section whose raw payload exceeds the WebGPU binding floor, checked on `data.len()` **before** `from_bytes` (no over-floor allocation), all-or-nothing per section: an unusable id 41 clears id 40 + id 41 together (the `entity_shadow_lights` pairing); an unusable id 27 or id 45 clears its own section and the compose degrades to the base atlas for that contribution. Verifiable by a crafted over-floor section per id. The composed-brightness shared floor is a bake-time classification input already baked into `cell_levels`; clearing a section at load degrades only that section's contribution and never recomputes another section's levels (P17).
- [ ] On the pinned arena-warren fixture (`content/dev/maps/stress-warren-showcase.map`), coarsening ON vs. the uniform baseline shows a measured reduction in the **gated** metric — per-frame direct-delta (id 41) read volume, the dominant per-frame cost (Direction) — plus resident delta bytes and compose dispatch time, each recorded with its ratio; id 27/45 traffic is measured and reported as a diagnostic, not gated. This gate is evaluated **only at a representative density** — a coarsest brick pitch ≤ 5 m (base `--sh-probe-spacing` ≈ 1.25 m, since a brick tiles at `AFFINITY_FACTOR`×base = 4×; confirm also at the 1.0 m shipping default → ~4 m; see Task 1). A degenerate sparse density such as 10 m spacing (→ ~40 m brick pitch) forces the error gate to keep id 41 all-L0 and does **not** count as an id-41 null result. If id 41 shows no reduction *at ≤5 m coarseness*, Task 5 records it and the owner decides whether to demote id 41 to a diagnostic (as id 27/45 are); the indirect delta (id 27) is the mechanism's consistent saving. Per-brick composed error stays within the relative `CoarsenParams` limits (`rel_p95_max` 0.10 / `rel_max_max` 0.25); `darkness_frac` (0.02) is a settled tuning constant, not a gated metric. The ≤1-level face-adjacency seam guarantee holds for every **participating** face-adjacent brick pair in every present section — zero-valid bricks are non-participating, labeled L0 only as a no-data sentinel, and the landed `smooth_pair` excludes them (test `p10_zero_valid_is_l0_and_non_participating`); a non-participating L0 cell adjacent to an L2 cell carries no delta and is not a seam (its reconstruction error is 0), so the emitted-PRL face-scan excludes non-participating cells. The level histogram is computed on the **post-smoothing** levels (protection halo included), and a manual-visual seam check finds no objectionable discontinuity (seam residuals reported as diagnostics, not gated on an absolute number). The invariants hold at N=0 (zero protected, zero coarsenable, zero delta sections) as well as N>0.
- [ ] The composed-atlas output **geometry/format/binding** is unchanged by activation (structural invariant I1, must hold exactly): the direct compose still emits a dense per-base-probe `Rgba16Float` D2Array at the id-35 grid dimensions, sampled downstream as `sh_direct_atlas` at group-3 binding 15 (billboard/fog/forward) and group-4 binding 15 (kinematic/skinned) via the shared `sh_atlas_sampler` at group-3 binding 2; downstream forward/billboard/fog/kinematic samplers and bind groups are untouched. Separately, the composed-atlas **values** may shift within the coarsening error tolerance: a composed-atlas golden captured before Task 2 flips the default, re-checked off→on for a fixture with no protected regions and error within limits, moving within tolerance is a recorded result, not a failure (per `experimental_spikes.md`, this replaces a baseline it is allowed to move off).

### Task 4: Cap reconciliation + loader binding-floor validation

State both quantities and scopes so the 64/128 pair is not read as clean 2× headroom on one number.

Set `DEFAULT_MAX_PAYLOAD_BYTES` (currently 256 MiB, `delta_sections.rs`) to the 64 MiB bake default and repoint the existing bake-side fail-loud check (`enforce_payload_cap`, `anyhow::ensure!` "exceeds cap"); update the unit tests that assert the 256-MiB default (`delta_section_config_defaults_to_desktop_cap`, `parse_args_sh_delta_max_size_defaults_to_256_mib`). **Note the regression surface:** `enforce_payload_cap` runs **unconditionally** (independent of coarsening), so lowering 256→64 MiB fail-louds any map whose **uncoarsened** aggregate payload sits in (64, 256] MiB. ## Open questions

- **Seam quality gate.** Resolved: no invented absolute ceiling. The mechanism's ≤1-level face-adjacency guarantee (`classify_levels` Phase D fixpoint smoothing, which runs after Phase C protection) is the structural seam bound; promote gates on that guarantee holding plus a manual-visual check, with seam residuals reported as diagnostics (and, if numeric, a relative residual consistent with the `rel_*` gate). The absolute `sh_analyze` `residual_max` is not a gate.
- **Cap value.** Resolved (owner): the committed two-tier posture — 64 MiB bake aggregate knob / 128 MiB per-section loader floor, both fail-loud (Task 4). Application decision (flag for owner veto): the 64 MiB bake cap stays **unconditional**, and the uncoarsened-aggregate-≤-cap check moves to Task 1/P5 rather than gating the cap behind `--sh-coarsen`.
- **Opt-out surface.** Resolved: worldspawn KVP `_sh_coarsen`, canonical field `uniform_grid_optout` (Boundary inventory).
- **`--sh-protect-aabb` disposition.** Resolved: keep as a measurement-only stand-in, unioned with the authored entity via `combined_protect_aabbs` (Task 3).
- **Measurement density for the id-41 gate.** Resolved (owner): evaluate the gate at a representative density with coarsest brick pitch ≤ 5 m — base `--sh-probe-spacing` ≈ 1.25 m (a brick tiles at `AFFINITY_FACTOR`×base = 4×), confirmed at the 1.0 m shipping default (~4 m). The first Task-1 slice measured at 10 m spacing (~40 m coarsest), which forced the error gate to keep sharp-gradient direct light (id 41) all-L0 and produced a false id-41 null; that density is excluded. This is a test/ship-density bound, **not** a new classifier max-spacing knob (the classifier math stays frozen; a hard spatial cap à la Unreal/Unity ~3 m was considered and left to a possible fast-follow). id 41 stays the gated metric at this density; a null *at ≤5 m* would be an owner call to demote it to a diagnostic (Task 5).
- **I5 scope (participating cells).** Resolved: the ≤1-level seam bound applies to **participating** face-adjacent bricks only. Zero-valid bricks are non-participating and labeled L0 as a no-data sentinel; the landed `smooth_pair` deliberately does not demote across them (test `p10_zero_valid_is_l0_and_non_participating`), and such a cell carries no delta (reconstruction error 0), so it cannot form a real seam. The emitted-PRL face-scan must exclude non-participating cells; the first slice's raw all-cell scan asserted an invariant the mechanism was never built to hold (a scan defect, not a mechanism defect).
