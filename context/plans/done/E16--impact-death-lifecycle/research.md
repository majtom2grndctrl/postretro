## Kill report / credit path (to re-key off despawn)
- The sweep returns a `DeathReport` (`crates/postretro/src/scripting/systems/health.rs:34-52`): `killed_tags` + index-aligned `killed_contributor_ledgers` (`ContributorLedgerSnapshot`, `:58-70`) per killed non-player, plus `player_died`/`player_contributor_ledger`. `run_death_sweep` feeds each tag set through `ProgressTracker::on_entity_killed` (`crates/scripting-core/src/reaction_dispatch.rs:59`) and appends `PLAYER_DIED_EVENT`; the caller fires the returned events via the death-event drain. Scoring/progress consume the report — they are decoupled from despawn today, which is what lets the report move to the removal pass without touching them.
- Credit freeze at the latch: `apply_damage_with_context` records contributors only while `!death_handled` (`crates/entities/src/components/health.rs:419`) — a latched corpse accumulates no later damage, so credit captured at first-0-HP cannot be stolen by corpse hits (test `apply_damage_with_context_does_not_record_after_death_latch`, `health.rs:706`).
- `registry.despawn(id)` — `crates/entities/src/registry.rs:890`, synchronous, clears columns/tags, bumps generation. Tags/ledger must be captured (or already latched) before removal — after `despawn` they are gone (sweep comment `systems/health.rs:168-169`).
- Replication prunes by despawn, not HP (`crates/postretro/src/netcode/replication.rs:246-258`); HUD reads the `player.health` slot projected from the component (`crates/postretro/src/netcode/state_slots.rs:545-561`) — both unaffected by moving the report.

## Health write-back (setHealth re-arm)
- No script health-write path exists; `applyDamage` (`crates/postretro/src/health/reactions.rs`) is damage-only. `player.health` slot is engine-owned readonly, projected *from* the component — writing the slot does not write HP.
- Storage write exists internally: `HealthComponent.current` public, written via `registry.set_component`; `refresh_from_descriptor` clamps on hot-reload (`crates/entities/src/components/health.rs:347-349`). The substrate's `setHealth` is a new absolute chokepoint mirroring `apply_damage`; this spec extends it: a finite positive stored result resets `death_handled` and discards both pending and live contributor credit. A zero stored result preserves them. `death_handled` is set only by `sweep_deaths`; clearing it on positive recovery re-arms kill detection. This is the real re-arm, distinct from the FSM-state recovery above.
