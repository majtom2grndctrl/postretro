## Corrections
- **Evaluation seam.** Path: tail of `simulate_tick_with_presentation_aim`, after `run_death_sweep` (`sim/src/sim/mod.rs:888`) → remote HITs waiting on this tick's FIRE authorization land after that function returns (`frame_loop/mod.rs:996` `host_flush_pending_hit_declarations`, then its own `host_run_remote_hit_death_sweep` at `:997`), and accumulators advance after it too (`frame_loop/mod.rs:983`). - **Crossing sentinel rule polarity.** Path: "strip the subscription as the crossing sentinel rule does" → that rule (`startup/lifecycle.rs:1105-1160`) strips an address only when *every* reaction there is sentinel-bound. The brief's rule drops an address when *any* reaction breaks a player-event rule. - **V4b is one hop.** `scoped_fire_targets`/`validate_trigger_coupled_pass_b` (`startup/reaction_validation.rs:~265-385`) inspect only `Sequence` `fire` steps, one hop, and never `onComplete`. Planning around it by adding a transitive walk over `fire` steps and `onComplete` for player-event subscriptions, cycle-safe like `event_contains_consequential` (`sim/src/trigger_bindings/partition.rs`).
- **Owned reads.** Path: "`DispatchScope` opts into `resolve_owned_input`" → `DispatchScope` (`scripting-core/src/ir/scopes.rs:149`) has no owned-input support. Only `EntityScope::resolve_owned_input` (`:515`) accepts an owner, and only `@impact.source`. - **Two derivations of weapon values.** The host HUD publisher (`sim/src/scripting_systems/ui_proxy.rs`) and owner-private replication (`netcode/src/state_slots.rs:927` chain plus `state_slots/resource_projection.rs`) compute weapon values separately. Reload is sampled per consumer (`WeaponComponent::reload_status` vs `owner_reload_status`, `entities/src/components/weapon.rs:540-548`; read-only `&self` samples over independent cursors). Planning around it by putting one raw lookup `(registry, slot, pawn, consumer) -> Option<SlotValue>` in `scripting-core`. Netcode keeps only wire shaping (`[slot, value]` correlation, `ReplicatedWireShape`, fingerprint tags). The HUD publisher and replication both call the lookup, and condition and `byPlayer` reads use the owner-projection sample (no cursor advances on read).
- **Health fallback leak.** Today `owner_private_source_value` falls through to the global scalar (the host's own value) when a pawn lacks `HealthComponent`. The lookup returns absent instead. That case is unobserved for a condition, and replication sends nothing for it.
- **Absence rule.** Today `overheated` and `reloadActive` always send `[slot, 0/1]` once an inventory exists. For the lookup, weapon slots are absent while the pawn has no active weapon (P18), and health slots are absent without `HealthComponent`. Owner-private wire encodings stay byte-identical (existing snapshot tests unchanged).

It sends only presentation, lifecycle and sentiment to the frame-end residual, and refuses a sentinel target there. So a player event's `on.player` commands and `byPlayer` reads resolve at its in-tick apply step, which runs right after the tick's snapshot evaluation. They do not wait for the frame-end drain. The residual carries only routed presentation and frame-end work, keyed by the internal target seat. Reading "drain" in ACs 34-35 as that apply step keeps their meaning. Proof uses the evaluate/apply split: a test removes the pawn between the two calls.
- **System reaction kinds.** `SystemReactionCommand` has 18 variants (`entities/src/reactions/system_commands.rs:14`), more than the brief's prose names. The classification covers all 18.
- **Parity test.** The byte-identical twin test is closet-reveal-specific (`startup/closet_reveal_surface_tests.rs:792`). The player-events example gets its own twin pair and parity test.
- **No presentation byte guard.** Nothing pins the encoded tags of `ServerPresentationPayload::{Spawn, OverlayFact}` (`net/src/wire.rs:75`). A before/after layout guard is added, following `net/src/handshake.rs:239`.

## Delegated answers
- **Inter-source drain order (P11).** Player-event residuals drain immediately after trigger residuals in the frame-end script drain (`frame_loop/mod.rs:~1357`). Their follow-ups join the same `pending_trigger_follow_ups` dispatch. Order is source-major across the frame, and tick order then authored order within each source. Reason: the frame drain is already source-major, and within every tick player events evaluate after triggers. A test that swaps the batches fails.
- **Shared engine lookup placement.** `scripting-core` (new `player_slots.rs`) returns raw `Option<SlotValue>`. Reason: every input is an `entities` component or slot record, the owned-read scopes that consume it live in `scripting-core`, and both `sim` and `netcode` depend on it, so no callback is needed.
- **P5.** The condition sees a global accumulated slot's advance **on tick N**, because evaluation follows `evaluate_slot_accumulators`.
- **P17.** A `byPlayer(on.player)` read in a fired reaction yields the value **at the fire's tick**, after that tick's snapshot evaluation and before any later fire in the same apply pass. Reason: `setState` is consequential and runs in-tick (see the `on.player` Correction), and residual steps take no owned reads.
- **Post-`wait` `byPlayer(on.player)`.** Dropped reaction-wide with V4a, as a post-`wait` `on.player` step is. The fire context does not survive a `wait` for reads either.
