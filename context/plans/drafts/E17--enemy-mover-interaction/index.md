# E17--enemy-mover-interaction

Brief · resumable · Epic 17 · reads: `context/lib/movement.md` §6 · `context/lib/entity_model.md` §7, §7c · `context/lib/build_pipeline.md` §Navigation bake · `context/lib/networking.md` §Current contract · read at 7dec6ed0

## Problem

Owner-requested capability, Epic 17: enemies treat movers as solid and as ground, as players already do. Today agent motion sweeps static geometry only and keeps a bare grounded flag, and the nav graph has no runtime notion of a mover, so enemies walk through closed doors, stand inside or fall through lifts, are never carried or pushed, and a crusher damages an enemy it merely overlaps in open air. When done, closed doors stop enemies and their routes; lifts, platforms and a room rising into place carry them; a `displace` mover pushes them clear; a mover pinning one holds or backs off exactly as for a player; `crush` damages them only when pinned or engulfed; and enemies route across a docked lift. Derivation: `research.md`.

## Decisions

- **Shared mover-contact primitives, separate controllers.** Carry, displace, release velocity and the push-blocked test become body-agnostic `postretro-physics` primitives that the player substrate and the agent controller both call, in the same order: carry → displace → combined sweep → ground ref → release. Players and enemies share geometry primitives, not controllers (`done/movement--static-overlap-invariant`); the agent keeps its own controller. Agent body motion moves from `sim` into physics, which owns movement and mover collision (`development_guide.md` §Workspace); this is the movement churn `done/gameplay-stack--ai-and-physics-crates` named as the leaf-crate risk, accepted. Body-side carry matches `movement.md` §6. The player path stays bit-identical.
- **Agent ground is a `GroundRef`.** `AgentComponent.is_grounded: bool` becomes a ground reference with an `is_grounded()` projection. It is the single source for carry, rider exemption, stuck suppression and link resolution.
- **Enemies follow the player block rules (owner, 2026-10-30).** `displace` pushes an unpinned enemy clear. A pinned living enemy makes `displace` and `stop` hold and `reverse` back off, exactly as a pinned player does; no non-crush mover damages or embeds a living enemy. `crush` damages enemies only when pinned against static geometry or another mover, or engulfed, and keeps damaging past death. A rider never stops or reverses its own mover. This supersedes `movement.md` §6 Moving bases (agents grounded against static geometry alone) and Pinned bodies ("agents are never carried or displaced"), and reverses `done/E17--rider-not-a-blocking-contact` AC8 for riders.
- **A pinned enemy steps clear (owner, 2026-11-06).** A living agent pinned by a non-crush mover drops `blocked` and steers out of that mover's course, as a player steps away, so a hold always ends and the mover docks.
- **Corpses ride, never block (owner, 2026-11-06).** A corpse is any quiescent agent: zero HP, or committed to removal by a queued despawn. It keeps gravity, carry and displacement but no steering. It never stops, reverses or holds a mover, and a pin against it is no yield. `crush` still damages it. Diverges from the player rule "dead pawns count": a dead player may be revived, a corpse waits only for the mod's despawn.
- **Crush effects run in a fixed order.** Multi-victim damage, `Crushed` events and impact callbacks are deterministic across runs. Owed here because agent pins rewrite the crush contact set whose order varies today.
- **Docked means at rest at a waypoint (owner, 2026-11-06).** A mover is docked at a waypoint while it rests there: a timed wait, a finished run, a `goToPathNode` hold, never started, or held there by a pin after a command to leave. Touching a waypoint within one tick's motion (`wait_ms` 0, a pass-through) is no dock. Camera occlusion keeps its stricter `mover_is_docked_closed`.
- **Closed doors are impassable to planning.** A mover docked at a waypoint gates the nav regions and portals it fills there; paths, reachability and replans respect the gate. The gate refuses crossings only (owner, 2026-11-06): an agent starting in a gated region plans out of it, and a goal in one is reached from its own side. Enemies detour or latch `blocked` and hold. The gate changes only on dock and undock, never on live posed bounds, so sweepers, crushers and mid-travel doors stay collision's job. A runtime side table, load-time derived: no NavMesh format change. Its footprint is nav-region overlap, not the baked door→portal association of `done/E17--doors-as-occluders`: nav regions are not BSP portals.
- **Gate changes replan first (owner, 2026-11-06).** Agents whose route a gate change affects, and every agent latched `blocked` when a gate clears, are admitted ahead of target drift within the existing replan budget.
- **Gate fidelity is measured before it is built.** Whether a doorway gets its own region or portal in the rectangular decomposition decides whether a load-time region and portal gate is enough. If a door overlaps a large region, the build stops for the owner before the gate rule. A bake-time region split changes the nav bake, not the format; only a baked portal kind bumps `NAVMESH_VERSION`.
- **Lifts are runtime links.** Load-time links from a mover's walkable top at each waypoint to adjacent regions, open only while it is docked there. Enemies board only an already docked mover, ride with steering and stuck detection suspended, and exit where it next docks at a waypoint with a link toward their goal. This covers lifts, multi-stop lifts and the rising room, kept in this brief (owner, 2026-11-06). Runtime links are the current implementation; baked portal kinds stay the direction of `build_pipeline.md` §Navigation bake.
- **Host-only.** Agents are host-simulated (`networking.md`); no wire, prediction or digest change. Gate and links are host-only state, read by nothing a client runs.
- **Non-goals.**
  - Remote presentation of riding enemies: roadmap **Co-op presentation of NPCs on moving geometry**. Until it lands a remote client draws a riding enemy off its mover by RTT/2 plus interpolation delay times mover speed (about 30–50 cm at 150 ms on a 3 m/s lift); host and listen-server views are exact.
  - Enemies opening doors or summoning lifts, and a costed wait-at-door link: roadmap **Enemy door operation**.
  - Movers blocking shots and sight: `drafts/E17--movers-block-shots-and-sight/`. The two land in either order; enemies seeing through a closed door until then is accepted.
  - Carrying agent yaw on rotating movers, `carry_yaw` included: a moving or engaged agent's facing re-derives from the AI facing slew; an idle rider or a corpse keeps its world yaw.
  - Agents using teleporters: only player pawns resolve teleporters (`entity_model.md` §7).

## Acceptance

### Automated
- [ ] A closed mover stops an agent at its skin; once open, the agent passes. A `displace` mover pushes an unpinned agent clear (O40).
- [ ] An agent grounded on a moving mover, with or without a destination, reports mover ground every tick, and its displacement equals the mover's carry within 1e-4 m across start, reverse and stop. A descender beyond ground-stick reach drops it under gravity; stepping off adds release velocity that decays with knockback drag (O2–O5, O33).
- [ ] Riders, including within the airborne grace, never stop or reverse their own mover; a non-rider agent in the sweep still triggers `stop` and `reverse` (O6).
- [ ] A non-crush mover pinning a living agent holds (`displace`, `stop`), or backs off when its reversed course pins nothing and holds when it pins a body (`reverse`), with no damage and no embedding; an agent and a player pinned on one tick get one decision (O9a–O9c).
- [ ] A `crush` mover carrying an agent through open air deals no damage; pinned against static geometry, another mover, or engulfed in one tick, the agent takes damage at the cadence past death (O7–O9).
- [ ] Multi-victim crush yields identical damage, event and callback order across runs, with at least four victims over at least eight runs (O10).
- [ ] A corpse in a `stop` or `reverse` doorway never holds or reverses the door; a corpse on a starting lift rides it; `crush` still damages a pinned corpse. A living agent with a queued despawn behaves as a corpse. An agent killed while another mover pins it holds that mover that tick; the hold releases in the next tick's blocking pass and the mover moves on the tick after (O11, O11a, O39, O47).
- [ ] With the only route closed, a chasing agent latches `blocked` and holds: position spread ≤ 0.05 m over 5 s, stuck recovery fires at most once. The door reaching its open waypoint, it passes within 2 s. Two gate flips before admission cost one replan. A failed replan whose old path crosses no gate keeps that path, as today (O12–O14, O28).
- [ ] Sixteen agents chasing through one door that docks closed each detour or latch `blocked` within ⌈16 / replan budget⌉ ticks of the flip, and none fires stuck recovery more than once after it (O29).
- [ ] On `stress-env-volumes` with every agent chasing a moving player, each agent whose route a door's dock cuts detours or latches `blocked`, and each agent latched `blocked` by it replans after it leaves, within ⌈N / replan budget⌉ ticks of the flip (O29, O43).
- [ ] A `ping_pong` lift returning onto an agent that waits `blocked` at its boarding spot docks within 2 s, and the agent then boards (O16, O42).
- [ ] An agent standing in a gated region clear of the door plans out of it, and a goal in a gated region is reached from its own side; only routes through the door are refused (O30).
- [ ] A brain whose target a door cuts off reads `targetReachable` false by its next acquisition-due tick, and true by the next one after the door leaves; Ai, combat scoring and steering read one gate generation per tick (O31, O32).
- [ ] An agent routes across a docked lift: boards, rides with steering and stuck detection paused, exits at the far terminus and replans. A lift leaving mid-board carries a grounded agent and otherwise closes the link (O15–O18).
- [ ] A rider whose lift leaves mid-exit or stops mid-shaft never walks off into the shaft and fires no stuck recovery while riding; a rider knocked off resumes steering and replans; an agent raised by a riser rides as a boarded one; no replan is admitted mid-ride (O34–O38).
- [ ] A rider whose target is reachable from the lift's next dock reads `targetReachable` true on every acquisition-due tick of the ride (O38, O48).
- [ ] An agent whose route crosses a lift docked flush with the floor walks across without stopping, and rides only if the lift leaves while it is on it (O37, O45).
- [ ] After unloading a level whose closed door gates a route and loading one that routes through the same region index, that route succeeds on the first tick (O49).
- [ ] A `ping_pong` door and a `ping_pong` lift gate and link on every tick that begins and ends inside a waypoint wait, and stop on the tick they leave (O24, O46).
- [ ] A door spawned closed and never moved gates routes from the first tick (O25).
- [ ] A closed door commanded open but held at its closed waypoint by a body in its opening course keeps its gate; the gate clears on the tick the door leaves. A `reverse` mover pinned at a middle-node dock backs off and undocks there on that tick (O26, O50).
- [ ] A `ping_pong` sweeper with `wait_ms` 0 and a door held mid-travel run a full cycle with no gate generation change and no replan admitted for them (O27).
- [ ] A mover sent by `goToPathNode` to a mid-path node and held there gates and links at that node as at a terminus: a door held closed there blocks routes, and an agent boards or exits a lift stopped there; a mover passing through the node without stopping does neither (O22, O23).
- [ ] A mover with no waypoints produces no gate and no link (O20). A level with zero movers keeps agent motion, steering and paths identical to today: a headless dump of a mover-free map with agents is byte-identical to one captured before the first slice (O21).
- [ ] Player movement and the predict/reconcile suites pass unchanged, and a recorded player run on a mover map (carry, displace, release, ground-stick) produces bit-identical positions and ground refs before and after the move to shared primitives.
- [ ] The source-text gate fails if the agent controller holds its own carry, displacement, release velocity or push-blocked test; both controllers call the shared primitives.
- [ ] `NAVMESH_VERSION` stays 2, the nav bake contract tests pass unedited, and the diff touches no wire-format or content-digest code (grep gate), unless the fidelity stop routes the owner to a bake split.
- [ ] A determinism scenario with an agent on a lift produces identical state across runs.
- [ ] The new per-tick paths (agent mover contact, gate update, link resolution) allocate nothing: `alloc_probe` in a test binary that installs the counting allocator, armed after warm-up ticks, over a window that carries and displaces an agent, flips a gate, and boards and exits a rider; a control window on the same thread with one known allocation reads exactly one.

## Path

- **First slice:** move `sim/src/agent/mod.rs::collide_and_slide` into physics and generalize `movement/mover_carry.rs` (`apply_mover_carry`, `displace_from_movers`, `apply_mover_release_velocity`, `mover_push_is_blocked_by_static`) plus `ground_ref_from_hit` behind `substrate.rs::integrate_collision`, behavior-preserving. Then thread `CombinedCollisionWorld` into `agent_steering::tick` at SteerAgents (built as player movement builds it). This falsifies the riskiest premise: steering and stuck recovery do not fight the shared substrate (door jitter, lift self-bounce, stuck loop).
- Release velocity enters `knockback_velocity`. The idle (no-destination) branch of `tick_impl` has its own `collide_and_slide` call and takes the same mover contact. Stuck detection pauses while riding. Corpses need a motion-only branch, since `tick_impl` drops quiescent agents today; physics needs its own quiescence test (`is_quiescent` is `sim`-private). `fixed_tick_queued_despawn_quiesces_brain_agent_steering` is rewritten to assert no steering only.
- Blocking pass: agent tuples carry their ground ref; `pin.rs::pawn_bodies` and `run_mover_pin_pretest` take living agents; crush uses `PinWorld::push_is_blocked` plus `point_inside_mover` on the capsule axis for engulfment; `pinned_crush_contacts` becomes ordered or is sorted; `agent_capsules` keeps corpses for crush only. Rival: a separate agent pin module, rejected because it duplicates the predicate.
- Nav gate: `sim/src/nav/gate.rs`, a reusable bitset with a generation counter. Fill set per waypoint: mover local AABB posed there, XZ overlap inflated by agent radius, band [floor + step height, floor + agent height], so a lift top at floor level fills nothing. `MoverCollider` needs a local AABB; its bound sphere is too loose for a long door. A public docked-at-waypoint predicate beside `mover_is_docked_closed`, read from phase every tick rather than from `terminus_events`, which fire only at the two ends (the terminus helpers are private; a `goToPathNode` arrival sets `completed` and clears `target_segment`). The gate updates once per tick after the mover tick and before Ai. A kept path that crosses a gated portal is dropped, since `agent_steering` keeps a path through a failed replan today. `find_path` takes the gate (callers: `agent_steering`, `ai/src/compute.rs`, `combat_positioning/scoring.rs`); a generation change marks affected agents drift-priority in `admit_replans`; `endpoints_are_topologically_connected` and `blocked_destination_now_directly_routable` consult it; `region_components` becomes a static superset.
- Links: one per mover per waypoint from upward walkable triangles posed there, joined to regions within step height and agent radius. `NavGraph` has no mutation API, so links need a construction path or a side structure `find_path` reads. An agent on a docked mover resolves its region through the link; `region_at` otherwise picks the floor under it in XZ. Board → Ride → Exit in a new `agent_steering/mover_link.rs`.
- Size: `agent_steering.rs` and `sim/mod.rs` are past ~800 lines and take threading edits only, new logic in siblings; `blocking.rs` splits along the player/agent seam first if it would pass ~1000.
- `agent/overlap_tests.rs::an_agent_ignores_a_mover_top_its_pawn_neighbour_steps_onto` asserts static-only agents and is rewritten. `the_agent_controller_holds_no_step_up_or_snap_to_floor_of_its_own` is the source-text gate for shared primitives: it moves with the controller and keeps guarding, now covering the mover-contact primitives too.
- Allocation: `tick_impl` and `agent_capsules` already allocate per tick, so the probe scopes to the new paths. The counting allocator is installed only in `postretro-sim` test builds; a probe in a physics or ai test reads zero whatever runs.
- At promotion: `movement.md` §6 Moving bases and Pinned bodies (agents carried and pinned; corpses ride, never block; dock meaning for gates); `build_pipeline.md` §Navigation bake (mover gates and links are runtime side tables today; a baked portal kind needs a `NAVMESH_VERSION` bump, so "no format break" is corrected, while baked kinds stay the direction).
