# movement--slide

## Goal

Add a speed-preserving `Sliding` movement state (Titanfall/Apex model) on the shipped state-machine seam: crouching while moving fast banks the player's horizontal momentum as a decaying boost, holds a crouched capsule, **accelerates downhill**, lets the player steer the slide, and — crucially — a slide → jump (or slide → stand) **keeps that speed**. Slide is the first state to consume the momentum-conservation policy in a gameplay-meaningful way (`movement.md` §6) and the first reuse of crouch's capsule-resize substrate helpers.

This spec ships slide **complete**, not as a flat-ground thin slice: it pulls the cross-cutting-policies D8 substrate contact-forwarding forward (slide is its first consumer, ahead of wall-run), integrates the state into co-op client-side prediction/reconciliation (slide is the first new predicted movement state added since the netcode landed), and — because the per-state intents already live in `movement/intents.rs` — carves that single file into an `intents/` submodule so slide's intent lands in its own file rather than deepening the shared one, before wall-run + vault pile onto it.

A flat-ground thin slice is not cleanly available, which is why slide ships complete rather than sliced: adding `MovementState::Sliding` compile-breaks the exhaustive (no-`_`-arm) engine↔wire conversion matches in `crates/postretro/src/netcode`, so the co-op integration is *forced*, not deferrable scope (a slice would either not compile or require a `_` arm that defeats the deliberate drift-guard design); and slope-awareness is the substance of a speed-preserving slide — a flat-only slide is a worse crouch. The coherent unit is the complete state.

Fifth in the `movement--*` series under Epic 11 (Advanced Movement). See `movement.md` §2/§4/§5/§6 and `networking.md` §"What gates, and what replicates instead".

## Scope

### In scope
- **Intents submodule tidy (Task 1, behavior-preserving):** the per-state intents already live in `movement/intents.rs` — a prior refactor extracted them (and dispatch, substrate, carry) out of `movement/mod.rs`. Split that single `intents.rs` into an `intents/` submodule (`intents/normal.rs`, `intents/dash.rs`, `intents/crouching.rs`, `intents/mod.rs`) so slide's intent lands in its own `intents/slide.rs` rather than deepening the shared file, before wall-run + vault pile on. Dispatch (`dispatch.rs`), substrate (`substrate.rs`), carry (`carry.rs`), scope, and `tick` are untouched. Regression-gated, no behavior change.
- **Substrate floor-normal forwarding (Task 2):** the cross-cutting-policies D8 seam — the substrate already computes the walkable floor normal each tick and discards it; record it on the `SubstrateResult` and carry it forward onto the component for the next tick's intent to read. No existing-state behavior change; slide is the first consumer.
- **Co-op prediction/reconciliation for `Sliding` (Task 5):** the client predicts its own pawn and reconciles against host acks (`networking.md`), and the wire mirrors each `MovementState` variant's live data explicitly. Adding `MovementState::Sliding` is compile-forced into the netcode integration (`crates/postretro/src/netcode`'s exhaustive engine↔wire conversion matches): mirror the variant (with its forwarded floor normal) on the wire, add the two exhaustive conversion arms, bump `SNAPSHOT_VERSION` and `WIRE_VERSION`, extend the hand-written variant drift-guard tests, and give a mispredicted slide the same wider correction-smoothing band dash gets. Slide tuning replicates for free on the existing descriptor `TuningPayload`.
- A `Sliding` variant on `MovementState`, carrying its live data (elapsed-time guard, the decaying boost vector, the eye-smoothing source).
- Entry from `Normal`: crouch-intent while grounded and moving at/above an authored speed gate banks current horizontal velocity (plus an `entryBoost` kick) into the slide boost and shrinks the capsule. Below the gate, the existing `Normal` → `Crouching` path fires (slide takes priority over crouch at speed).
- Per-tick slide physics on the D4 base+boost model: **slope-aware acceleration** (downhill gravity projection scaled by `slopeAssist`, read from the forwarded floor normal), a constant-linear boost decay (`slideDrag`), **direction-steer** (rotate the boost toward input at an authored `steerRate`), eye-height smoothing to the crouched eye, and the boost↔realized-velocity reconciliation `Dash` uses (no phantom wall kick).
- The momentum-conservation payoff via `KEEP_ALL` carries: slide → jump preserves horizontal speed + boost; slide → stand (crouch released, headroom clear) preserves speed (the "slide cancel"); slide off a ledge keeps speed into the air.
- A `minDurationMs` floor so a quick tap still yields a satisfying slide, composed with `slideDrag` per D9.
- Reuse of crouch's substrate helpers unchanged — `resize_capsule` (Feet anchor on grounded entry), `standup_clearance_probe`, `stand_up_resize` — and the crouched capsule dimensions from `CrouchParams` (slide requires crouch enabled).
- An optional `SlideParams` descriptor (present-then-all-required, like `dash`/`crouch`): six literal fields, dual-path JS + Luau parse/validate, `register_type` emission, type-name maps, `EXPECTED_TS`/`EXPECTED_LUAU` (+ `_WITH_DOCS`) updates, drift-test coverage, regenerated committed `.d.ts`/`.d.luau`. Materialize `slide: Option<SlideParams>` on `PlayerMovementComponent`.
- A `SLIDE_MAX_MS` seamed engine constant — a generous safety backstop bounding the state (not a dash-style gameplay clock; terrain, decay, and input are the real bounds).
- Correcting the `carry.rs` doc-comment that earmarks slide as the first `Zero`/`Scale` consumer (Decision D4).

### Out of scope (non-goals)
- **IR/expression-form slide fields.** `SlideParams` values are plain literals. Expression adoption (the `Dash`/`MovementScope` path) is E14's concern — only *computed/conditional/derived* behavior consolidates onto the command buffer (`scripting.md` §11); slide's six knobs are static tuning. Dash got IR as a dedicated adopter spec; slide does not pull it in.
- **Wall-relative carry rules + wall-normal forwarding.** `projectOntoWallPlane`/`reflect` and the forwarded *wall* normal belong to `movement--wall-run` — slide does not consume them. Building them now is speculation. (Slide forwards only the *floor* normal it actually uses.)
- **New input action.** Slide reuses the resolved `crouch_intent` bit and the derived jump edges — no `Action::Slide`, no `MovementInput` field, no input-layer changes.
- **New netcode contract.** Slide rides the existing prediction/reconciliation contract (`networking.md`) — no server rewind, no rollback, no new input/control payload. Because slide adds no `InputCommand`/Control field, no *Input/Control-channel* vocabulary changes — but adding the `WireMovementState::Sliding` variant changes a snapshot wire type's bitcode byte layout, so **both `SNAPSHOT_VERSION` and `WIRE_VERSION` bump** (Gate 1 gates on any wire-type layout change — `networking.md` §"Two-gate handshake" — exactly as every prior snapshot-record layout change, e.g. mover replay provenance and E17's `blocked` phase, bumped both). No host-side per-state code: the host stamps movement state generically (D12).
- Map-overridable slide tuning (movement physics is descriptor-owned, never FGD KVPs — `movement.md` §7).
- Per-tick script-authored slide (the surface is declarative — `movement.md` §2, §7).

## Decisions

**D1 — `Sliding` is a `Dash`/`Crouching` hybrid on the existing seam.** `MovementState::Sliding { elapsed_ms, boost, eye_current }`: `elapsed_ms` + `boost` mirror `Dash` (time guard + the D4 decaying boost); `eye_current` mirrors `Crouching` (eye-smoothing source). Dispatched in `dispatch_state_intent`, with an `outgoing_boost` arm returning the live boost; per-state data borrowed in place. The boost machinery (reconcile → decay → recombine) and the eye/resize/probe machinery are both reused — little net-new math.

**D2 — Entry banks current momentum (+ `entryBoost` kick); carry is `KEEP_ALL`.** `Normal` → `Sliding` seeds `boost = current horizontal velocity + entryBoost·slide_dir` and leaves the resulting `component.velocity` consistent (the kick is an additive bump along the slide direction). The entry blend is authored entirely in the intent (like `try_enter_dash`): `try_enter_slide` sets `component.velocity = boost` (so `base = velocity − boost = 0` at entry), and the dispatch carry is the `KEEP_ALL` no-op. `entryBoost = 0` is pure speed-preservation.

**D3 — Slide requires crouch.** Slide reuses the crouched capsule dimensions (`CrouchParams.half_height`/`eye_height`) and crouch's resize/probe helpers, per the roadmap ("depends on crouch's capsule resize"). When `slide` is present but `crouch` is absent, slide is disabled — `from_descriptor` warns once and the `Normal` → `Sliding` transition never fires (graceful, mirroring the dash bind-failure path). No separate slide capsule height field.

**D4 — Slide consumes `KEEP_ALL`, not `Zero`/`Scale`; correct the `carry.rs` comment.** `movement.md` §6 frames slide's non-trivial carry as "slide→jump keeps slide speed" — a *gameplay-meaningful* `KEEP_ALL` (dash's was a parity no-op; slide's preserves real momentum across a state change). A pure speed-preserving slide on the boost-heavy velocity model has no natural use for `Zero`/`Scale` — `Scale` acts on the base layer (`velocity − boost`), ≈0 during a slide. `carry.rs` names slide as the intended first `Zero`/`Scale` consumer in **two** places — the body doc-comment on the horizontal-carry vocabulary and the `#[allow(dead_code)]` note that spells out `movement--slide` — and **both** must be re-homed to the environment-probe states (wall-run's wall rules; a vault may `Zero` horizontal on a mantle). Record slide as the first gameplay-meaningful `KEEP_ALL` consumer. Keep the `#[allow(dead_code)]` on `Zero`/`Scale`/`Drop` — no production consumer remains after re-homing.

**D5 — Going airborne hands off to `Crouching`.** Slide is a grounded mechanic. Leaving the ground mid-slide (no jump) ends the slide with a `KEEP_ALL` transition to `Crouching` (capsule already crouched, `eye_current` handed over), preserving speed into the air. `Crouching` already owns airborne-crouch and stand-up-on-release, so slide does not duplicate that logic.

**D6 — Jump is never suppressed (slide-jump), mirroring crouch D10.** A jump edge during a slide runs the stand-up probe first: clear headroom ⇒ stand (resize to standing) and exit to `Normal` with the jump applied; blocked ⇒ apply the jump and exit to `Crouching` with the crouched capsule retained. Either path uses `KEEP_ALL`, so the launch keeps the slide's horizontal speed — the headline momentum tech. Jump overrides `minDurationMs` (D9).

**D7 — `slideDrag` is a constant linear boost decay (no Normal-friction fold), `≥ 0`.** Unlike `dashDrag`'s dual path, `slideDrag` always linearly decelerates the boost (world-units/sec²), validated non-negative (`validate_non_negative_finite`). `slideDrag = 0` is a first-class config — a frictionless ice / pure-momentum slide, the Ultrakill/Neon-White end of the flexibility band (`movement.md` §3): the boost never bleeds, so a flat frictionless slide never reaches the speed-decay exit and is bounded instead by the player (jump D6, crouch-release stand-up D9, ledge handoff D5) and, when crouch is held on flat ground, solely by the `SLIDE_MAX_MS` backstop (D9) — which is the guaranteed terminator in that config, not the drag. Slide wants its own low, designed friction distinct from `Normal`'s contextual decay, so the base layer is left un-frictioned during the slide; on a sustained downhill the slope term (D8) can outrun the drag, again the `SLIDE_MAX_MS` backstop's job (D9).

**D8 — Slope-aware via the substrate floor-normal forwarding (pulls cross-cutting-policies D8 forward).** Slide is the first consumer of the forwarded floor normal. Per the intent/substrate split (`movement.md` §4: "contact flows forward, not sideways"), the slide intent never casts — it reads last tick's floor normal carried on the component. Each tick it projects world gravity onto the floor plane (the downhill-along-slope vector, magnitude `g·sin θ`) and adds `slopeAssist ×` the HORIZONTAL component of that vector to the boost: downhill accelerates, uphill bleeds faster. Horizontal-only keeps the D4 boost-is-horizontal invariant the reconcile clamp and carry depend on (both operate on XZ); the substrate's ground-stick realizes the vertical follow (§4: intents author velocity, the substrate owns projection). Flat ground (`sin θ = 0`) and no forwarded normal (airborne / first tick) degenerate to no slope effect. `slopeAssist` is the authored knob (flexibility band — Neon White vs. Titanfall want different downhill feel).

**D9 — `minDurationMs` and `slideDrag` are complementary, not redundant.** `slideDrag` shapes the *high-speed* decay curve; `minDurationMs` fixes the *low-entry-speed* case (a tap just above `minSpeed` would otherwise hit the speed-decay exit almost immediately). Drag cannot selectively fix the tap case — slowing it lengthens every slide. They compose by `minDurationMs` gating only the **automatic** exits (the speed-decay exit and the crouch-release stand-up); **jump (D6) and ledge handoff (D5) and `SLIDE_MAX_MS` always win**. This is the "committed but jump-cancelable" Titanfall feel.

**D10 — Direction-steer rotates the boost toward input at an authored turn rate.** Unlike dash's short burst (base-only steer is fine for 200 ms), a multi-second slide must be steerable. `steerRate` is a directly authored angular rate (degrees/sec, `validate_non_negative_finite`): each tick the boost's horizontal direction rotates toward the input direction by at most `steerRate · dt` (magnitude preserved). `0` = committed (no steer). A direct rate, not a `[0,1]` fraction of a hidden engine ceiling — the flexibility band (`movement.md` §3) wants an Ultrakill-agile slide and a Titanfall-committed slide both reachable, which a hidden ceiling would cap. (Dash's `[0,1]` `steerControl` scales a physically-grounded acceleration; slide's steer rotates a direction — a genuinely different knob, so a different unit is honest.)

**D11 — Split `intents.rs` into an `intents/` submodule before slide.** A prior refactor already extracted the per-state intents, dispatch, substrate, and carry out of `movement/mod.rs` into sibling files (`movement/intents.rs`, `dispatch.rs`, `substrate.rs`, `carry.rs`); `mod.rs`'s production surface is now small (`tick`, `MovementInput`, `SubstrateResult`, `Transition`, and the like). The file now past the split smell is `intents.rs`, which holds `normal_intent`/`dash_intent`/`crouching_intent` together, and wall-run + vault are next. Carve `intents.rs` into an `intents/` submodule (`intents/mod.rs` + one file per state) first as a behavior-preserving refactor (regression-gated), so slide's intent lands in its own `intents/slide.rs` rather than deepening the shared file.

**D12 — `Sliding` replicates its variant data on the wire; both `SNAPSHOT_VERSION` and `WIRE_VERSION` bump.** The wire mirror `WireMovementState` (`crates/net/src/wire.rs`) enumerates each `MovementState` variant's live data explicitly (`Dash{elapsed_ms, boost}`, `Crouching{eye_current}`), and the engine↔wire conversions (`movement_state_enum_to_wire`/`wire_to_movement_state_enum`, `crates/postretro/src/netcode/movement_state.rs`) are **exhaustive matches with no `_` arm** — so `MovementState::Sliding` does not compile until they mirror it. The wire enum's finiteness check matches on `WireMovementState`, not `MovementState`, so it is broken only by adding the `Sliding` wire variant — a deliberate Task 5 edit, not compiler-forced by the engine variant (Task 4). Add `WireMovementState::Sliding { elapsed_ms, boost, eye_current, floor_normal }`: all three live fields must cross or every authoritative-snapshot merge silently rewinds the slide clock (`elapsed_ms` drives the D9 guards), drops the preserved momentum (`boost`), and pops the eye (`eye_current`). **`floor_normal` crosses folded into the `Sliding` variant** (not `WirePlayerMovementState`) so it is paid only while a pawn is actually sliding: the engine→wire conversion sources it from `component.last_floor_normal` and the wire→engine merge writes it back before replay, so the first replayed slide tick reads the host's floor normal rather than the newest-forward-predicted one (see D13). `SNAPSHOT_VERSION` bumps by one (the snapshot record layout changed), per `networking.md` §"Version gates" ("bumps only when a change lands on the snapshot record itself"). **`WIRE_VERSION` bumps by one as well**: adding the `WireMovementState::Sliding` variant changes a wire type's bitcode byte layout, which `networking.md` §"Two-gate handshake" pins to `WIRE_VERSION` ("bumps when any wire type's bitcode byte layout changes … reordered enum"), and Gate 1 must refuse a pre-slide peer at the transport layer rather than let it silently reject every slide snapshot. This is the established pattern — every prior snapshot wire-type layout change bumped both (mover replay provenance: `SNAPSHOT_VERSION` 11→12 *and* `WIRE_VERSION` 12→13; E17 `blocked`: `SNAPSHOT_VERSION` →13 *and* `WIRE_VERSION` →17). Only the *Input/Control-channel* vocabulary is untouched — slide adds no `InputCommand`/Control field. Slide **tuning** (`SlideParams`) needs no wire mirror: `TuningPayload` serde-serializes the whole `PlayerMovementDescriptor` as opaque bytes, so the `Serialize`/`Deserialize` derives `SlideParams` inherits by mirroring `CrouchParams` carry it to clients host-authoritatively (`networking.md`: the client predicts with the host's numbers).

**D13 — `last_floor_normal` crosses the wire so reconcile replay is exact on varying terrain.** Slide is the first state to read forwarded substrate contact (`last_floor_normal`, Task 2). The reconcile path (`reconcile.rs`) restores the wire subset onto a cloned component, then replays the unacked command tail through `replay` (`netcode/prediction.rs`); a field not in the wire subset keeps the cloned registry value — i.e. the newest forward-predicted tick's value, temporally *ahead* of the authoritative baseline replay starts from. `last_floor_normal` is neither replayed-from-command nor otherwise restored, so without D12's `floor_normal` on the wire the first replayed slide tick computes a slope-accel term (D8) the host never did. On flat or uniform-slope ground the normal is constant across the replay window and there is no divergence; it diverges only on curved/faceted descents — precisely slide's showcase terrain — and can push replay past the harness position gate. Crossing it (D12) makes replay exact there. The cost is bounded to slide ticks because `floor_normal` rides the `Sliding` variant, not every pawn's snapshot.

**D14 — A mispredicted slide gets the dash-tier correction-smoothing band.** Correction classification (`classify_correction`, `netcode/prediction.rs`) gives a dash tick (`included_dash`) a wider smoothed offset than the ordinary cap because a dash burst legitimately produces a big visible delta; above the teleport threshold a correction hard-snaps. Slide preserves *more* speed over a *longer* window, so a mispredicted slide correction is at least as large and would otherwise fall under the ordinary cap and rubber-band (or snap). Extend the classification so a tick whose state is `Sliding` also earns the wider (dash-tier) band — keyed on `matches!(state, MovementState::Sliding{..})`, mirroring how `included_dash` is set (`dash_requested || matches!(state, Dash{..})`; slide has no request edge, so the state match alone). This is presentation-only — gameplay always snaps to authority; it only shapes the visible correction. Scope it to the production classification path (`classify_correction` + `PredictedTick.included_dash`/`unacked_window_included_dash`, consumed in `reconcile.rs`); the `sim/predict_reconcile.rs` harness keys its `replay_included_dash` off an input bit slide does not have, so it does not observe slide.

## Acceptance criteria

### Automated (test-gated)
- [ ] **Split is behavior-preserving:** after `intents.rs` is carved into the `intents/` submodule, the full existing movement + dash + crouch regression suite passes unchanged.
- [ ] **Substrate forwarding is additive:** with the floor-normal now recorded on `SubstrateResult` and forwarded to the component, all existing-state regression tests pass unchanged (no `Normal`/`Dash`/`Crouching` behavior delta); a test asserts the forwarded normal matches the walkable contact on a grounded tick and is `None` when airborne (the field is `Option<Vec3>`, so airborne is `None`, not a zero sentinel).
- [ ] Entry banks speed (+ kick): with `slide` + `crouch` present, grounded, moving at horizontal speed ≥ `slide.minSpeed`, the `crouch_intent` bit enters `Sliding` — collision `half_height` is the crouched value, the capsule's lowest point is unchanged (feet planted), and entry horizontal speed equals pre-entry speed + `entryBoost` (no cap applied).
- [ ] Entry gate: crouch-intent while grounded and moving BELOW `slide.minSpeed` enters `Crouching`, not `Sliding`.
- [ ] Slope acceleration (D8): on a NEW sloped-floor fixture (a walkable tilted plane, `n.y ∈ (cos_walkable, 1)`), a downhill slide with `slopeAssist > 0` gains more horizontal speed than the SAME slope with `slopeAssist = 0` — assert the *delta*, isolating the slope term from the substrate's ground-stick re-projection; an uphill slide bleeds faster than flat; flat ground adds no slope term.
- [ ] Boost decays (`slideDrag > 0`): on flat ground, total horizontal speed bleeds at the constant linear `slideDrag` rate and the slide exits when it reaches the crouch tier.
- [ ] Frictionless slide (`slideDrag = 0`, D7): on flat ground with `crouch_intent` held, a slide with `slideDrag = 0` does NOT speed-decay (horizontal speed holds), so the automatic speed-decay exit never fires — it persists to `SLIDE_MAX_MS` (the backstop forces exit) rather than ending early. (Pins the permit side of the `≥ 0` validator against the reject side below.)
- [ ] Direction-steer (D10): with `steerRate > 0`, sustained input perpendicular to the slide rotates the velocity toward the input direction at up to `steerRate · dt` per tick (magnitude preserved, relative to the post-reconcile/post-decay boost); with `steerRate = 0` the slide direction is committed (input does not rotate it).
- [ ] Min-duration floor (D9): with `minDurationMs > 0`, a slide entered just above `minSpeed` (or with crouch released immediately) persists at least `minDurationMs` (for `minDurationMs ≤ SLIDE_MAX_MS`; per D9 the `SLIDE_MAX_MS` backstop overrides the floor, so a `minDurationMs` authored above the backstop yields a slide bounded by `SLIDE_MAX_MS`, not by the floor — `minDurationMs` has no upper-bound validator) — the speed-decay and crouch-release exits are suppressed within the floor; a jump within the floor still exits immediately (D6).
- [ ] Natural exit: after the floor, when total horizontal speed decays to ≤ `ground.speed.crouch`, the slide ends — to `Crouching` if `crouch_intent` is still held, else via the stand-up probe to `Normal` (clear) or `Crouching` (blocked).
- [ ] Slide-jump preserves speed (D6): a jump during a slide launches the arc and exits with horizontal speed preserved — to `Normal` when headroom is clear (resize to standing), to `Crouching` when blocked. The jump is never swallowed.
- [ ] Slide-cancel preserves speed (D2/D6): releasing `crouch_intent` after the floor with clear headroom exits to `Normal` keeping horizontal speed; blocked headroom exits to `Crouching`.
- [ ] Ledge handoff (D5): leaving the ground mid-slide (no jump) transitions to `Crouching` with horizontal speed preserved into the air.
- [ ] Time guard: on the sloped-floor fixture, a sustained downhill steep enough that the slope term outruns `slideDrag` cannot persist past `SLIDE_MAX_MS` (the backstop forces exit).
- [ ] Wall reconciliation: a slide driven head-on into a wall projects velocity along the contact (substrate) with no phantom backward kick on the following tick.
- [ ] Slide requires crouch (D3): a descriptor with `slide` present + `crouch` absent materializes `component.slide == None` (asserted on state, like the dash bind-failure precedent `from_descriptor_disables_dash_when_expression_fails_to_bind`, which checks state not logs), so the `Normal` → `Sliding` transition never fires. (The one-time `log::warn` is an implementation note, not asserted.)
- [ ] Absent `slide` disables slide: crouch-intent at any speed enters `Crouching` (or nothing if crouch also absent).
- [ ] Present `slide` requires all six fields: an absent inner field is rejected in BOTH JS and Luau (present-then-all-required, like `dash`/`crouch`).
- [ ] Descriptor parsers reject invalid `slide` fields symmetrically in JS and Luau (each path names the offending field; wording/granularity differ per path as `dash`/`crouch` do): `minSpeed` rejects missing/non-finite/non-positive (zero rejected); `slideDrag`, `slopeAssist`, `entryBoost`, `minDurationMs`, and `steerRate` reject missing/non-finite/negative (zero allowed).
- [ ] The SDK type-drift test (`committed_sdk_types_match_current_registry`) passes with `SlideParams` present in `sdk/types/postretro.d.ts` and `.d.luau`, and `slide?` on `PlayerMovementDescriptor`.
- [ ] Neither `carry.rs` comment site (the horizontal-carry body doc-comment and the `#[allow(dead_code)]` note) names slide as the first `Zero`/`Scale` consumer — both re-homed to the environment-probe states; slide is recorded as the first gameplay-meaningful `KEEP_ALL` consumer. (Source-inspection check, not a unit test.)
- [ ] **Wire round-trips the `Sliding` variant (D12):** the three enum-carried fields (`elapsed_ms`, `boost`, `eye_current`) survive the engine-enum round-trip unchanged, asserted in the variant round-trip drift-guard tests (`movement_state_variants_round_trip` in `wire.rs`, `movement_state_variants_round_trip_through_wire` in `movement_state.rs`) and covered by the finiteness guard (`movement_state_finiteness_covers_every_variant`). Because `MovementState::Sliding` carries no floor normal and the enum conversions have no component, `floor_normal` is covered separately: `movement_state_variants_round_trip` (`wire.rs`, bitcode round-trip of the wire variant) exercises the wire variant's `floor_normal` field on both the `Some` and `None` arms, and a non-`None` `component.last_floor_normal` on a `Sliding`-state component survives the full component round-trip (`movement_state_to_wire` → `merge_wire_into_movement_state_checked`), asserted by extending `component_to_wire_round_trips_mutable_subset` (`movement_state.rs`) with a `Sliding` case — the state must be `Sliding` for the field to cross, since it rides only that wire variant.
- [ ] **Version gates (D12):** `SNAPSHOT_VERSION` is bumped by exactly one AND `WIRE_VERSION` is bumped by exactly one (the `Sliding` wire variant changes a wire type's bitcode layout). (Source-inspection check; the version-mismatch reject tests for both constants continue to pass against the new values.)
- [ ] **A mispredicted slide reconciles under the harness threshold (D12/D13):** in the deterministic predict/reconcile harness, a client that predicts a slide across a sloped fixture and receives a matching authoritative snapshot reconciles with position error within the harness gate — covering both cases: a slide ALREADY in progress at the authoritative baseline reproduces because `boost` and `floor_normal` cross the wire on the `Sliding` variant and are restored before replay (this is the case D13's wire fix exists for — the first replayed slide tick reads the host's `floor_normal`, not the newest-forward-predicted one); a slide entered WITHIN the replay window has no `Sliding` baseline on the wire, so `floor_normal` is not restored — instead `try_enter_slide` re-runs on the entry command and re-derives its boost-seed from the reconciled velocity, and the first `sliding_intent` after it reads the `last_floor_normal` that the entry tick's OWN substrate recomputes from the reconciled position.
- [ ] **Slide earns the wider correction band (D14):** a predicted `Sliding` tick sets the wide (dash-tier) correction-band flag at the flag-setting seam (`predict_tick` / `unacked_window_included_dash`), so a mispredicted slide takes the dash-tier smoothed offset rather than the ordinary cap. The flag→band mapping is pinned by the existing dash case in `classify_correction_uses_pinned_thresholds` (`classify_correction` is state-blind — it sees the flag, not the state); the slide-specific assertion is at the seam that sets the flag on a `Sliding` tick (or, if the parallel-slide-flag option is taken, `classify_correction` distinguishes the case directly and the pinned-thresholds test covers it).

### Manual-visual (no automated verification — eyeball in-engine)
- [ ] Sprint → crouch reads as a smooth slide that carries speed; the camera dips to the crouched eye; speed visibly bleeds on flat and builds downhill.
- [ ] Slide → jump chains continuously, launching with the slide's speed (no dead frame, no reset); the slide can be steered around a corner.

## Tasks

### Task 1: Carve `movement/intents.rs` into an `intents/` submodule

## Rough sketch

`Sliding` is a `Dash`/`Crouching` hybrid behind the same seam — boost machinery from `dash_intent`, eye/resize/probe from `crouching_intent` + the substrate helpers.

Entry (`try_enter_slide`, from `normal_intent`'s crouch branch before `Normal` → `Crouching`):
```
// Proposed design
if input.crouch_intent && component.is_grounded {
    if let (Some(slide), Some(crouch)) = (component.slide, component.crouch) {
        let horiz = Vec2::new(component.velocity.x, component.velocity.z);
        if horiz.length() >= slide.min_speed {
            let dir = horiz.normalize_or_zero();
            let boost = Vec3::new(component.velocity.x, 0.0, component.velocity.z)
                      + Vec3::new(dir.x, 0.0, dir.y) * slide.entry_boost;
            component.velocity.x = boost.x; component.velocity.z = boost.z;
            let eye_current = component.capsule.eye_height; // standing eye, smooths down
            let delta = resize_capsule(component, crouch.half_height, crouch.eye_height, ResizeAnchor::Feet);
            position.y += delta;
            component.capsule.eye_height = eye_current; // restore: eye smooths, capsule snaps
            return Some(Transition { next: Sliding { elapsed_ms: 0.0, boost, eye_current }, carry: KEEP_ALL });
        }
    }
}
// else: existing Normal -> Crouching path
```

`sliding_intent` per tick: gravity → boost reconcile (dash clamp) → slope accel (from `last_floor_normal`) → direction-steer (rotate boost) → linear `slide_drag` decay → recombine → eye smooth → `elapsed_ms += dt*1000` → exit checks (jump/ledge always; auto/release gated by `min_duration_ms`; `SLIDE_MAX_MS` always). Total velocity = (`velocity − boost`) base + boost; slope feeds the boost, drag bleeds it, steer rotates it.

**Slope term (D8):** with `n = last_floor_normal`, the downhill-along-plane gravity is `a = gravity_vec − (gravity_vec·n) n` (points downhill, magnitude `g·sin θ`); add `slope_assist ·` the horizontal (XZ) component of `a` `· dt` to the (horizontal) boost — keeping the boost horizontal so the reconcile/carry machinery holds; the substrate's ground-stick keeps the slide on the floor. The exact magnitude coefficient is feel-tuned.

**Interaction to document at promotion (not a bug): airborne speed cap.** `Normal`'s airborne branch caps horizontal speed to the run tier *only when movement input is given* and `air.bunny_hop` is off. A slide-jump / ledge handoff above the run cap keeps that speed in the air only while the player gives no air input, or when `air.bunny_hop` is enabled; steering in air without bunny-hop re-caps. Existing `Normal` behavior, surfaced because slide is the first state that routinely hands off above the run cap — capture in `movement.md` at promotion.

## Open questions
- **`SLIDE_MAX_MS` value (feel, not architectural).** The generous safety backstop (seconds, not dash's 200 ms) bounding a sustained-downhill slide and — with `slideDrag = 0` and crouch held on flat ground (D7) — the sole automatic terminator. Pick the value in-engine so it never cuts a legitimate descent or a deliberate frictionless glide.
- **Slope-term magnitude coefficient (feel, not architectural).** The exact scaling of the horizontal downhill-gravity term (beyond `slopeAssist`) is tuned in-engine; the *form* — horizontal projection, boost-fed (D8) — is fixed.
