## Handoff

Problem: The first-person viewmodel never moves relative to the camera. `viewmodel_camera_space_transform` (main.rs) composes only `WeaponPlacementDescriptor` with the same view-feel offsets the camera gets, and `collect_viewmodel` (mesh_render.rs) draws it rigid. So nothing on screen shows weapon state, look, firing or landing — it reads as Doom II. The most visible case is switching: no shipped weapon authors `lowerMs`/`raiseMs` (both default 0), so a switch is a same-tick model swap. Even authored durations would be invisible, because the transform never reads `WieldableState::Lowering`/`Raising`.
Outcome: A render-side viewmodel motion layer with four channels — lower/raise (weapon switch, and vault while it blocks fire), look lag, fire kick, landing kick — tuned per weapon through a reusable profile, scaled by view-feel scale and reduced motion. Every weapon gets lower/raise with no art or authoring, and can opt into the other channels with no art. Switching takes a visible non-zero time by default.

Verified facts: (by symbol)

Both parser twins deserialize the whole weapon with serde (`weapon_descriptor_from_js`, `weapon_descriptor_from_lua`), so a serde default fn covers both. The host-resolved value reaches clients through `WieldableTuningPayload` (combat-model carried_loadout.rs), whose `weapon_descriptor()` is a struct literal.
  - Switch flow: `run_local_weapon_command_inner` (sim weapon_stage/commands/local.rs). BeginLower targets the active weapon. On `machine.lowered`, `finish_lowering`, `begin_raising(incoming)` and `active_slot = target` happen in one tick, and the incoming cooldown is clamped to >= raise_ms. (Raising, BeginLower) restarts the full lower. A third-slot press only retargets `switch_target`. Pressing the origin slot is rejected. With lower_ms 0 everything finishes in the select tick. A raise with raise_ms 0 has total 0 for one tick.

Decisions (owner-ruled 2026-10-14 unless noted):
  - Scope: one viewmodel motion layer, four channels — lower/raise, look lag, fire kick, landing kick. A separate weapon bob is deferred (the weapon already follows camera bob).
  - Composition: viewmodel = camera-follow view feel (as today, pose eye drop included, pose pitch/roll excluded) ∘ placement ∘ motion-layer offsets. The layer never feeds the fire origin, muzzle terms, aim, the camera or the third-person mount. With all channels at rest the transform is bit-equal to today's.
  - Per-weapon motion profile, set up like placement: a pure reusable builder, a weapon-level field, a mod-wide manifest default, and an engine fallback, so a value is defined once in script and reused. It must not be named `viewFeel`, which is reserved by player-descriptor-composition.
  - (owner-ruled 2026-10-21) Name: weapon field `viewmodelMotion`, builder `defineViewmodelMotion`, manifest key `defaultViewmodelMotion`. It names what it moves, and avoids the reserved `viewFeel`, the SDK's UI `motion`, and the `motion` movement namespace `movement--vault-entry-feel` plans.
  - (owner-ruled 2026-10-21) Shape: five optional groups. `lowered` is a placement-relative delta in placement's own vocabulary (`positionFromCenter`, `rotation`), used by both the switch and the vault lower. `vault` holds the vault-lower `easeIn`/`easeOut` shares. `lookLag`, `fireKick` and `landingKick` hold their channel's tuning; the brief drafts their fields. Unknown keys reject, as `viewFeel.pose` does.
  - (owner-ruled 2026-10-21) Resolution: placement's tier order (instance > weapon > character > mod default > engine), with character and instance as reserved parameters as placement has them. Unlike placement, each group resolves on its own, so a weapon that sets only `fireKick` keeps the mod's `lowered`. The `vault` group's fallback below the mod default is the halved pose shares (see the vault lower timing decision).
  - (owner-ruled 2026-10-21, replaces "host-resolved into the tuning payload with an epoch bump") The profile stays local to match view feel. It is presentation only, so it follows the view-feel and sound-key precedent: stripped from tuning and resolved from the client's own content, with no `TUNING_PAYLOAD_EPOCH` bump. Only `lowerMs`/`raiseMs`, which gate fire, stay host values (they already ride the payload). A client whose content differs sees its own motion, as it does its own view feel.
  - `lowerMs`/`raiseMs` get a non-zero engine default. An explicit 0 still means instant. Update the SDK .d.ts/.d.luau, the goldens and primitives/mod.rs docs. Gated on the host switch-timing prerequisite.
  - (owner-ruled 2026-10-21) Defaults split by what each channel does. Lower/raise shows a fire lockout, the retro lineage has it, and the non-zero duration default makes that lockout exist in every mod, so the engine fallback `lowered` pose is non-zero. Look lag, fire kick and landing kick are modern feel, which the product uses sparingly, and view feel is opt-in. Their engine fallback is 0, and the dev content's `defaultViewmodelMotion` turns them on subtly, as player.ts does for bob.
  - (owner-ruled 2026-10-21) Durations: 150/200 ms, final values from playtest. Fast switching is core to the genre, so a switch stays well under Doom's (see Not verified).
  - (owner-ruled 2026-10-21) Docs: no art guidance. The lowered pose is procedural and placement-relative, so it asks nothing of an artist. The primitive-surface contract needs SDK types and docs in the same change: document `viewmodelMotion`, its default, and the `lowerMs`/`raiseMs` default in docs/scripting-reference.md §`components.weapon`. Placement is undocumented there too; documenting it alongside is in bounds. Note the overlap with the stale `scripting-reference-weapon-docs` draft, which owns the weapon-docs backfill.
  - Scaling: every channel follows the presented view-feel scale and reduced motion, and integrators keep advancing at 0. Accepted consequence: with reduced motion on, a switch has a lockout with no visual cue.
  - Lowered weight: render-side, 0..1, presented with frame alpha. It never steps: a restart mid-raise continues from the current weight; a refusal or a snap to Idle releases from the last presented weight; overlapping sources take the max.
  - (review fix, follows "never steps") Switch mechanics. A lower that starts with weight w0 left (a restart mid-raise) rises from w0, `w0 + (1 − w0) × smoothstep(lower progress)`, never rejoining from 0. A switch release (refusal, snap to Idle) runs over the now-active weapon's resolved `raiseMs`, at least `MIN_RELEASE_S` (0.1 s).
  - (follows the landed pose rule) Lowered values: the outgoing and incoming weapons can have different lowered poses. A release fades the values last presented, and overlapping sources blend their value sets by weight, as `vault_row::present` does. At the repoint the raise starts from the outgoing weapon's lowered values and crossfades to the incoming weapon's over raise progress, so the model swap at full weight never steps the pose; the weight blend alone would average the two on the first frame.
  - Vault: the weapon lowers while `vault_blocks_fire` holds. `allowFire: true` never lowers. This runs whether or not `viewFeel.pose.vault` is authored.
  - (owner-ruled 2026-10-21) Vault lower timing follows the vault's presented progress, the same smoothstep envelope as the pose row. The motion profile gives authors their own vault-lower `easeIn`/`easeOut` shares, separate from the camera pose. When the profile sets none, the weapon takes half of the vault row's shares: it is fully lowered by `easeIn` / 2 of the climb, so the gun is away before the camera pose reaches full swing, and it raises over the last `easeOut` / 2, back up as the pawn reaches the top. Each weapon ramp lasts at least `MIN_RELEASE_S` of climb time, capped at half the climb, so an authored or halved share of 0 neither snaps the weapon down nor leaves it down to the end. The gate (`vault_blocks_fire`) opens on the tick the path ends, or the tick before (pawn_gate.rs), and presented progress trails by (1 − alpha) of a tick, so the weapon is up within a tick of fire returning. Resolution: weapon profile > mod default profile > half the local `viewFeel.pose.vault` row's shares > half of `VaultPoseRow::DEFAULT_EASE_IN`/`DEFAULT_EASE_OUT` (0.075 / 0.1) when no vault row is authored. Instance and character tiers are reserved above the weapon, as for every group. The shared helper's join, rewind and release rules apply, so a reconcile mid-vault never steps the weapon.
  - (replaces the pre-landing refactor) Refactor: move the timing half of `vault_row::advance` (join ramp, rewind, release from the last weight with its value snapshot, hold, max on overlap), `present`'s weight-blended values and `eye_drop`'s early blend into one shared presented-weight helper in view_feel/. The pose vault row (no behavior change; the ledge-focus reference and `focus_deg` stay in vault_row), the switch lower and the vault lower all use it; the switch lower adds the seeded restart and repoint crossfade above. Sequence with `movement--vault-entry-feel` Phase 2, which touches the same overlap: whichever lands second rebases onto the other. The landed code already returns weights before values, so the cut is along an existing seam. No draft amendment is needed: `movement--state-view-pose` is done, and `view_feel::pose::tests` pins the vault row through the move.
  - Look lag is driven by player look, never by mover carry. Standing on a turntable produces no lag.
  - Fire kick reads the local pawn's `"activate"` emissions, once per predicted shot, and never on reconcile replay.
  - Landing kick reads movement edges, the same as camera impulses.
  - Fix the stale "no weapon entity" comments.
  - Authored lower/raise clips are a follow-up. The layer keeps the lowered weight and the lowering/raising phase readable for it.
Non-goals:
  - Authored clips and viewmodel clip sampling.
  - A separate weapon bob.
  - Third-person or observer motion.
  - A raise on spawn, pickup or drop (those stay instant).
  - Switch rule changes: no reverse or cancel, no proportional restart.
  - Host switch timing (`coop--host-switch-timing`).
  - HUD equip-state slots.
  - Camera recoil or aim change.
Proof:
  Automated:
    - Weight function: Idle 0, Lowering 0→1, Raising 1→0. Durations of 0 give no NaN and no flicker frame.
    - Continuity: a switch mid-raise continues from the current weight, with no dip. The repoint between weapons with different lowered poses never steps. A third-slot retarget leaves the trajectory unchanged. A refusal releases with no step.
    - The presented weight is monotonic within a lower at 30/60/240 Hz and with frame_dt 0.
    - `view_feel::pose::tests` pass unchanged after the helper extraction.
    - A refusal mid-raise between weapons with different lowered poses releases with no step, over the active weapon's `raiseMs` (at least 0.1 s).
    - The layer reads the profile from local descriptors by archetype: a connected client whose tuning-built weapon carries no profile still shows its local `viewmodelMotion`.
    - A vault with `allowFire` false lowers, and with it true does not. Entry and exit tick edges. Works with no `viewFeel.pose.vault` row (half the engine shares). With a row and no profile shares the weapon is fully down at `easeIn` / 2 and starts up at 1 − `easeOut` / 2; profile shares override both. Shares of 0 (authored or halved) still ramp over at least 0.1 s, and the weapon is up within a tick of the gate opening. A vault row's eye drop and the weapon lower compose without a step.
    - Look lag is zero on a turntable with no input, and present with input.
    - Fire kick fires once per local shot. Another pawn's shot and a reconcile replay produce no kick.
    - A landing edge kicks.
    - All channels at rest give a transform bit-equal to today's `viewmodel_world_transform`. The fire origin and `client_fire_muzzle_terms` are unchanged under any channel.
    - Scale and reduced motion pin both sides: 0 gives none, 1 gives full, and the integrator resumes from its live state.
    - JS/Luau parser twins handle `viewmodelMotion`, `defineViewmodelMotion` and `defaultViewmodelMotion` (accept, unknown-key reject, range reject). Per-group resolution: weapon > mod default > engine for each group, and a weapon setting one group keeps the mod default's others.
    - With no `viewmodelMotion` anywhere, a switch lowers to the engine `lowered` pose and look lag and both kicks are exactly zero.
    - The tuning payload carries no profile and the epoch is unchanged; a connected client resolves its own profile.
    - The `lowerMs`/`raiseMs` default applies when omitted, and an explicit 0 still means instant. Fix the tests that assumed a same-tick switch.
    - Connected-client harness: a predicted switch shows the lower. The archetype-fallback window gives weight 0.
