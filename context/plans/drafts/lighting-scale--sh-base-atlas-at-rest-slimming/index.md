# Lighting Scale — SH Base Atlas At-Rest Slimming

> **Status:** draft. Certain-win storage work — no measurement gate, no visual-risk mechanism. Prerequisite of the gated sibling `lighting-scale--adaptive-base-probe-density` (drafts/), which populates the density-level field this spec reserves.
> **Track:** Lighting / build pipeline — at-rest cost of the base octahedral SH volume (PRL id 34).
> **Related:** `context/lib/build_pipeline.md` §PRL section IDs (id 34/35 entries) · `context/lib/rendering_pipeline.md` §4 "Indirect", §7.1 step 5 · `context/plans/done/sh-array-atlas/` (layer-aware atlas, landed) · `context/plans/drafts/lighting-scale--adaptive-base-probe-density/` (the follow-on this spec's format field serves).

## Why this is its own spec, not phase 1 of the adaptive-density spec

`/orchestrate` consumes one spec per run: one feature branch, one integration, one preflight + review gate. The adaptive-density work is behind a measurement spike it may not clear, and it rewrites the sampler contract across five pipelines; this spec is unconditional, touches no sampler, and ships a certain win (disk, load time, base-atlas VRAM) regardless of how that spike lands. Binding them would hold this work hostage to the sibling's gate: a mid-run no-go leaves one branch half-implemented and one review panel judging a mixture. Split as two orchestrate runs, coupled through three surfaces this spec pins: the reserved per-probe density-level field (I5, Wire format), the one-`u32`-per-probe indirection word (I3), and the compact x-fastest payload ordering (Wire format). Only the first and third are on-disk contracts; the word is built at load and never serialized (I3), so the sibling may redefine its encoding — including claiming its unassigned high bits — as a renderer change with no format consequence. What the reservation buys is **not** avoiding a second version bump: the sibling bumps id 34 regardless, because v9 parse-rejects a nonzero level. It buys that the bump changes validation semantics only, with zero layout churn, because the level byte already sits in the metadata record's existing padding — which is what averts an unplanned third bump from a mis-shaped record. Cost of the split: a second review gate. Accepted.

## Goal

The base octahedral SH irradiance volume (`OctahedralShVolume`, PRL id 34) stores a full 288 B `Rgba16Float` octahedral tile for **every** probe of a uniform grid spanning the whole world AABB (`probe_grid_layout`, `crates/level-compiler/src/sh_bake.rs:148-194`), including probes inside solid geometry and in exterior space — on `campaign-test` at the 1.0 m default, 57,128 of 194,028 probes are valid (29.4%), yet the section is 57,436,908 B (~296 B/probe, 52.1% of the map's SH bytes; recorded sweep, Measured basis). It is also the only SH atlas with no at-rest format tag: it always serializes and uploads dense `Rgba16Float` (`upload_atlas_texture`, `crates/renderer/src/render/sh_volume.rs:951-1002`), while the sibling direct atlas (id 35) already ships BC6H behind an `irradiance_format` tag. This spec makes the at-rest payload valid-probes-only and BC6H by default, moves per-probe validity out of the atlas alpha channel (BC6H is RGB-only) onto the metadata that already carries it, and reserves a per-probe density-level field — always zero here — for the adaptive-density sibling. **This spec does not reduce per-pixel sampler bandwidth or composed-atlas VRAM: the runtime composed total atlas stays dense per-probe `Rgba16Float`, and every sampler shader is untouched. The wins are disk size, load time, and base-atlas VRAM only.**

## Measured basis

Recorded owner sweep, `campaign-test` at `--sh-probe-spacing 1.0 --lightmap-density 0.8 --soft-shadow-samples 64` (2026-08; not re-run this session — the closest in-repo corroboration is `context/plans/done/incremental-bake-per-element/research.md:179`, which records id 34 at 57,436,896 B / 194,028 probes from an earlier configuration; the 12 B delta is trailing descriptor/slot-table variation between bakes, not a discrepancy in the per-probe identity):

| Quantity | Value |
|---|---|
| Grid probes (world-AABB grid) | 194,028 |
| Valid probes | 57,128 (29.4% — 70.6% solid/exterior) |
| id 34 section bytes | 57,436,908 B (~296 B/probe = 288 B tile + 8 B metadata) |
| id 41 / 35 / 27 / 45 bytes | 34,857,290 / 6,990,796 / 5,451,890 / 5,451,890 B (4 selected lights) |
| Dense tile payload | 194,028 × 288 B = 55.88 MB |
| Valid-only tile payload (same density) | 57,128 × 288 B = 16.45 MB (3.4×) |
| Valid-only + BC6H (8× on tiles) | ~2.1 MB tiles + 1.55 MB dense metadata (projection) |

Per-probe identity: tile = `tile_dimension² × 4 × 2 B` = 6² × 8 = 288 B; metadata record = 8 B (`OCTAHEDRAL_PROBE_STRIDE`, `crates/level-format/src/sh_volume.rs:40`).

## Scope

### In scope

- **id 34 version 9 format:** atlas payload carries tiles for valid probes only, in x-fastest probe order; an at-rest format tag (BC6H default / uncompressed debug) mirroring id 35's `irradiance_format` discipline; a per-probe density-level field, zero in every v9 bake, validated as zero at parse; version bump with the existing named reject.
- **Compiler emission:** compact-atlas packing, BC6H encode mirroring the direct-atlas encoder, honoring the existing `--uncompressed-irradiance` debug bypass; one-line footprint summary at `log::info`.
- **Runtime consumption:** verbatim BC6H upload of the compacted base atlas; a per-probe indirection-word storage buffer (compact tile slot, or an invalid sentinel) built at load; the indirect SH compose pass reads the base through a non-filtering sampler and the indirection word, and writes validity into the composed atlas alpha — so **no sampler shader changes** (warrant in Rough sketch).
- **Dev-tools continuity:** probe-marker irradiance colors served by the existing live GPU readback of the composed dense atlas (no CPU BC6H decode anywhere); once-per-load footprint log.
- **Findings note:** before → after disk / load-time / base-atlas VRAM with ratios, plus the explicit unchanged-bandwidth statement.

### Out of scope (non-goals)

- **Any sampler-side change.** `sh_sample.wgsl`, `forward.wgsl`, `fog_volume.wgsl`, `billboard.wgsl`, `skinned_mesh.wgsl`, `kinematic_brush.wgsl` are not edited; the composed total atlas keeps its dense per-probe layout (Invariant I1).
- **Composed-atlas or per-frame bandwidth reduction.** The compose output shape is unchanged; per-pixel sampler traffic is identical. The adaptive-density sibling owns that goal.
- **Non-uniform probe density / classification.** The level field is reserved and zero. No classifier, no thresholds, no density knobs here.
- **id 35 changes.** Already BC6H behind a tag; its dense per-probe tile layout is load-bearing for direct sampling when no composed direct atlas exists (`crates/renderer/src/render/sh_volume.rs:592` binds the base direct atlas straight into the sampler slot).
- **Delta sections (id 27/41/45).** Their payloads are keyed to the base grid's cell decomposition, which this spec does not touch — grid origin, dims, and spacing are byte-identical to v8 bakes.
- **Probe metadata compaction.** The per-probe metadata records (validity, depth moments) stay dense over the full grid: the depth-moment 3D texture packer consumes them dense (`pack_probe_depth_moments`, `crates/renderer/src/render/sh_volume.rs:913-927`), and at 8 B/probe (1.55 MB on campaign-test) they are not the burden.

## Direction

**Problem.** id 34's at-rest cost is dense storage over a world-AABB grid: 70.6% of stored tiles belong to probes the runtime weights to zero, and the remainder is stored uncompressed while every peer atlas in the engine (lightmap id 22, direct SH id 35) is BC6H at rest.

**Prior commitments.**
- Pre-release no-backward-compatibility: version bump, named reject, no shim (`context/lib/development_guide.md:171`, §1.6).
- BC6H-at-rest is the established engine pattern with a complete in-tree precedent to mirror: `encode_direct_section_bc6h` (`crates/level-compiler/src/direct_sh_bake.rs:876-925`) handles the 4-alignment padding (tile dimension 6 is not block-aligned), the `--uncompressed-irradiance` debug bypass, and drops alpha at encode ("RGB feeds the encoder, A drops", `crates/level-compiler/src/direct_sh_bake.rs:898-899`) — which is precisely why validity cannot stay in alpha. The compose-side BC6H read precedent also exists: the direct compose samples its BC6H base at texel centers through a non-filtering sampler because Metal rejects `textureLoad` on compressed formats (`crates/renderer/src/shaders/direct_sh_compose.wgsl:143-149`).
- **Do not cite `context/lib/rendering_pipeline.md:95` as evidence for this change** — that paragraph describes the *lightmap* irradiance atlas (id 22), not the octahedral SH volume. The id-35 precedent above is the correct one.
- The indirect compose dispatches every world-rendering frame (`crates/renderer/src/render/renderer_shadow_passes.rs:1020-1027`), so the base-atlas read this spec re-routes is per-frame hot-path code; the added cost is one indirection-word load and a sampler fetch replacing a `textureLoad`.

**Alternatives rejected.**
- *Load-time re-expansion to a dense atlas* (store valid-only on disk, expand before upload): forfeits the base-atlas VRAM win entirely, and forecloses BC6H — the encoder is a bake-side cost (`crates/level-compiler/src/bc6h.rs`); there is no load-time encode path and building one would violate the near-instant-boot northstar.
- *Validity as a second small texture* instead of packing it into the indirection word: spends a sampled-texture binding and a second fetch in the compose where one storage word already must exist for the slot remap. One `u32` per probe carries both (sentinel = invalid).
- *An on-disk probe→slot remap table:* unnecessary — the compact slot is derivable at load as the probe's rank among valid probes, because the compact payload preserves x-fastest probe order and the per-probe validity bytes are already in the section (`OctahedralShProbe.validity`, `crates/level-format/src/sh_volume.rs:47-54`). A prefix-sum over bytes the loader already holds beats a redundant table that could disagree with them.
- *Keeping `Rgba16Float` and shipping only the valid-only compaction:* leaves the 8× BC6H factor on the table for no risk saved — the BC6H quality question is already settled by id 22 and id 35 shipping it as production default on the same class of irradiance data.

## Acceptance criteria

Split per `context/lib/experimental_spikes.md`: honesty gates vs measured findings. Measured findings are before → after pairs with ratios — never thresholds to iterate toward.

**Honesty gates:**

- [ ] A v9 section round-trips: serialize → parse reproduces grid geometry, per-probe metadata, level field, format tag, and compact payload exactly (uncompressed path bit-exact; BC6H path byte-exact on the encoded blob).
- [ ] Parse rejects, each with a distinct named error: a non-9 version (existing "recompile" message shape); an unknown format tag; a nonzero density level; a compact payload whose length does not match the tag's identity for the valid-probe count; a validity/metadata count that disagrees with grid dimensions.
- [ ] A `--uncompressed-irradiance` compile of `content/dev/maps/gate-heavily-lit.map` is deterministic across two `--no-cache` runs (byte-identical `.prl`). The BC6H default path is exempt from byte-identity (lossy encode — same exemption the lightmap stage carries) but must be stable in section length across runs.
- [ ] `campaign-test` compiled at defaults boots to first rendered frame with no wgpu validation errors; indirect lighting renders on world geometry, entities, and fog (visual: no black world, no missing-probe falloff regression at former invalid-probe locations — invalid probes contributed zero weight before and must contribute zero weight after).
- [ ] Loading a pre-v9 `.prl` rejects with the named version-mismatch error and degrades to the no-SH path cleanly. No compat shim.
- [ ] Dense-geometry identity: for the same map, the v9 section's `atlas_dimensions`, `atlas_tiles_per_row`, `tiles_per_layer`, and `layer_count` are byte-identical to the v8 bake's values (compact geometry rides only the new fields). This is the gate against the failure the sampler-diff check cannot see: compact geometry leaking into the shared sampler uniform corrupts every SH fetch with no shader or BGL diff.
- [ ] No sampler WGSL file and no sampler bind-group layout changes in the diff (negative-existence: verified by review/grep gate, not a runtime test — this check alone proves nothing about sampler correctness; the dense-geometry identity AC and visual A/B carry that).
- [ ] Dev-tools probe markers: validity green/red coloring works from load; per-probe irradiance colors appear once the live-irradiance readback completes (the accepted semantic shift in Task 3 — colors come from the composed-atlas readback, not a load-time CPU mirror), on a BC6H-default map.
- [ ] Logging: prl-build prints one info summary (valid/total probes, compact bytes, format tag); runtime logs the base-atlas footprint once per load (dev-tools); nothing added per frame.

**Measured findings (each "before → after, ratio", recorded in the findings note):**

- [ ] id 34 section bytes on `campaign-test` at the sweep configuration: recorded baseline 57,436,908 B → measured v9 bytes (both BC6H default and `--uncompressed-irradiance`), with the valid-probe count confirming the recorded 57,128 / 194,028.
- [ ] Total `.prl` size, same map, before → after.
- [ ] Base-atlas VRAM: dense `Rgba16Float` allocation (194,028 × 288 B class) → compacted BC6H texture bytes, from the once-per-load footprint log.
- [ ] Map load wall-time, before → after (coarse; same host, warm OS cache, three runs each).
- [ ] The explicit statement, as a recorded finding: composed-atlas VRAM and per-frame sampler bandwidth are unchanged by this spec; the bandwidth lever is the adaptive-density sibling.

## Tasks

### Task 1: id 34 v9 format contract (level-format)

Rework `OctahedralShVolumeSection` (`crates/level-format/src/sh_volume.rs`) to version 9: bump `SH_VOLUME_VERSION` (`crates/level-format/src/sh_volume.rs:31`; the reject arm at `crates/level-format/src/sh_volume.rs:260-266` already yields the named error for any other version — extend its message text, no new mechanism). Changes, stated as constraints (field order/offsets are implementer-pinned; Wire format section binds the encoding): (a) the atlas payload becomes **compact** — tiles for valid probes only, x-fastest probe order preserved, prefixed or tagged by an `irradiance_format` field mirroring id 35's tag discipline (`crates/level-format/src/direct_sh_volume.rs:41-92` is the model: tag constants, `expected_irradiance_len`-style length identity per tag, unknown-tag reject); the compact atlas has its own layer-aware layout computed over the **valid** probe count via the existing `irradiance_atlas_array_layout` path in `crates/level-format/src/octahedral.rs`, carried in **new** `compact_atlas_*` fields (Wire format) — every existing v8 field, including `atlas_dimensions` / `atlas_tiles_per_row` / `tiles_per_layer` / `layer_count`, keeps its v8 meaning: the dense per-probe layout the composed runtime atlas and sampler tile math use (Invariant I9; the consumers that depend on this are enumerated in Task 3). (b) each per-probe metadata record gains a **density level** field, `u8`, always 0 in v9, parse-rejected if nonzero ("reserved for adaptive density") — the record currently packs `validity` + two f16 moments + 3 padding bytes into an 8-byte stride (`OCTAHEDRAL_PROBE_STRIDE`, `crates/level-format/src/sh_volume.rs:38-54`); keeping the stride at 8 by taking one padding byte is preferred but not mandated. (c) parse validates: version, tag, level==0, metadata count == grid probe count, compact payload length == tag identity over the valid count. Update `placeholder()`, `HEADER_SIZE` if the header grows, the doc-comment layout block (`crates/level-format/src/sh_volume.rs:103-137`), and round-trip/reject tests in-file (existing test shapes at `crates/level-format/src/sh_volume.rs:713+`). No BC6H code moves in this task or any other: the compiler's reference decoder is `#[cfg(test)]`-gated, Mode-11-only (`assert_eq!` on the mode, `crates/level-compiler/src/bc6h.rs:309-314`), and documented as non-production because runtime decode is the GPU's job (`crates/level-compiler/src/bc6h.rs:307-308`) — it stays exactly where it is; the dev-tools consumer that once motivated moving it is served by the existing GPU readback instead (Task 3).

### Task 2: compiler emission — compact pack + BC6H encode

In the compiler's SH packaging path, build the v9 section: filter the dense per-probe tile stream to valid probes (validity already computed per probe in `probe_grid_layout` and carried on `OctahedralShProbe`; the tile packer that writes validity into alpha today is `pack_octahedral_irradiance_tile`, `crates/level-compiler/src/sh_bake.rs:795-839` — the alpha channel becomes dont-care and the invalid-probe zero-tile branch becomes "emit no tile"), lay the surviving tiles out with the compact-layout helper from Task 1, and BC6H-encode the compact atlas by mirroring `encode_direct_section_bc6h` (`crates/level-compiler/src/direct_sh_bake.rs:876-925`): pad each layer's axes up to multiples of 4 (tile dimension 6 is not block-aligned — blocks straddle tile boundaries, accepted lossy, same as id 35), zero fringe, encode via `bc6h::encode_bc6h_rgb_from_f32_rgba`, store the padded blob under the BC6H tag; when the existing `--uncompressed-irradiance` flag is set (already parsed at `crates/level-compiler/src/main.rs:727-728` and threaded to the direct-SH encode at `crates/level-compiler/src/pipeline.rs:835`), emit the compact `Rgba16Float` payload under the uncompressed tag instead. Wire the same flag to this encode at the same pipeline seam. Cache posture, with warrant: the `sh_group` stage caches baked per-group probe *values*, not section bytes, and this task changes only the PRL section encoding downstream of those values — probe values, grid layout, and validity computation are untouched — so no `SH_GROUP_STAGE_VERSION` bump is needed. The version's doc comment (`crates/level-compiler/src/sh_group.rs:41-44`) does list "the payload codec" as a bump trigger; that phrase means the codec of the **cached group entries themselves** (how per-group values serialize into the stage cache), which this task does not touch — the id-34 section codec is not part of the cached payload. A warm-cache rebuild must produce the new v9 section from cached values; that is the honesty check, not a version bump. Add the one-line `log::info` summary: total probes, valid probes, compact tile bytes, encoded bytes, format tag. Focused tests: compact payload identity (valid count × 288 B pre-encode), invalid-probe exclusion, uncompressed determinism.

### Task 3: runtime — upload, indirection words, compose rewire

Consume v9 in the renderer; the loader needs only pass-through parse (Task 1's `from_bytes` does the validation). All edits land in `crates/renderer/src/render/sh_volume.rs` and `crates/renderer/src/shaders/sh_compose.wgsl` unless named otherwise. **Dense-geometry consumers stay on the unchanged v8-meaning fields (Invariant I9) — enumerate and leave them reading `atlas_dimensions` / `atlas_tiles_per_row` / `tiles_per_layer` / `layer_count`:** the verbatim assignments into `ShVolumeResources` (`crates/renderer/src/render/sh_volume.rs:410-415`), the `BIND_SH_GRID_INFO` sampler uniform built from them (`build_grid_info_bytes` call, `crates/renderer/src/render/sh_volume.rs:479-492` — this is the tile geometry every sampler uses against the dense composed atlas), the compose `GridDims` params (`crates/renderer/src/render/sh_compose.rs:120-129`), `direct_compose_layout`'s no-id-35 fallback (`crates/renderer/src/render/direct_sh_compose.rs:347-355`), and both `ShProbeReadback::new` call sites (`crates/renderer/src/render/renderer_full_init.rs:243-252`, `crates/renderer/src/render/renderer_resources.rs:418-427`). None of these change behavior; the new `compact_atlas_*` fields feed only the base-atlas upload and the slot→texel mapping below. (a) **Upload:** replace the dense `upload_atlas_texture` call for the base atlas (`crates/renderer/src/render/sh_volume.rs:390-397`; the dense uploader with its `Rgba16Float` format and size assert is `crates/renderer/src/render/sh_volume.rs:951-1002`) with a tag-branched path mirroring the direct atlas's verbatim BC6H upload (`upload_direct_atlas_texture`, doc at `crates/renderer/src/render/sh_volume.rs:1004-1009`): BC6H tag → `Bc6hRgbUfloat` texture from the padded blob; uncompressed tag → `Rgba16Float` from compact texels; both sized to the **compact** atlas dimensions. (b) **Indirection words:** build one `u32` per grid probe at load — invalid probes get a sentinel (`0xFFFF_FFFF`), valid probes get their compact tile slot = rank among valid probes in x-fastest order (prefix count over the metadata validity bytes) — and upload as a new read-only storage buffer in the compose bind group. Budget audit, pinned: the compose BGL currently carries six COMPUTE-visible storage buffers (bindings 20-25, `crates/renderer/src/shaders/sh_compose.wgsl:64-75`); this adds exactly one, 7 of the un-raised ceiling of 8 (`context/lib/rendering_pipeline.md` §10 "Widen visibility minimally"). Also add a non-filtering sampler binding for the BC6H base read. (c) **Compose WGSL** (`sh_compose.wgsl`): the base atlas read at `crates/renderer/src/shaders/sh_compose.wgsl:193` becomes a texel-center `textureSampleLevel` through the non-filtering sampler normalized by `textureDimensions` of the base texture (the Metal-constraint precedent is `crates/renderer/src/shaders/direct_sh_compose.wgsl:143-149`); the texel's source location comes from the probe's indirection word (sentinel → skip the fetch); the validity early-out at `crates/renderer/src/shaders/sh_compose.wgsl:196` (`base.a < 0.5`) becomes a sentinel test on the indirection word; and the composed write at `crates/renderer/src/shaders/sh_compose.wgsl:217` stores alpha = 1.0/0.0 **derived from the word**, preserving the composed atlas's alpha-validity contract so the samplers stay untouched — the complete validity-read inventory this rests on is pinned in Invariant I2. Out-of-grid texels (`!atlas_mapping.in_grid`) and invalid probes store a zero tile with alpha 0 (today they copy the base texel through, `crates/renderer/src/shaders/sh_compose.wgsl:196-205` — with a compact base there is no texel to copy; zero-with-alpha-0 is what the dense path stored for invalid probes anyway, warrant: `pack_octahedral_irradiance_tile` leaves invalid tiles all-zero, `crates/level-compiler/src/sh_bake.rs:800-826`). (d) **Dev-tools probe markers:** the load-time CPU mirror `probe_irradiance` (`crates/renderer/src/render/sh_volume.rs:371-387`, fed by `probe_average_irradiance` at `crates/renderer/src/render/sh_volume.rs:1260`) reads dense atlas texels that no longer exist at rest. Do **not** decode BC6H on the CPU for it — the compiler's reference decoder is test-gated, Mode-11-only, and documented non-production (`crates/level-compiler/src/bc6h.rs:307-314`). Instead, seed `probe_irradiance` with the neutral placeholder at load and let the **existing live readback path** supply real colors: `ShProbeReadback` already copies the composed dense atlas (`encode_copy`, `crates/renderer/src/render/sh_diagnostics.rs:370-376`), decodes it into per-probe RGB (`decode_probe_irradiance_atlas`, `crates/renderer/src/render/sh_diagnostics.rs:453-458`), and swaps the result into `sh_volume_resources.probe_irradiance` each completed readback (`crates/renderer/src/render/renderer_render_frame.rs:1000-1001`) — all of it reads the composed `Rgba16Float` atlas this spec leaves dense, so it needs no changes. Accepted semantic shift, stated for the AC: marker irradiance colors appear once the live-irradiance overlay readback completes rather than from load; validity green/red coloring (from metadata, `crates/renderer/src/render/sh_diagnostics.rs:17,251`) is unaffected and immediate. (e) **Footprint log:** once per load (dev-tools), base-atlas bytes + format + valid/total probe counts. The GridDims uniform (`crates/renderer/src/shaders/sh_compose.wgsl:33-45`) keeps describing the dense composed atlas — dispatch bounds and `map_atlas_texel` are unchanged — and its two spare words (`_pad0`, `_pad1`, `crates/renderer/src/shaders/sh_compose.wgsl:43-44`) carry the compact tiles-per-row and tiles-per-layer the shader needs to turn an indirection slot into a base-atlas texel; the Rust-side params struct (`crates/renderer/src/render/sh_compose.rs:120-129`) and its byte builder gain the two fields in lockstep, layout size unchanged.

## Wire format

v9 rides the existing id-34 section; conventions mirror v8 exactly — little-endian throughout, version as the first `u32`, existing header field widths retained. Constraints for the additions (field order and exact offsets are implementer-pinned at landing; the doc-comment layout block in `crates/level-format/src/sh_volume.rs` is updated in the same change):

- **No existing v8 field changes meaning across the bump.** `atlas_dimensions`, `atlas_tiles_per_row`, `tiles_per_layer`, `layer_count`, and every grid field keep describing the **dense** per-probe layout — the geometry the runtime composed atlas and the sampler tile math use, and the geometry the renderer assigns verbatim into its shared state and sampler uniform (`crates/renderer/src/render/sh_volume.rs:410-415`, `:479-492`). Redefining them to mean the compact payload would ship compact geometry into the sampler uniform with no shader or BGL diff — silent whole-world mis-sampling — and would break the documented id-34/id-35 geometry identity (`context/lib/build_pipeline.md:199`, `:222`). The compact payload gets its **own, new** fields.
- **Format tag:** a `u32` with the same two-value discipline as id 35 (`IRRADIANCE_FORMAT_BC6H` / `IRRADIANCE_FORMAT_RGBA16F` — reuse the existing constants). Unknown tag rejects at parse. BC6H payload is the 4-aligned padded block blob, layer-major; uncompressed payload is compact `Rgba16Float` texels, layer-major then row-major. Each tag has an exact length identity over the compact atlas geometry; mismatch rejects.
- **Compact atlas geometry, new fields:** `compact_atlas_dimensions`, `compact_layer_count`, `compact_tiles_per_layer`, `compact_tiles_per_row` (four header words) describing the **valid-probe** tile set, computed by the same layer-aware layout helper v8 uses for the dense set. Only the base-atlas upload, the indirection-word slot→texel mapping, and the compose pass's base fetch consume them.
- **Compact payload membership:** exactly the probes whose metadata validity byte is nonzero, in x-fastest linear probe order. No per-probe slot table on disk — slot = valid-rank, derivable (Invariant I3).
- **Per-probe metadata record:** gains a `u8` density level; v9 writes 0 and parse rejects nonzero. Validity and the two f16 depth moments keep their v8 semantics. Keeping the 8-byte record stride is preferred (a padding byte exists); if the stride changes, `probe_stride` in the header carries it as today.
- **Empty/degenerate cases follow v8:** empty geometry emits the placeholder-shaped section (zero dims, no probes, no payload); zero valid probes emits an empty compact payload and the runtime degrades to the no-SH path.

## Open questions / risks

- **BC6H loss on base irradiance.** id 35 ships the same encoder on the same data class (octahedral irradiance tiles) as production default, and blocks already straddle tile boundaries there; risk is bounded and the manual A/B in Task 4 is the check. If an artifact shows up it shows up behind the tag — `--uncompressed-irradiance` is the escape hatch, not a redesign.
- **Load-time prefix-sum cost.** The indirection-word build is one linear pass over 194 K validity bytes at campaign-test scale — load-time only, negligible. No CPU decode exists anywhere in this spec (dev-tools colors come from the GPU readback, Task 3).
- **Sweep numbers are recorded, not re-derived.** The campaign-test byte counts and probe counts in Measured basis are the owner's recorded sweep; Task 4's baseline compile re-derives the "before" side on the measurement host before comparing.
