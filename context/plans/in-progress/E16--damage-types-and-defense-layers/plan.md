## Delegated answers

- **Where the layer storage lives.** Per-entity layer values, last good parameter values and the last-hit stamp are a POD component column in `entities`, the registry's closed vocabulary. Matrix math, drain order and recharge live in `combat-model` (pure, unit-testable) and `sim`. This keeps domain logic out of the `entities` chokepoint (development_guide §Layering invariants).
- **How a damage type is identified at runtime.** By `DamageTypeIndex(u16)`, its position in the registered `damageTypes` list, interned per session at manifest commit. Names stay the identity on every author and data surface. The index is never authored, persisted or carried across a level change (`scripting.md` §11 IR substrate).
- **Call-site gate (Grants AC 15).** A source-scan test lists the functions allowed to write layer values, following the grep gate that keeps app offscreen constructors behind one helper.
